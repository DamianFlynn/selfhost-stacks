    VOLUME NUMBER DERIVATION — the heart of the tool and the place it will be got wrong.
    Read the distinct manifest directory names from now-manifest.ndjson. Each looks like
    `1993. Now That's What I Call Music! 25`, with `[2019 Reissue]` variants on some. Derive the volume
    number by, in order: strip a leading four-digit year followed by a period and whitespace; strip any
    trailing bracketed annotation such as a reissue marker; then take the number that remains. Emit the
    full mapping to OUT_DIR/now-volume-numbers.tsv as directory-name TAB derived-number TAB rule-applied,
    one row per distinct directory name, and treat that file as a reviewable artifact in its own right —
    the number assignment is the risk, so it must be readable without reading the code.

    ASSERT TOTAL COVERAGE, which is what makes a derived mapping trustworthy: the derived numbers must be
    exactly the integers 1 through 115, each appearing exactly once, with the collection root as the only
    unmapped entry. Any gap, any duplicate, any number outside the range, or any directory name that
    yields no number, is a hard failure that stops the tool — never a skip and never a guess.

    DO NOT PARSE A TRAILING NUMBER OFF THE ALBUM TAG. D-03 is a measured trap and it is recorded here
    verbatim rather than paraphrased. The 117 distinct album values include volume 1 tagged
    `Now That's What I Call Music` with no number at all; volume 2 tagged
    `Now, That's What I Call Music II` with a Roman numeral and a comma; and volume 36 split across three
    spellings — `...! Vol.36 CD1` on 16 files, `...! Vol.36  CD2` on 20 files WITH A DOUBLE SPACE, and
    `...! 36` on 4 files. `...Vol.36 CD1` ends in 1 and `...Vol.36  CD2` ends in 2, so a trailing-number
    regex silently misfiles 36 tracks into volumes 1 and 2. It exits 0 and it looks right. Punctuation
    varies too: 96 values spell it `Music!` and 19 spell it `Music`.

    THE ALBUM TAG IS THE INDEPENDENT CROSS-CHECK, via an EXPLICIT ALIAS TABLE, never a regex. Build
    OUT_DIR/now-album-aliases.tsv with one row per distinct album value mapping it to a volume number,
    seeded from the manifest association — for each album string, the volume its files predominantly map
    to under the manifest — and emit it for review with the file count per row. Every one of the three
    volume-36 spellings maps to 36. Volume 1's numberless string maps to 1. Volume 2's Roman-numeral
    string maps to 2. Any album string whose files map to more than one manifest volume is flagged in the
    table rather than resolved.

    DISAGREEMENT HANDLING. For every file, compare the manifest-derived volume against the alias-derived
    volume. Agreement is the normal case. On disagreement, or where the album string is absent from the
    alias table, the destination is
    /mnt/tank/downloads/complete/nzb/_inbox/99-quarantine/now-volume-disagreement/ and NEVER a guessed
    volume. Note explicitly in the header: files landing there are NOT junk and must not be deleted. The
    junk sweep completed in plan 05-04, before this runs, so nothing will act on them; they are the
    "content the operator deliberately kept" case D-11 allows, and they are handed to Phase 6.

    DESTINATION LAYOUT. Volume folders are created INSIDE NOW_ROOT, named `Vol NNN` with three-digit
    zero padding from `Vol 001` to `Vol 115`, so the folders sort lexically in volume order. Flat: all
    discs of a volume live in ONE folder and the CD1/CD2 split is NOT restored. Every file already
    carries a disc value with zero omissions and the maximum disc count is 2, so the tags carry the disc
    structure; beets treats one directory as one album candidate, so handing it two directories risks
    matching one volume as two albums, which is the multi-disc shape QUAL-03 reserves for Phase 7 to
    exercise deliberately. Whether the LIBRARY path format splits discs is Phase 6's call at the
    path-format layer where it belongs.

    The four kept sidecars get destinations too, per D-06's by-value triage: back.bmp, cd1.bmp and cd2.bmp
    follow volume 77 — they are NOW 77 case scans carrying both tracklists, a barcode and catalogue
    number UK:CDNOW77 — and the volume-115 cue follows volume 115. The 9,541-line m3u map stays at
    NOW_ROOT, beside the collection it maps. If plan 05-03's cd2.bmp inspection found it is not volume
    77, use what was actually found rather than the presumption.

    PLAN SUBCOMMAND — read-only. Emits SPLIT_MAP with one row per file as
    `src_abs_path TAB dst_abs_path TAB volume TAB source_instrument TAB agreement`, plus
    now-volume-numbers.tsv, now-album-aliases.tsv, and OUT_DIR/now-reconciliation.txt. Refuse to
    overwrite an existing SPLIT_MAP. Print the reconciliation and close with an explicit statement that
    NOTHING HAS BEEN MOVED. Returns 0 always: it reports, it does not assert.

    RECONCILIATION, ASSERTED RATHER THAN HOPED FOR, and with DISJOINT buckets. Every file counted into
    files_seen takes exactly one route: mapped-to-a-volume, routed-to-disagreement, kept-sidecar, or
    refused-by-fence. State that as an equation and assert it. normalise-dj-tags.py's WR-06 comment
    records a live defect where one file landed in two buckets and the total never balanced. Report:
    the sum of per-volume mp3 counts, which must equal the freshly measured mp3 count from plan 05-05;
    the per-volume identity `files_present == sum of tracktotal` with its exceptions named against
    05-NOW-INVENTORY.md's pre-declared list; and the manifest-only entries on their OWN line, never
    folded into any total.

    APPLY SUBCOMMAND — not run by this plan. Its first statements are two refusals, checked before
    anything else is required so both are reachable and testable anywhere: refuse if SPLIT_MAP is absent;
    refuse if SNAPSHOT_PROOF is absent, unreadable, or does not contain the literal
    tank/downloads@pre-phase5. That snapshot is this subcommand's only rollback, zfs cannot resolve on
    LXC 100, and an unreachable atlantis means the snapshot state is UNKNOWN — a refusal, not a skip and
    not a pass. The existing @pre-project and @pre-chown are a month stale, so a proof naming the wrong
    snapshot MUST fail, which the substring check gives for free.

    Apply then re-validates every row against live state before acting — source exists, is a regular
    non-symlink file with link count one, has the size the map recorded, and the destination does not
    already exist — and aborts the whole run on conflict rather than skipping a row. It creates the
    volume directories, then renames one row at a time by name from the map, collecting failures rather
    than aborting so one stuck file cannot strand the rest. After each rename it asserts the inode is
    unchanged: _inbox, unsorted and dj-mixes are all one dataset, so every move is an inode-preserving
    rename, instant and free. It then re-runs the reconciliation from the RESULTING tree, not from the
    map.

    EXIT-CODE CONVENTION, stated: `plan` 0 always; `apply` 0 when every row moved and the post-move
    reconciliation balances, 1 when at least one row failed or the reconciliation does not balance,
    2 on usage error or a missing map or snapshot proof.
