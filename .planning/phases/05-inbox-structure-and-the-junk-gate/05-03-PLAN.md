<objective>
Build the junk gate and run its read-only half.

on disk rather than between two branches of one process: a branch can be skipped by a flag, an env var

the file.

human, no." Read and approve a file; never sit at a prompt.

Purpose: catch rule-shaped junk mechanically while leaving the decoy folder, the low-value sidecars
and the video rip to an explicit human yes — and leave the rules written down, which Phase 8's new
inflow needs regardless.
Output: `scripts/phase05-junk-sweep.sh` and `/mnt/fast/safety/phase05/junk-candidates.tsv`.

    explicit warning that NOTHING HAS BEEN MOVED OR DELETED and that an operator must approve the file
    before `sweep` will act. `enumerate` returns 0 always: it reports, it does not assert. If
    `$APPROVED_LIST` already exists, refuse rather than overwrite — an approved file must never be
    silently replaced by a fresh enumeration.

    SWEEP SUBCOMMAND — the acting half, written now but not run until plan 05-04. Its FIRST statements,
    before anything else is required, are two refusals so that both are reachable and testable
    anywhere: refuse if `$APPROVED_LIST` does not exist, naming it and telling the caller to run

    willing to lose, not that they are still junk.

    file gates both the move and the delete: first `mv` each approved path into
    `$QUARANTINE/<UTC timestamp>/` and assert it arrived there; then delete what arrived. Rows tagged
    `PROPOSAL` are moved to their proposed destination and NOT deleted.

    BANNED PRIMITIVES, stated in the header and enforced by shape. The script must not contain a find

    strings as well as out of code: the analog recorded that an echoed banner string satisfies a
    comment-stripped grep just as real code does.

    ZFS ASYNC FREE. Do NOT assert a reclaimed-space floor immediately after deleting. ZFS frees space
    asynchronously and `zfs list` can lag a large delete by about 20 seconds. Assert the ABSENCE of
    each deleted path; report reclaimed space as informational with the lag named.

    EXIT-CODE CONVENTION, stated rather than inherited, because the estate has no single one:
    `enumerate` 0 always; `sweep` 0 when every approved row is gone from its original location and the
    quarantine directory is empty of deleted rows, 1 when at least one removal failed or a listed row
    became unsafe between approval and sweep, 2 on usage error or when the approved list or the
    snapshot proof is missing.
