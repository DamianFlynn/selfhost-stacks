<objective>
Normalise ownership across the whole download tree, last, with an instrument that can actually see the
change and a second one that proves it did not reach the library.

D-24 is an operator decision taken against the stated recommendation, and the counter-argument is
preserved so a reviewer meets reasoning rather than silence: Phase 1 normalised the LIBRARY because it
is exported over NFS, where ZFS `acltype=nfsv4` ACLs are not exported and mode bits are the only lever
a client sees. `tank/downloads` is not exported, is 0777, and uid 3000 is the download client
legitimately owning what it wrote. The operator chose to normalise it anyway, all 209,039 entries,
`incomplete/` included.

Two things make this harder than Phase 1's equivalent. It is about 74 times the entry count — 197,776
of those entries are currently uid 3000 — so a synchronous `chown -R` over an ssh session that may drop
is a real exposure with no resume ledger. And D-27 puts the chown last, so `@pre-phase5` already carries
the split's roughly 4,746 renames and a `zfs diff` against it would drown the chown signal in expected
lines. Phase 1 hit exactly that and took a separate `@pre-chown` baseline; the same is done here.

Purpose: satisfy the ownership half of the phase and close the uid-3000 carry-in recorded in STATE.md.
Output: a verified tree-wide chown, with the untouched-proof for the library taken alongside it.
</objective>

    CONSTANTS. `DOWNLOADS=/mnt/tank/downloads`; `LIBRARY=/mnt/tank/media/Music`; `UIDGID=568:568`;

    `OUT_DIR=${OUT_DIR:-/mnt/fast/safety/phase05}`. Copy the route-detection and delegation helpers from
    freeze-music-apply.sh wholesale in shape: read-only detection first so the route is known and printed
    before anything mutates, then a single exec helper that runs locally when zfs exists and over ssh to
    atlantis otherwise.

    PRECONDITIONS, each a refusal and none a skip. Refuse if the zfs route is unavailable — an
    unreachable atlantis means the snapshot state is UNKNOWN, and the snapshot is the only rollback for a
    bad recursive chown. Refuse if `tank/downloads@pre-phase5` does not exist, since D-01's fence must
    still be there. Then take the fresh baseline `tank/downloads@pre-phase5-chown` and refuse to proceed
    if it cannot be created or read back. Also take `tank/media/Music@pre-phase5-chown` at the same
    moment: it is the untouched-proof instrument for the library half and it must be fresh, because
    Phase 1's month-old `tank/media/Music@pre-chown` could carry unrelated drift and would make a
    non-zero diff ambiguous.

    WHY A SECOND SNAPSHOT AT ALL, stated in a comment so it is not optimised away: D-27 orders the chown
    last, so `@pre-phase5` already carries the split's roughly 4,746 renames plus the junk sweep's
    deletions plus the tag write's modifications. A `zfs diff` against it would show all of those and
    drown the chown's signal. Phase 1's plan 01-08 hit exactly this and took a separate `@pre-chown` for
    the same reason. Note also that the stat manifest cannot substitute: it keys on mtime, and chown
    moves ctime not mtime, so a zero from a stat manifest afterwards is EXPECTED and not reassuring —
    plan 01-06 proved that when its gate passed while `zfs diff` showed a real metadata change.
    `zfs diff` against the fresh snapshot is the only instrument that can verify this.

    SCOPE GUARD, ALL-CAPS and literal, before anything is delegated. The chown runs as REAL root on the
    Proxmox host, not as a namespaced container root, so a wrong constant here is a hypervisor-wide
    recursive chown rather than a contained mistake. Assert the literal: if `DOWNLOADS` is not exactly
    `/mnt/tank/downloads`, refuse. Re-assert the path on the FAR SIDE with a directory test before
    chowning, because a bind mount present here but absent there would otherwise make the recursive chown
    a silent no-op against a path the remote auto-creates.

    USE THE SYMLINK-SAFE FORM. Run the chown with the flag that affects symbolic links themselves rather
    than their referents. Without it a symlink under `tank/downloads` pointing into
    `/mnt/tank/media/Music` would have its TARGET chowned, silently reaching the library and breaching
    Phase 1's D-20. This is not hypothetical for this estate: `normalise-dj-tags.py`'s CR-04 records that
    exactly one symlink under a scratch tree defeated a path fence silently, and a hardlink did the same
    with no symlink involved. State the reason in a comment beside the flag.

    SESSION SURVIVAL. This is 209,039 entries, about 74 times the Phase 1 operation, and the only analog
    in the estate runs the chown synchronously over ssh with no timeout — untested at this scale. A
    dropped ssh mid-chown leaves a partially normalised tree with no resume ledger. Solve it by
    detaching: write a small runner onto atlantis that performs the chown and then writes its exit status
    to a sentinel file, and launch it in a new session, immune to a hangup, with stdin closed and stdout
    and stderr redirected to a log file on atlantis. The ssh call returns immediately; the caller then
    polls for the sentinel on a bounded loop with a stated maximum wait and prints progress. Prefer the
    new-session launcher from util-linux, which is present on Debian-based Proxmox; probe for it and fall
    back to a hangup-immune launcher, and refuse rather than silently running synchronously if neither is
    available. Note in the header that `tmux` and `screen` are not installed on LXC 100 and that
    atlantis's toolset was not previously measured, so the probe is the point.

    RESUME STORY, stated explicitly because there is no ledger: a recursive chown is idempotent, so an
    interrupted run is recovered by re-running the same command. That is the recovery path. The sentinel
    distinguishes "finished with status N" from "still running" from "the runner died without writing a
    sentinel", and the third case is a could-not-look, not a pass.

    CENSUS. Before the chown, count entries under `DOWNLOADS` grouped by owning uid and gid, from
    atlantis, and record the totals. After the chown, repeat. The 2026-09-18 measurement was 209,039
    entries with 197,776 at uid 3000; state the fresh numbers beside those.

    NO MODE PASS. Do not run chmod, do not attempt it, do not swallow a failure with a fallback. chmod is
    impossible on this pool: it returns EPERM as real root for every mode, including a no-op chmod on a
    file already at 0777, because aclmode=restricted plus aclinherit=passthrough gives even new files a
    non-trivial NFSv4 ACL. Everything on tank is 0777 and stays that way. Say so in a comment rather than
    leaving the absence to be read as an oversight.

    NO STANDING ASSERTION. D-25: do not add, and do not suggest adding, a health check asserting 568:568
    across tank/downloads. The download client keeps writing as uid 3000 at roughly one job per 72
    seconds, so new 3000-owned files appear almost immediately after the chown completes. Such a check
    would go red on the next download and train everyone to ignore it — the precise failure mode Phase
    02.1's CR-01 spent four gap-closure plans repairing in the other direction. The measurement and its
    date are the deliverable. Put that in the header.

    EXIT-CODE CONVENTION, stated: 0 when the chown completed, the after census shows every entry at
    568:568, the zfs diff shows only M lines, and the library untouched-proof shows zero lines; 1 when
    the chown ran but a verification failed; 2 on usage error or an unmet precondition.
  </action>
