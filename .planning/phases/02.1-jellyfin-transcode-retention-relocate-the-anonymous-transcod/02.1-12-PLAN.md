<objective>
Close **GAP 2 (CR-02)**: the claim *"Jellyfin publishes NO host port … reachable only from a host that
can route to its t3_proxy address"* is false. It appears at `scripts/check-jellyfin-transcode.sh:10-11`
and `scripts/quick-health-check.sh:252, 299-301`, and it is the **last compensating control** in
`.planning/PROJECT.md`'s residual-risk acceptance for the administrator-equivalent Jellyfin API key
that **this phase widened from read-only to write** (`POST /System/Configuration/encoding`).

Measured three times independently (code review, verifier, orchestrator): `jellyfin` holds the LAN
macvlan address `172.16.1.76` on `iot_macvlan`, and `curl http://172.16.1.76:8096/health` from the
workstation returns **HTTP 200**. The admin-equivalent API surface is reachable from the whole
`172.16.1.0/24` and, via the two subnet routers, from the tailnet. The accepted risk was sized
against an endpoint believed unreachable outside one container.

**GET THE MECHANISM RIGHT — this is the part most likely to be encoded wrongly.** The review's
secondary claim, that `ports:` at `jellyfin.yaml:89-93` publishes on LXC 100's host interface via
`docker-proxy`, **does NOT reproduce**: `ss -tlnp` on LXC 100 shows nothing on `172.16.1.159:8096`,
and `curl 127.0.0.1:8096` inside LXC 100 returns `000`. The `ports:` mapping is effectively **inert**
under this container's macvlan attachment. **The exposure is SOLELY the macvlan address.** Writing
"it publishes 8096 on the host interface" into the file would replace one false claim with another,
and the next reader would act on it.

It also matters that the corrected text says the *right* thing about why the script uses
`docker inspect`: not because there is no other route, but because `172.16.1.76` is unreachable
**from LXC 100** under macvlan host isolation — which is already correctly stated at
`check-jellyfin-transcode.sh:268` and then generalised into a false claim about every host eight
lines earlier, in the same file.

This plan **measures before it writes**. Restating a claim without verifying it is how this estate
launders unverified text into looking twice-confirmed — the standing lesson from the keeper.sh README
(3 of 5 documented sync rules were architecturally impossible). The correction is a documentation
change, so the evidence it rests on must be produced here, not cited from elsewhere.

Discharges: D-19/D-20 (the check's contract must be true), D-40 (the credential gate, whose
compensating-control list this corrects). CONS-04 applied to prose.

Purpose: a security acceptance resting on a false premise is worse than no acceptance, because it
reads as reasoned.
Output: two corrected scripts, a re-derived PROJECT.md risk acceptance, and the measurement both are
written against.
</objective>
