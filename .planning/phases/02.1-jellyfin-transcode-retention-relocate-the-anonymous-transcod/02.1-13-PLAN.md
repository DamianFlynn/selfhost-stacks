<objective>
`scripts/quick-health-check.sh` puts **no wall-clock bound on any ssh call**. `SSH_OPTS` carries
`ConnectTimeout=10`, which bounds the *connect* and nothing after it: a wedged dockerd accepts the
connection instantly and then hangs the remote command forever. That is not a hypothetical shape —
it is this estate's documented **2026-08-31 amdgpu HMM signature**, where `dockerd` blocked reading
`/proc/*/smaps` behind a dead `mmap_lock` and every `docker` call stopped returning. The health check
would sit there indefinitely, printing nothing, exiting nothing.

The code review recorded this as **WR-08 (Info, not scored)**, correctly noting it is a pre-existing
pattern this phase extended rather than introduced. It is included here for one specific reason, and
the reason is a coupling rather than an opinion:

**Plan 02.1-11's fix has no value unless the check terminates.** 02.1-11 makes a drifted
`TranscodingTempPath` fail closed and legible on the green path. A check that hangs never reaches
that verdict — it produces neither a tick nor a red, which is strictly worse than the false green
CR-01 described, because there is not even a transcript to disbelieve. Shipping a fail-closed
assertion into a script that can fail to *return* would close one door and leave the frame off the
other. This is the same reasoning that put the WR-10 reachability gate in this file: the estate's
recorded history is "the check was green because nobody could look", and "the check never answered"
is that story's next chapter.

**The mechanism is chosen for portability, and the choice is not obvious.** `quick-health-check.sh`
runs on the **macOS workstation**, which does not ship `timeout` (Homebrew coreutils provides
`gtimeout`), so a workstation-side wrapper would be an undeclared dependency. `ssh`'s own
`ServerAliveInterval`/`ServerAliveCountMax` does **not** solve it either: sshd is alive and answers
keepalives happily while the command it spawned is blocked — the transport is healthy, the command
is not. The bound therefore goes on the **remote** side, using coreutils `timeout` on LXC 100, which
is Linux and has it. This is the same instrument `scripts/disable-jellyfin-hwaccel.sh:172,234` already
uses for exactly this hazard; the difference is that script runs on Linux and can wrap locally, so
the pattern is adapted rather than copied verbatim — and that adaptation must be stated in the file,
because "why isn't this `timeout ssh …` like the other one?" is the first question a reader will ask.

Discharges: D-19 (fail closed — a bound that cannot be read is UNKNOWN, never green), D-20/D-22 (the
fold-in's contract, and the honesty about what a manual check does and does not cover).

Purpose: the assertion 02.1-11 installs is only worth what the script's ability to return is worth.
Output: every remote command bounded, a timeout surfaced as its own condition, and the bound driven
against a real hang.
</objective>
