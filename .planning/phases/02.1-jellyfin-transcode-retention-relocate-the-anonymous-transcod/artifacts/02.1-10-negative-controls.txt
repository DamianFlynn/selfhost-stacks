WHAT THIS IS
  The executed evidence for VALIDATION.md rows 21, 22, 23 and 24 -- all four of
  which are `fires` rows -- plus a fourth control (the usage-error exit code)
  and the restore-and-reverify step for every test that touched anything.

  Rows 21-24 are `fires` rows for one reason: reading the fail-closed branches
  in check-jellyfin-transcode.sh and agreeing they look right discharges
  NOTHING. This estate's worst outage was six weeks of two containers being down
  while the health check reported clean, and the shape of that failure was a
  check that could not see them rather than a check that saw them and lied. A
  branch that has never been executed is a branch that is not known to work.

WHAT WAS *NOT* MUTATED, STATED UP FRONT BECAUSE IT IS THE DESIGN
  Controls 1, 2 and 3 are PURE ENVIRONMENT OVERRIDES. They set ZFS_HOST,
  JELLYFIN_CONTAINER and JELLYFIN_SECRETS for the duration of one process and
  change nothing else. Control 4 passes a bad flag. Across all four:

    - no file was created, edited, moved or deleted
    - no mode or owner was changed, temporarily or otherwise
    - no container was created, stopped, started or removed
    - no ZFS property was read-modified or written
    - no package was installed and no image was pulled

  Asserted rather than claimed, after the four controls ran:

    jellyfin:                                  running healthy
    git -C /mnt/fast/stacks status --porcelain scripts/   -> EMPTY
    sha256 check-jellyfin-transcode.sh (host)  d33356c551113fd972c515fc288ef8f00a1180bb8f17119165c81c21971444b5
    sha256 check-jellyfin-transcode.sh (wkstn) d33356c551113fd972c515fc288ef8f00a1180bb8f17119165c81c21971444b5
    docker ps -a | grep -c '^no-such-container-021$'      -> 0
    stat -c '%a %U' /mnt/fast/secrets/jellyfin-deercrest.env -> 600 root
    test -e /mnt/fast/spike-021/no-such-credential.env    -> ABSENT (as required)

  THE THREE ENV OVERRIDES ARE WHY THIS PAGE EXISTS AT ALL. Plan 02.1-02 added
  ZFS_HOST, JELLYFIN_CONTAINER and JELLYFIN_SECRETS in the ${VAR:-default} form
  specifically so these controls could be run without mutating a real file. The
  cross-AI review's Plan-02 finding is the reason the third one is there: the
  reviewed version hardcoded the credential path, so control 3 either could not
  run or required chmod'ing the real file -- and `600 root` on that file is
  itself an invariant that check-music-consumers.sh asserts. Staging a failure
  in one check by breaking a different check's invariant is not a control, it is
  a second defect.

  Overriding a path does NOT weaken the gate. The 600-root assertion runs
  against whatever path is in use, so control 3 is refused for the RIGHT reason.

WORDING THE REFUSAL ACCURATELY (control 3)
  The credential gate fires on the file being ABSENT, or on its mode/owner not
  being exactly `600 root`. It does NOT fire on the file being "unreadable":
  this script runs as root and root can read anything, so "unreadable" describes
  a condition that cannot occur here. The distinction is kept because a later
  reader who believes the gate catches unreadability will trust it to catch
  something it structurally cannot.

WHY THIS CONTROL MATTERS MORE THAN IT LOOKS -- THE SUBTLE PART
  `docker inspect` on a missing container produces EMPTY OUTPUT. The
  zero-volume-mounts assertion in section 2 is literally `result == ""`. So an
  ABSENT CONTAINER WOULD SATISFY THE VERY TEST THAT IS SUPPOSED TO PROVE THE
  CONTAINER IS CLEAN. "Nothing is mounted" and "there is nothing to ask about"
  would render identically, and the phase's central invariant would report green
  on a stopped Jellyfin.

  That is the CR-02 distinction from disable-jellyfin-hwaccel.sh -- "NOTHING HELD"
  AND "COULD NOT LOOK" ARE DIFFERENT ANSWERS AND MUST NOT SHARE A VERDICT -- and
  it is why check-jellyfin-transcode.sh:338-349 proves the container EXISTS
  before it enumerates anything, with its own distinct message. This control is
  the proof that that guard is load-bearing rather than decorative.

EXPECTED

  rather than passing section 2 on an empty enumeration. The plan's rollback
  table says that if it passes, that is a real defect in
  check-jellyfin-transcode.sh to fix here before the fold-in lands.

OBSERVED -- exit 1, and the guard held. NO defect to fix:

THIS CONTROL IS EXECUTABLE AT ALL ONLY BECAUSE THE PATH IS ENV-OVERRIDABLE.
  Plan 02.1-02 made JELLYFIN_SECRETS an override in response to the cross-AI
  review's Plan-02 finding. The reviewed version hardcoded it. Without the
  override this control had exactly two forms, and both are wrong:

    (a) do not run it -- leaving a fail-closed branch on the credential route
        unexecuted, which is the thing rows 21-24 exist to refuse; or
    (b) chmod or chown the REAL /mnt/fast/secrets/jellyfin-deercrest.env to
        stage the condition -- which breaks an invariant a DIFFERENT check
        (check-music-consumers.sh) asserts, in order to test this one.

  Pointing the variable at a path that does not exist is the clean third option
  and it is why 02.1-02's change was worth making.

EXPECTED
  exit non-zero, and section 5 reports UNKNOWN rather than an empty settings
  report. An encoding section that printed no values and said nothing would be
  indistinguishable from an encoding section that read seven values and found
  them all correct -- the CONS-04 substitution in its purest form.

    /mnt/fast/spike-021/no-such-credential.env, D-40). UNKNOWN, not green"
    -- and NO key/value lines are printed. The seven REPORTED lines that appear
    in every healthy run are absent, so there is no possibility of reading a
    stale or empty report as a clean one.
  - `unreachable: 1`, counted apart from bound violations
  - FAILURES total: 2

  Sections 1-4 stayed green, correctly: none of them needs the API key. Again,

  unreadability will trust it to catch something it structurally cannot.

CONTROL 4 -- USAGE ERROR IS EXIT 2, NOT EXIT 1
================================================================================

COMMAND
  ssh -n -o BatchMode=yes root@172.16.1.159 \
    'bash /mnt/fast/stacks/scripts/check-jellyfin-transcode.sh --nonsense'

WHY THIS IS A CONTROL AND NOT A FORMALITY
  This is the estate's exit-code convention, established at
  check-music-freeze.sh:31-42: a failed ASSERTION is exit 1, a usage or
  ENVIRONMENT error is exit 2. It is what lets the fold-in in
  quick-health-check.sh distinguish "the check found problems with the estate"
  from "the check was invoked wrongly / cannot run here". Conflating the two
  produces the worst possible reading of a red: an operator investigating a
  Jellyfin fault that is really a typo, or -- far worse -- dismissing a genuine
  red as a harness problem.

  The same exit 2 also covers the Darwin platform guard: this script measures
  free space with `df -B1 --output=avail`, BSD df silently ignores --output, and
  the result would parse into a WRONG NUMBER rather than into an error. "This
  instrument cannot be used here" is not "the estate is broken".
