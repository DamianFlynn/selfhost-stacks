PART 6 — WHAT THE PLAN TEXT GOT WRONG
================================================================================

Recorded, not massaged. Four items.

1. THE PLAN'S 124 BRANCH PLACEMENT WOULD HAVE MADE THE BRANCH UNREACHABLE ON EXACTLY THE CASE IT
   EXISTS FOR — the most important item here.

   The plan says: "Before the existing `elif [ "$RC" -eq 0 ]`, insert a branch for
   `[ "$RC" -eq 124 ]`", while the `[ -z "$OUT" ]` empty-output test "must stay first".

   Both instructions are individually right and together they are broken. A command killed by
   `timeout` USUALLY PRODUCES NO OUTPUT — the `sleep 30` stub the plan itself specifies produces
   exactly none. So on a real hang both conditions are true at once, and an unmodified
   empty-output test wins. Had the branch been inserted exactly as written, the driven control
   would have printed:

       ⚠️  UNKNOWN — 172.16.1.159 unreachable or the audit produced no output

   for a host that answered ssh perfectly and was demonstrably reachable — failing the plan's OWN
   task-2 criterion ("the transcode block's output contains the timeout-specific text"), and
   reintroducing the very conflation this plan exists to remove, just relocated: "the host is
   unreachable" and "the command did not finish" are different answers.

   RESOLUTION, which satisfies both of the plan's intents rather than trading one off:
   the empty-output test stays textually and logically FIRST, and gains a single qualification —
   it defers when, and only when, the remote exit status was 124:

       if [ -z "$TRANSCODE_OUT" ] && [ "$TRANSCODE_RC" -ne 124 ]; then

   02.1-10's finding is fully preserved: a zero-byte remote script exits 0, not 124, so it still
   lands in the empty-output branch and is still caught there. Verified live in PART 3: the
   `unreachable or the audit produced no output` string appears 0 times in the driven transcript.

2. THE BOUNDED-CALL COUNT CRITERION DOES NOT BALANCE. `raw ssh count - 2 == bound count` gives
   15 - 2 = 13 against 10 bounds. The three-line gap is three `echo` lines printing re-run hints
   to the reader, not call sites. Both raw numbers and the corrected call-site count (12) are in
   PART 1 so the subtraction is checkable rather than asserted.

3. `grep -c 'apt\|apt-get\|install'` CANNOT RETURN 0 ON THIS FILE AND NEVER COULD. It returns 3
   both before and after this plan, matching "apt" inside "capturing" in a pre-existing comment
   repeated at three call sites. A word-boundary form of the same check returns 0. Full detail in
   PART 1. Nothing is fetched, and the `timeout` probe refuses rather than providing.

4. THE "DELIVER FIRST" STEP IS NOT EXECUTABLE UNDER WORKTREE ISOLATION, and for this plan it is
   also unnecessary, because the payload is workstation-resident. Full reasoning in PART 5.
   Consequence stated plainly so nobody overreads this file: these runs prove the bound works in
   the copy that was committed. They do NOT prove anything about a bounded quick-health-check.sh
   on LXC 100 — that copy is not the one anybody executes, and it is not this plan's payload.
