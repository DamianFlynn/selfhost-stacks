================================================================================
02.1 D-32 PASSIVE `/` WATCH  --  OBSERVATION ONLY
================================================================================

WHAT THIS IS
  D-32 (operator decision, 2026-09-02). The operator chose a PASSIVE guard over
  actively clearing the anonymous volume's `transcodes/`. This file records a
  cheap re-observation of LXC 100's root-filesystem headroom and the anonymous
  volume's transcode footprint, taken at the head of each plan in phase 02.1, so
  that if `/` starts filling mid-phase there is an EARLY SIGNAL rather than a
  surprise.

WHAT THIS IS NOT
  This watch ASSERTS NOTHING. It is not a gate, not a check, and not a control.
  It does not pass or fail. It is a record of observations, and it exists to be
  read by a human comparing consecutive lines.

  IT NEVER WRITES TO OR DELETES LIVE TRANSCODE DATA.
  The watch is `du`, `df`, `find` and `docker inspect` and nothing else. No
  `rm`, no `mv`, no `truncate`, no redirect into
  /var/lib/docker/volumes/$OLD_VOL/_data/ is permitted by any plan appending
  here.

  The existing cache is NOT removed by this guard. It is removed by the normal
  cutover path -- the copy (02.1-04), the recreate (02.1-05), and the
  `docker volume rm` in 02.1-06.

FORMAT
  One line per sample, appended at the HEAD of each plan, oldest first.
  Every size is a BYTE INTEGER. Measuring with `df` in GiB-rounding block mode
  (the `-B` flag with a `G` argument) is PROHIBITED: it rounds UP, which is up
  to 1 GiB of optimism against a 20 GiB floor (03-01's finding, commit b217ada).
  The flag is spelled out in words rather than written literally so that a
  mechanical grep for it over this artifact returns zero -- the check is "no
  field was measured that way", and a prohibition notice must not trip it.

  An unreadable `df` or `du` is recorded as the literal UNKNOWN, never as 0.
  "Could not look" and "it is empty" are different answers, and 03-01 already
  paid for conflating them.

  Once 02.1-06 deletes the volume, the oldvol_* fields become the literal GONE
  rather than UNKNOWN, so a later reader can tell the planned transition apart
  from an instrument failure at a glance.

  Fields:
    <iso8601-utc> plan=<id>
      root_avail_bytes=        `df -B1 --output=avail /`
      root_size_bytes=         `df -B1 --output=size /`
      oldvol_transcodes_bytes= `du -sb .../_data/transcodes`   <-- the growing part
      oldvol_total_bytes=      `du -sb .../_data`
      oldvol_transcodes_files= `find .../transcodes -type f | wc -l`
