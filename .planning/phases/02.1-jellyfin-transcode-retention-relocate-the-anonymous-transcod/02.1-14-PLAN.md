<objective>
Close the phase's one outstanding **human-verification** item. `02.1-VALIDATION.md`'s manual-only row
(line 134, TRAN-01/TRAN-04) asks a question no assertion in this phase answers: *play one title that
remuxes and one that re-encodes through a real client on the new binds; confirm each starts, seeks,
and survives a seek-back past `SegmentKeepSeconds` (300 s) — which costs a transcode restart of a few
seconds, not a failure.*

**It is not closed, and the reason it is not closed is the interesting part.** The operator's one
recorded playback session (2026-09-02, ~22:20-22:40Z, after the cutover) **direct-played**: zero
segments, zero ffmpeg, zero bytes on `/`. `02.1-10-SUMMARY.md` records it honestly as *"not transcode
evidence — an empty `/mnt/fast/transcode` after a direct-play session is the absence of a test."*
That is a real result about the cutover not breaking playback, and it is not the result this row asks
for.

**Do NOT plan an automated substitute, and do not let one creep in.** 02.1-06 already proved the
mechanism firing — segments landing, deletion firing with advancing ranges, the throttler echoing
`target gap 1800000000` back in Jellyfin's own words — with a purpose-built HLS client, executed, with
the transcript recorded. That question is answered. This row asks a **different** question:
*perceptual watchability through a real client*. An HLS fetcher cannot answer it, and running one
again would produce a transcript that looks like evidence for a claim it does not support — the exact
shape this phase has refused four times.

What this plan *does* automate is the part a human is bad at: **establishing which path each session
actually took.** The 2026-09-02 session is the proof that "I watched something and it was fine" does
not distinguish direct play from remux from re-encode. So each session is pinned by ffmpeg's own live
command line — a `copy` video codec (remux) versus `libx264` (re-encode) — captured while the operator
is watching, alongside a segment count and a `/` reading. The human supplies the judgement; the
machine supplies which thing was judged.

Discharges: D-27 (in-flight playback interrupted by the recreate is accepted — the cutover is long
past, so this is a clean session), and the manual row of the VALIDATION contract.
`workflow.human_verify_mode` is `end-of-phase`, which is why this is a plan of its own at the end
rather than a `<verify><human-check>` buried in an executed task.

Purpose: the phase changed where Jellyfin writes every cache byte and turned on two retention levers.
Nobody has yet confirmed with their eyes that it still plays.
Output: two watched sessions, each pinned to its codec path by machine evidence, with the seek-back
restart observed and distinguished from a failure.
