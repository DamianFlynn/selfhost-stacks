# Phase 02.1 Plan 02: The Standing Transcode-Retention Check and Its Baseline — Summary

`scripts/check-jellyfin-transcode.sh` now answers in one 90-second command whether `/` has headroom,
whether Jellyfin holds any anonymous volume, whether `fast/transcode` is actually **mounted** as well
as quota'd, and what the seven encoding values read back as — and its own first run caught a defect in
itself that would have corrupted every before/after comparison in the phase.

## Completed by a continuation agent

**This plan was executed by two agents.** The first was terminated mid-work by a transient API server
error (class: unknown-failure — not a plan defect, not a quota limit) with tasks 1 and 2 committed and
a 42-line fix uncommitted in the tree. The second agent verified that in-flight diff, committed it,
re-synced the corrected script to the host, and captured the authoritative baseline **from the
corrected script** rather than inheriting the pre-fix transcript. Recorded here because the artifact
provenance is load-bearing: see *The defect the script found in itself* below.

## What Was Built

**`scripts/check-jellyfin-transcode.sh` (commit `d38ef89`, 615 lines).** Host-resident on LXC 100,
read-only by contract, six sections, and the whole contract reprinted by `-h`. It is host-resident
rather than workstation-resident for two independent reasons stated in the header: the docker mount
enumeration and the Jellyfin API call cannot each be expressed as one ssh'd command, and **Jellyfin
publishes no host port**, so it is reachable only from a host that can route to its `t3_proxy`
address.

Four things the cross-AI review put in the script rather than leaving to be retro-fitted, all present:

- **All three env overrides in the `${VAR:-default}` form** (`ZFS_HOST`, `JELLYFIN_CONTAINER`,
  `JELLYFIN_SECRETS`), so 02.1-10's negative controls run without mutating any real file. The third is
  the review finding: without it, control 3 either cannot run or requires `chmod`ing the real
  `600 root` credential — which is itself an invariant `check-music-consumers.sh` asserts.

## Key Findings

### The defect the script found in itself, on its own first baseline run

The script's very first `--baseline` reported `EnableSegmentDeletion = <absent>`,
`EnableThrottling = <absent>` and `EnableHardwareEncoding = <absent>`. All three were genuinely
**`false`** in the API response.

The cause is one operator: `jq -r '.[$k] // "<absent>"'`. **`//` is jq's ALTERNATIVE operator and
treats both `null` AND `false` as empty**, so every boolean that is honestly `false` rendered as
"the key is not in the object". `enc_val()` replaces it with an explicit three-way read —
`<absent>` / `null` / the literal value including `false` (commit `89ad3f2`).

This is not cosmetic, on two counts:

1. **It landed on the most expensive value in the set.** `EnableHardwareEncoding` is the amdgpu HMM
   mitigation applied 2026-08-31 18:27, and the incident it mitigates took the estate down for ~6
   hours. "Absent" and "false" carry **opposite** implications for whether that hazard is still
   contained.
2. **It would have corrupted the phase's before/after comparison.** After 02.1-07 sets those keys
   `true`, a reader diffing transcripts against an `<absent>` baseline would conclude *the key had
   appeared* rather than *the value had moved*.

It is also the exact conflation the rest of the file is built to prevent — CR-02's "NOTHING HELD and
COULD NOT LOOK are different answers, and must not share a verdict". The script asserted that rule
across five sections and then broke it in the sixth. **The pre-fix transcript was discarded, not
committed**, and the committed one names the discarded run and why, so provenance is on the record.

### The mounted/quota split is visible in the baseline, which is the whole point of row 36

```
transcode mounted:  zfs=yes  devid=47  parent=64519      <-- GREEN
transcode quota:    0 bytes  (target 53687091200)        <-- RED
```

Mounted is green from **two instruments that share no failure mode**: the ZFS `mounted` property
fetched from atlantis over ssh, and a container-side `stat -c %d` comparison showing
`/mnt/fast/transcode` (dev 47) does not share a device id with `/mnt/fast` (dev 64519) — which needs
neither ssh nor `zfs`, and therefore still answers when the delegation route is down. Quota is red
because 02.1-03 has not run.

The inverse case is why the review added the assertion: were the dataset **unmounted**,
`/mnt/fast/transcode` would be a plain directory on the parent, **the bind would still work**, the
container would still write — and `zfs get quota fast/transcode` would **still return 53687091200 and
read perfectly green**. A green quota on an unmounted dataset is a false pass of exactly the shape
this phase exists to stop being fooled by.

### 02.1-02's own stop condition is tripped, and the operator decision is OWED BEFORE 02.1-03

The plan says to **stop and report** if the measured `/` margin is under ~5 GiB. It is **182.6 MiB**.

```
/ avail    = 21666320384 bytes = 20.18 GiB
D-17 floor = 21474836480 bytes = 20.00 GiB
MARGIN     =   191483904 bytes = 182.6 MiB
```

The plan was **completed anyway, deliberately and on a narrow basis** (decision recorded in
`02.1-D32-watch.txt` by the first agent and re-affirmed here): every action in this plan is read-only
with respect to `/` — an ssh'd `git pull --ff-only` into `/mnt/fast/stacks`, which is on `/mnt/fast`
and **not** on `/`; a `--baseline` run that asserts and writes nothing; and artifacts written under
`.planning/` on the workstation. Finishing it cannot consume `/`. **Not** finishing it would have left
the phase with no standing check on the host while the budget ran down — the precise failure
02.1-01's closing note warns about.

**The decision that is still owed is an ORDERING one, and it belongs to the operator: should
02.1-09's image reap move ahead of 02.1-03?** 02.1-03 is the first mutation (Terraform, the dataset,
the quota). D-31 put the reap at the end of the phase, and that was ruled when the plan set assumed
~13 GiB of headroom. Nobody has re-ruled on it with 182 MiB in hand.

One piece of good news in the drift: the cache was **byte-identical** across the 02.1-01 and 02.1-02
watch samples 16 minutes apart. The ~6 GiB/day figure is an average over two days, not a steady drip —
transcode cache grows during playback and is flat between sessions. The budget is spent when the TV
is on, which is a less predictable clock than "hours from now", not a safer one.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] `jq '//'` conflated `false` with absent in the encoding read-back**

- **Found during:** Task 2, on the script's own first `--baseline` run
- **Issue:** `.[$k] // "<absent>"` rendered three genuinely-`false` booleans as `<absent>`, including
  the amdgpu mitigation flag. Full reasoning above.
- **Fix:** `enc_val()`, an explicit three-way `has($k)` / `== null` / `tostring` read. Verified live:
  the committed baseline now shows `false` three times and `<absent>` exactly once, correctly.
- **Files modified:** `scripts/check-jellyfin-transcode.sh`
- **Commit:** `89ad3f2` (authored by the first agent, verified and committed by the continuation agent)

**2. [Rule 1 — Bug] The margin comment cited a transcript that was never committed**

- **Found during:** Task 2, after capturing the authoritative baseline
- **Issue:** The `FLOOR_BYTES` comment recorded `21669597184` / 186 MiB "on the `--baseline` run
  recorded in `artifacts/02.1-02-baseline.txt`" — figures from the **discarded pre-fix run** at
  20:56:25Z. The committed transcript reads `21666320384` / 182.6 MiB at 21:00:32Z. The cross-reference
  would have pointed at a file that does not contain the quoted number: the repo's own
  "docs describe intent, not reality" hazard, in miniature.
- **Fix:** Comment rewritten to quote the committed transcript, and to state explicitly that the
  ~3 MiB difference is four minutes of live drift on a filesystem serving 78+ containers rather than
  disagreement — so a future reader does not "correct" it back.
- **Files modified:** `scripts/check-jellyfin-transcode.sh`
- **Commit:** `0138db1`

No Rule 4 situation arose. No package was installed. No `terraform` command was run. The two known
