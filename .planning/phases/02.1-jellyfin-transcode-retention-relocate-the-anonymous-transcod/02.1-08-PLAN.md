<objective>
Close the two policy holes that let an upstream release silently undo everything the rest of this
phase configured.

This plan is the second half of the **D-31 split**. The requirement-ID landing that used to share a
plan with this work is now 02.1-01 and runs first, because every plan's frontmatter cites TRAN-01…09.
What is left here is the actual policy work — and it is deliberately at the tail, because it carries
the phase's most likely stall and `/` is already protected by the time it runs.

Two problems:

1. `renovate.json5` has **no** `jellyfin/jellyfin` rule of any kind. Jellyfin falls through to
   `packageRules[2]` ("Auto-merge minor updates for all Docker images", `automerge: true`,
   `platformAutomerge: true`, `schedule: ["at any time"]`). Jellyfin has been on `10.` since 2019, so
   its *de facto* major releases all present to Renovate as **minor** — 10.9 introduced segment
   deletion, 10.10 changed lyric saving, 10.11 reworked encoding. The exact surface this phase
   configures sits behind a rule that lets Jellyfin's biggest releases through unattended (D-23).
2. `scripts/check-renovate.sh:22` tests for `renovate.json`, but the repo has `renovate.json5`. The
   script `exit 1`s before checking anything, so **lines 26-173 have never executed**. Line 81 repeats
   the same wrong filename in a message and becomes reachable the moment line 22 is fixed — fix both
   together or the fix moves the failure rather than removing it (D-25).

**Three things the cross-AI review changed here:**

- **The JSON5 verify command was fragile — the one concern both reviewers raised independently.**
  `JSON.parse(s.replace(/^\s*\/\/.*$/gm,""))` strips only *line-leading* `//` comments. A block
  comment, an inline comment, a trailing comma or an unquoted key anywhere in a ~40-rule JSON5 file
  throws a syntax error and fails the verification for reasons that have nothing to do with the change.
  Today's file happens to contain none of those, so the command would pass — which is worse, not
  better: it would keep passing until someone adds an ordinary JSON5 construct and then fail
  mysteriously.
- **The `check-renovate.sh` execution risk is budgeted as a task step, not asserted as a
  precondition.** 148 lines that have never run under `set -euo pipefail` will plausibly abort on a
  `grep -c` returning 1, an unset variable, or a missing `gh` auth. The reviewed plan simply asserted
  exit 0 and had no contingency; the review named this as the phase's most likely stall.
- **The stated threat model was overclaimed.** The retention settings live in `encoding.xml` in
  appdata, and an image upgrade does **not** overwrite them.

Purpose: this phase's controls are only durable if an upstream release cannot revert them without a
human seeing it, and the validator that would catch a Renovate config error has never run.
Output: one packageRule, a working `check-renovate.sh`, and a transcript of its first real execution.
</objective>
