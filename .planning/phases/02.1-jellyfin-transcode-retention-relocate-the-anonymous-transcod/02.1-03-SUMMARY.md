# Phase 02.1 Plan 03: The Dataset Declaration and the Quota — Summary

`fast/transcode` is now **declared** rather than merely present, and carries `quota=50G` — the one
bound in this architecture with no gating conditions on it, the one that still holds when segment
deletion, throttling and the 48-hour cleanup task have all failed. It was landed by two separate
`terraform apply` runs in a directory where a bare apply was once measured planning `1 to destroy` on
LXC 100, each from its own saved plan file, each asserted mechanically before it ran.

## The operator ruling, and why there were two applies

**This plan was halted by a previous executor at its own precondition gate, and correctly so.** Task 1
opens with a baseline `cd infra && terraform plan -detailed-exitcode -input=false`, and the plan's

## What Was Built

**`infra/jellyfin-transcode-dataset.tf` (commit `dd1a63c`).** One file, one concern:
`null_resource.jellyfin_transcode_dataset`, `depends_on = [null_resource.host_setup]`.

The header states the safety argument rather than assuming the reader reconstructs it: the dataset
already exists, is already bind-mounted into LXC 100 as `mp18` at `infra/lxc-selfhost.tf:248-251`
(**do not touch it**), has never been *declared* because `host.tf:63` only `mkdir -p`s the path — and
a `null_resource` adds **no attribute** to `proxmox_virtual_environment_container.selfhost`, which is
precisely why this is safe. The destroy landmine is untouched, not defused.

It copies `infra/nfs-music-export.tf:139-186`, **not** `infra/lxc-mpe.tf:48-69`. This supersedes
D-07's cited line reference while honouring D-07's intent; the file says so, so the deviation is
auditable rather than silent. The mpe precedent has two defects fatal to this file's purpose:

- **No `triggers`.** After the first apply it is inert, so a later `quota=` edit plans clean and does
  nothing — which would convert "the properties are code" into "the properties were code once".
- **No `set -e`.** Terraform concatenates `inline` into one script and reports the **last** command's
  exit status, so a failed `zfs set quota=` would be invisible: the read-back still runs, still exits
  0, and the apply reports success while the bound is simply absent.

**Three defects the cross-AI review found and this file does not reproduce:**

| Defect in the reviewed version | What is here instead |
|---|---|
| `zfs get -H` read-back, with an acceptance criterion asserting `1048576` — the non-parsable form returns `1M`, so the criterion fails for the wrong reason | `zfs get -Hp`, and `grep -c 'zfs get -H '` over the file returns **0** — the non-parsable form appears nowhere |
| Saved plan path `/mnt/fast/spike-021/phase021.tfplan`, an LXC 100 path; Terraform runs on the workstation | `mktemp -t phase021-XXXXXX`, absolute path recorded in the transcript, deleted after use |
| Unconditional `chown` on every trigger change against a `drwxrwsr-x` directory, and `var.apps_uid`/`var.apps_gid` interpolated into the provisioner while absent from `triggers` | `chown` guarded by a `stat -c %u:%g` comparison, followed by an **unconditional `chmod 2775`**; and `owner = "${var.apps_uid}:${var.apps_gid}"` is now a `triggers` key |

The `triggers` map carries the `join(",", …)` of all five properties, the `owner` pair, and a
`revision` field for forcing a re-run. `grep -c 'var.apps_uid'` returns **3**. The `inline` list opens
with the literal `"set -e"`.

**`var.jellyfin_transcode_quota` (commit `dd1a63c`).** Type `string`, default `50G`, with a
description naming D-13 and stating in words that it is a **backstop, not a working limit** — with
segment deletion on, steady state should sit orders of magnitude below it, so playback never meets the
ceiling. `grep -c '"50G"'` over `jellyfin-transcode-dataset.tf` returns **0**: the quota is never
inlined.

## Key Findings

### Assumption A3 is CONFIRMED, and byte-exact

This was the plan's one genuinely open empirical question, and the before reading is unobtainable once
the quota is set — so it was taken first, deliberately.

| | `df -B1 --output=size /mnt/fast/transcode` from LXC 100 |
|---|---|
| **Before** (21:37:30Z) | `1442767175680` (1.312 TiB — approximately the pool's free space) |
| **After** (21:39:02Z) | `53687091200` |
| Target | `53687091200` |
| Delta | **0 bytes** |

ZFS derives `statvfs` `f_blocks` from `referenced + available` with `available` capped by the
enclosing quota, so `df` inside the unprivileged container reports the **quota** as the filesystem
size. **VALIDATION.md row 12 is CONFIRMED**, and the standing check has a genuine second instrument
for the bound — one that needs neither ssh nor `zfs`, and therefore still answers when the delegation
route to atlantis is down.

Confirmed with a second independent instrument before being written down, per the 01-09 standing rule:
`stat -f` returns `blocks=51200 bsize=1048576`, and 51200 × 1048576 = 53687091200. Agrees to the byte.

A pleasant side-effect worth recording: that `bsize=1048576` is `recordsize=1M` **visible from inside
the container without asking atlantis at all**.

**What A3 does not licence.** A green `df` size is evidence the quota is *set*, and that the path the
container writes to is the quota'd dataset. It is **not** evidence the quota *fires* — that needs a
write which actually meets the ceiling and gets `ENOSPC`, and it is 02.1-08's job. Row 12's instrument
is a cheap corroborator, never a replacement for row 9.

### Everything read back from the authoritative source, not from Terraform's output

From atlantis at 21:38:54Z:

```
quota           53687091200      <- row 9   PASS (exactly 50 G)
compression     off              <- row 31  PASS
sync            disabled         <- row 31  PASS
recordsize      1048576          <- row 31  PASS
atime           off              <- row 31  PASS
mounted         yes              <- row 36  PASS

stat -c "%a %U:%G" /mnt/fast/transcode  ->  2775 apps:apps
zfs list -r -t all fast/transcode       ->  the dataset alone, no children, no snapshots
```

**The setgid bit survived the provisioner.** That is what the guarded `chown` plus unconditional
`chmod 2775` exist for, and proving `2775` *after* the apply turns it from an intention into a fact
rather than into a reasoning exercise about whether Linux's `chown` strips SGID from a directory.

`zfs list` also shows `AVAIL` already dropped from 1.31 T to **50.0 G** — the quota is live in ZFS's
own accounting, not merely stored as a property. And the dataset being alone is the premise of the
`quota` vs `refquota` equivalence argument: today the two would bound the same bytes, so choosing
`quota` costs nothing now and is what stops a future child dataset or snapshot escaping the bound
later. The other half of D-15/CONS-04 is the errno: `refquota` returns `EDQUOT`, `quota` returns
**`ENOSPC`** — the errno the incident's 764 zero-byte files already signature, and the string every log
grep in this estate is built on.
