<objective>
Disarm a one-command, silent revert of this entire phase.

`scripts/disable-jellyfin-hwaccel.sh` is the estate's amdgpu recovery runbook for a fault that
**recurred on 2026-08-31** and cost ~6 hours of downtime. Its `do_enable` action restores the
**whole** `encoding.xml` from the newest `.bak` — and the only `.bak` on disk is
`encoding.xml.bak.20260831T182741Z`, taken *before* this phase's settings exist. Running `enable`
after this phase lands therefore turns `TranscodingTempPath`, `EnableSegmentDeletion` and
`EnableThrottling` back to their pre-phase values **and reports success**.

The script already knows. `do_enable` prints *"the ENTIRE encoding.xml is restored, not just this"*
and its WR-07 comment says *"do_enable restores the WHOLE FILE, so a stale backup reverts everything
else the operator changed in Jellyfin's Playback settings too, and nothing reported it."* The
post-restore verification added in IN-06 checks `HardwareAccelerationType` **only**.

D-29 rules this in scope. Detect-only — letting the standing check catch the reverted state after the
fact — was rejected because it leaves a known revert path armed, and because the check is manual
(D-22) so "after the fact" could be weeks. Deferring was rejected on this project's own documented
failure mode: a deferred known-bad config rule is how the wrtag `<0.30.0` pin survived for months.

**Scope call, made here and recorded so it is not rediscovered:** take the *minimal* change. Preserve
and re-assert the three retention values plus `TranscodingTempPath` across the restore, and widen the
post-restore verification to cover them. Do **not** convert the mutation mechanism from direct XML
editing to the REST API in this plan, even though line 72-76's comment says *"Once 02-04 lands,
prefer the API"* and 02-04 **has** landed. The file-based route works when Jellyfin is down, which is
exactly the condition this script exists for; converting it is a separate change with its own failure
modes, and this plan is already touching a live incident-recovery runbook. The comment must be
updated so it stops claiming something untrue, and the conversion recorded as explicitly deferred.

Purpose: TRAN-04's durability. Everything else in this phase is protected by a ZFS property or a
Renovate rule; this is the one revert path that lives inside the estate's own tooling.
Output: a hardened `do_enable`, and an executed transcript proving it.
</objective>
