<objective>
Reclaim the ~62 GB of unreferenced Docker images sitting on LXC 100's root filesystem, through the
approval gate that already exists.

`docker system df` reports Images 95, 66.54 GB, **62.44 GB (93%) reclaimable** as of 2026-09-02 —
so 03-01's audited 27 images were always the conservative subset. D-28 pulls this into scope
deliberately, knowing it adds an approval gate to an insertion that is blocking Phase 3.

Two ordering reasons put it first in this phase rather than last. It gives the phase headroom for
plan 06's 392 MB cache copy, which transiently doubles the cache while both copies exist. And more
importantly it keeps attribution clean: if the reap and the volume deletion both credit the same
`df` reading, neither change owns its own delta, and this project's documented failure is
instruments that report green while the thing is broken.

No new tooling. `scripts/spike03-image-headroom.sh` already has everything: its `inventory`/`prune`
split is joined by a **file on disk** specifically so the gate cannot be branch-skipped from inside
one process; it builds the referenced set from `docker ps -a` with **no status filter**, covering the
estate's documented `created`-state blind spot (dispatcharr and teleport sat there for six weeks
behind a filtered check); it re-validates the approved list against a freshly derived referenced set
immediately before deleting anything, because a container may have been created between approval and
now; and `docker image prune -a` / `docker system prune` are **prohibited by name**, with the
prohibition asserted by a comment-stripped grep — the banner deliberately says "reap" rather than the
prohibited word, because a banner string would satisfy a naive grep just as well as a real call.

Purpose: the image reclaim is the one **irreversible** act in this whole phase, which is exactly why
it keeps its own human gate while the Jellyfin recreate does not (D-27, D-28).
Output: a reclaimed root filesystem, an approved reap list under `.planning/`, and before/after
free-space figures in bytes.
</objective>
