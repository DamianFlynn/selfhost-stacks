<objective>
Rebuild the container from the delivered compose file, prove the mount shape, and turn on Jellyfin's
own retention levers without re-arming a six-hour outage.

D-27 waives an approval gate on the recreate — it is treated as a routine compose change, accepting
that in-flight playback is interrupted. That waiver covers **only** the recreate. The
`docker volume rm` remains ordered after Jellyfin is *proven* running on the new path (D-10), which is
plan 02.1-06.

The recreate is what makes the file change real. Deleting the `/dev/shm` line from `jellyfin.yaml`
does not remove the mount from the *running* container; only the recreate does. Docker sorts container
mounts by the **number of path segments** in the destination, so `/cache` (1) mounts before
`/cache/transcodes` (2) regardless of declaration order — that is what `sortMounts` exists for. That
behaviour was read at moby v28.3.2 while this estate runs 29.2.1, which is assumption **A4**, and it
is cheap to falsify: write one file into `/cache/transcodes` from inside the container and check it
appears on `/mnt/fast/transcode` on the host. Do that rather than assuming it.

Then the settings, and this is where the phase's sharpest hazard lives.
`POST /System/Configuration/encoding` is a **full-object replace**: `UpdateNamedConfiguration`
deserialises the entire body into `EncodingOptions` and saves it wholesale, so every property absent
from the body reverts to its C# constructor default. `EnableHardwareEncoding`'s constructor default is
**`true`**; its live value is **`false`**, written at 2026-08-31 18:27 by
`scripts/disable-jellyfin-hwaccel.sh` as the mitigation for the amdgpu HMM kernel oops that took the
whole estate down for six hours. A partial POST silently re-arms it. Read-modify-write is not a nicety
here.

And asserting only the five fields you meant to change is the same shape as 01-06's path-set diff: it
passes while something else was rewritten. So the assertion covers the **non**-changes too.

**Two things the cross-AI review changed here:**

- **The "nothing else moved" proof is a key-set assertion, not a diff-line count.** The reviewed
  version accepted `grep -cE '^[<>]' … -le 12`, which would also pass a diff containing **six** changed
  keys. The prose criteria did require reading the diff, so this was belt-and-braces only — but a
  belt-and-braces check that can be satisfied by the wrong thing is not one.
- **The three encoding JSON artifacts are declared in `files_modified`.** The reviewed version's verify
  read `artifacts/encoding.readback.json` while never declaring it, so a downstream consumer had no
  way to know it existed.

Purpose: TRAN-01's mount shape and TRAN-04's settings, both established with the amdgpu mitigation
provably intact.
Output: a recreated container on the new binds, and the encoding round-trip's before/after evidence.
</objective>
