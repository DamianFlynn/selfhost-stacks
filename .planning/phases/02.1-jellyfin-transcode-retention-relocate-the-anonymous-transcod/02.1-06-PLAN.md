<objective>
Prove the bounds fire. Do not exit on "configured" — and do not exit on a transcript that only looks
like evidence.

CONS-04 is this project's definition of done and D-15 applies it here: a control that *reads back* is
not a control that *fires*. This estate has been burned by that substitution twice — 01-06's path-set
diff passed while 83 `.nfo` were rewritten in place, and 02-08's `exportfs -v` kept printing a line for
a mount the client was refusing. Plan 02.1-05 read the settings back from the API. That is the standing
check's job and it discharges nothing here.

**The cross-AI review found that two of this plan's proofs could not fire as originally written**, and
it made the point that matters more than either individual defect: *because this phase's entire
epistemology is "reading it back is not evidence", a proof that cannot fail is worse here than
elsewhere — it produces a recorded transcript that looks like evidence.* Both are repaired:

**The segment-deletion and throttling proofs needed a client, and the reviewed version never specified
one.** `TranscodingSegmentCleaner` deletes indices **behind the client's download position**, and
`IsThrottleAllowed` returns false with `"No throttle data"` when that position is zero. "Force a
transcode" without a client that fetches segments sequentially therefore proves nothing — and worse,
the reviewed stop condition ("if the count rises monotonically, stop and report") would have fired on
a *harness* defect while reading as a *configuration* failure. This plan specifies the proof client
explicitly and adds a **download-head advance assertion** that separates the two diagnoses.

**The 49.5 GB ballast was disproportionate.** `compression=off` means it genuinely allocates 49.5 GB
on a host with a documented whole-estate wedge correlated with `/proc/pressure/io full ≈ 96%` — and
`disable-jellyfin-hwaccel.sh` already carries an IO-pressure precondition idiom the reviewed plan did
not reuse. It is replaced by a temporary `quota=1G` shrink: the same `dsl_dir.c` code path, the same
errno, roughly 1/50th the IO, seconds instead of minutes. D-13 fixes the 50 G *value*, not the proof
*method*, so this is planner discretion and is recorded as such in CONTEXT.md.

Three things this plan proves that no API response can show:

**Segments actually land in the new place, and nothing lands in the old one.** The second half is only
meaningful **while the old volume still exists**. Run it after the deletion and the test is vacuous —
an empty path proves nothing. So the observation comes first and the deletion comes second, as
separate tasks, in that order. That ordering is D-10's and it is not negotiable.

**Segment deletion and throttling actually start.** `EnableThrottling: true` is inert unless
`IsPkeyPauseSupported` or ffmpeg ≤ 6.1 — a gate the API cannot show. This estate's
`jellyfin-ffmpeg 7.1.4` was probed with Jellyfin's own detection command and does carry the
`p pause transcoding` runtime key, so the throttler should start; "should" is not evidence.

**The quota refuses a write.** ZFS `quota` returns **`ENOSPC`** — "No space left on device" — which is
the errno the incident's 764 zero-byte files already signature, and the string every log grep in this
estate is built on. `refquota` would have returned `EDQUOT` / "Disk quota exceeded", which such a grep
silently misses; that is why plan 02.1-03 set `quota`. And the property being bought is not that
playback survives — it will not — but that **`/` does not move**.

**On the `human-check` in task 1, and why this plan is still `autonomous: true`.** Round 2 asked,
fairly, whether a plan carrying a mandatory human playback check can honestly be marked autonomous.
It can here, and only because of this project's configuration: `.planning/config.json` sets
`workflow.human_verify_mode: end-of-phase`, which **forbids a `checkpoint:human-verify` task inside a
plan** and routes every human verification to a single end-of-phase pass. That constraint is what
drove the round-1 shape, and it still holds. So, stated plainly rather than left to inference: **the
`human-check` below is collected at the end of the phase, not in-task. It does not block this plan,
it does not block the wave, and no task waits on it.** This plan's own completion rests entirely on
its `automated` assertions, which is why `autonomous: true` is accurate rather than convenient. The
perceptual question — is the result actually watchable — is real and is discharged by none of the
automated rows, which is why it is written down instead of dropped; it simply has a different
collection point. (`checkpoint:human-action` remains available under this mode and is used in
`02.1-09` for the reap approval, because that is a human *action*, not a human *verification*.)

Purpose: the phase's whole premise is that these controls hold when nobody is watching. Reading them
back is how the last three attempts would have signed off.
Output: two transcripts, an anonymous volume that no longer exists, and `/` structurally protected
from the end of this wave.
</objective>
