# Phase 02.1 Plan 01: Land the TRAN Requirement IDs and Open the D-32 Watch — Summary

TRAN-01…09 are now authoritative before any plan cites them, ROADMAP's Phase 02.1 placeholders are
gone, and the D-32 watch opened on a phase-start reading that is materially worse than the plan set
assumed: `/` has 185 MiB of margin, not 13 GiB, because the transcode cache already refilled to
12.55 GiB.

## What Was Built

**REQUIREMENTS.md — TRAN-01…TRAN-09 as a phase insertion (commit `950d1a9`).** A new
`### Transcode retention` section carrying nine unchecked bullets, each with its discharging
D-numbers in a parenthesised note. TRAN-09 additionally records that it originated as a *research
finding* (`02.1-RESEARCH.md` § Pitfall 1, Assumptions Log A1) rather than a CONTEXT decision, and was
ruled in scope by the operator on 2026-09-02 as D-29.

The point of the task was not the nine bullets — it was keeping the document's claim about *itself*
true. REQUIREMENTS.md asserts "Both totals agree, and every requirement appears in exactly one phase
row above", and that claim is backed by machinery. Four things moved together:

| Region | Change |
|---|---|
| `## Traceability` | Nine `\| TRAN-0N \| Phase 02.1 \| Pending \|` rows, between CONS-03 and CONS-04 |
| `Coverage:` | Gained `Phase insertions (not part of the v1 denominator): TRAN-01…09 = 9` and `Total tracked: 48` |

**The v1 denominator stays at 39 deliberately.** Incrementing it to 48 would have silently moved the
goalposts of a milestone that is already part-executed — every prior "N of 39" statement in STATE.md
and the summaries would become incomparable with every statement after it. A dated revision note
records that reasoning so the choice is not re-litigated as an oversight.

**ROADMAP.md — Phase 02.1's real content (commit `a1dca2f`).** `**Goal:** [Urgent work - to be
planned]` and `**Requirements**: TBD` are replaced with the Goal paragraph, a `**Depends on**` line,

(`Goal` → `Depends on` → `Requirements` → `Success Criteria` → `Plans` → `Research`), and
`**Plans:** 10 plans` was normalised to `**Plans**: 10 plans in 9 waves`.

Eight criteria come from RESEARCH.md § *Proposed ROADMAP Wording*. The **ninth is new** — the
research draft predates D-29/D-30 and stops at TRAN-08. It requires that

**The volume id and the D-32 watch (commit `dd87a65`).** `docker inspect jellyfin` returned exactly

## Key Findings

**`/` is at 20.18 GiB, 185 MiB above the floor — not the ~33-36 GiB the plan set was written
against.** This is the headline and it changes how the rest of the phase should be run.

```
root_avail_bytes = 21668859904 = 20.18 GiB
D-17 floor       = 21474836480 = 20.00 GiB
margin           =   194023424 = 185 MiB
```

The plan's stated stop condition is "already **below** the floor". It is above, so 02.1-01 proceeded
as written. But the margin is 185 MiB against a plan set whose text assumes 13 GiB of headroom.

Verified with a second independent instrument before being written down, per the 01-09 standing rule:
`stat -f` returned `bavail=5290180` blocks at `bsize=4096` = 21668577280 bytes, matching plain
`df -B1 /` to the byte. Also worth carrying: `stat -f` `bfree` is 28.56 GiB against `bavail`'s
20.18 GiB — 8.38 GiB is root-reserved, and the floor must be checked against **avail**.

**The cache has already refilled to 12.55 GiB across 1,324 files.** The Jellyfin container has been
up since `2026-08-31T18:27:41Z` (the amdgpu incident recovery), so that accumulated in roughly two
days — about 6 GiB/day, accounting for very nearly all of the ~14 GiB `/` has lost since 03-01 took
it to 36 GiB.

**This is the incident repeating, caught early, on the watch's very first sample.** It is exactly
what D-32 was ruled to detect. It is not a reason to stop — it is the reason the phase exists, and
D-31 already put the cutover on the critical path so `/` is structurally protected at the end of
wave 6. The cutover chain is what reclaims this 12.55 GiB.

**It is a reason not to let the phase idle.** At ~6 GiB/day against 185 MiB of margin, `/` crosses
the D-17 floor within about a day and reaches zero within roughly three. Any plan that stalls —
particularly 02.1-09's blocking human gate — spends a budget measured in hours. If a later sample
reads below `21474836480`, that is the operator decision point 02.1-01's rollback table describes:
the reap may need to move earlier, and that is an operator call.

**Most of Task 2 was already on disk.** The ten-plan list, the nine wave headers, the D-31 and
round-2 renumbering notes, `line 50`'s phase-list entry and the Progress row's `0/10` had all landed
in the prior planning commits. Only the header block genuinely needed writing. Verified rather than
assumed: all ten plan filenames were diffed against the actual directory listing, and every plan's
`wave:` / `depends_on:` frontmatter was read and matched against its ROADMAP bullet and wave header.
All ten agree.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] The artifact's own prohibition notice tripped its own acceptance check**

- **Found during:** Task 3 verification
- **Issue:** The plan's acceptance criterion requires `grep -c 'df -BG'` over the watch artifact to
  return **0**. The header's prohibition — written as "`df -BG` is prohibited by name", which is
  exactly the phrasing the plan's own action text uses — made it return **1**. A future reader or the
  phase verifier running that grep would have read a correctly-written artifact as a failure.
- **Fix:** Reworded to name the flag in words ("the `-B` flag with a `G` argument") and added a line
  stating explicitly why it is spelled out that way, so the prohibition survives without tripping the
  mechanical check. Re-verified: count is now 0.
- **Files modified:** `artifacts/02.1-D32-watch.txt`
- **Commit:** `dd87a65`

Legitimacy Audit* records that this phase installs nothing, and `docker`, `df`, `du` and `find` were
already present on LXC 100.
