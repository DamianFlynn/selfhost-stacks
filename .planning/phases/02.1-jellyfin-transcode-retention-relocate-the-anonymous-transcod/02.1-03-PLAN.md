<objective>
Make `fast/transcode` and its tuning code, and set the bound that this whole phase rests on.

The dataset already exists on atlantis, is empty, has 1.4 T available, is owned `apps:apps` with the
setgid bit, and is already bind-mounted into LXC 100 as `mp18` — declared at
`infra/lxc-selfhost.tf:248-251`. It has **never been declared**: `infra/host.tf:63` only `mkdir -p`s
the path. That `mp18` already exists is the single luckiest fact in the phase, because
`infra/lxc-selfhost.tf:322-341` carries `ignore_changes = [mount_point]`, which means adding a bind
mount by editing that file **plans clean and does nothing**. This phase needs no `mount_point`
change at all.

D-12 makes the ZFS quota the load-bearing bound: it lives in a dataset property, so it cannot be
flipped from a UI, survives a container recreate, survives an image upgrade, and caps the blast
radius at one dataset. D-13 sets it at **50 G** — a backstop, not a working limit. A total runaway is
then 4% of the pool's 1.31 T free rather than an outage.

The residual cost is real and is this plan's whole discipline problem: declaring the dataset means
running `terraform apply` in `infra/`, where a bare apply was measured on 2026-08-31 to plan
`1 to destroy` on `proxmox_virtual_environment_container.selfhost` — **LXC 100 and its ~103
containers**. A visual plan review is not sufficient. The guard is a saved plan file plus a
mechanical `terraform show -json | jq` assertion of exactly one change and zero destroys, and the
apply consumes that same saved file — which is what makes "I read it" and "that is what ran" the same
claim.

Purpose: the quota is the only bound in the architecture with no gating conditions on it — the only
one that still holds when segment deletion, throttling and the 48-hour cleanup task have all failed.
Output: `infra/jellyfin-transcode-dataset.tf`, `var.jellyfin_transcode_quota`, `quota=50G` live, and
the A3 `df` evidence the standing check's second instrument depends on.
</objective>
