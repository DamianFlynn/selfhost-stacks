<objective>
Build the standing check this phase's every other plan samples against, and get it onto the host.

`scripts/quick-health-check.sh` is 217 lines and contains **no disk check of any kind**. That is why
19 GB accumulated in an anonymous Docker volume over ~36 hours with nothing saying so, and `/` went
from 2.2 GiB free to zero while an unrelated approval gate was open. D-20 answers with a new
standalone script covering `/` headroom, the absent anonymous volume, the transcode quota and the
five encoding values read back — matching the shape of `check-music-freeze.sh` and
`check-music-consumers.sh` exactly, so it stays runnable alone when debugging.

This plan builds the script and records its `--baseline`. It deliberately does **not** fold it into
`quick-health-check.sh` — that is plan 09, after the cutover, because folding in a check that asserts
the post-state would leave the estate's shared health check red for the whole phase, and a
permanently-red check trains the reader to ignore it (the 01-09 trap).

It also carries the **first D-26 delivery**. `/mnt/fast/stacks` on LXC 100 is at `962410a` while the
workstation tree is at `b915c27` — the host is **4 commits behind `origin/main`**. This is live, not
ceremonial: the estate has a documented failure where merged PRs never touched the host and
`docker ps` disagreed with git.

Purpose: every later plan in this phase samples with this script after each task commit; without it
there is no feedback loop under 90 seconds.
Output: `scripts/check-jellyfin-transcode.sh`, a recorded baseline transcript, and a host checkout
level with `origin/main`.
</objective>
