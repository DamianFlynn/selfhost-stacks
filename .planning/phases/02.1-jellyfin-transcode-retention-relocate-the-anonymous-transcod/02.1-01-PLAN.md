<objective>
Land this phase's requirement IDs in the project's own documents, and close the two policy holes
that let an upstream release silently undo everything the rest of the phase configures.

Three separate problems, all documentation-and-policy, none of which touch the live estate:

1. ROADMAP.md Phase 02.1 still reads `Goal: [Urgent work - to be planned]` / `Requirements: TBD`,
   and REQUIREMENTS.md has no `TRAN-` prefix at all. The eight other plans in this phase reference
   TRAN-01..TRAN-09 in their frontmatter; those IDs must exist somewhere authoritative.
2. `renovate.json5` has **no** `jellyfin/jellyfin` rule of any kind. Jellyfin falls through to
   `packageRules[2]` ("Auto-merge minor updates for all Docker images", `automerge: true`,
   `platformAutomerge: true`, `schedule: ["at any time"]`). Jellyfin has been on `10.` since 2019,
   so its *de facto* major releases all present to Renovate as **minor** — 10.9 introduced segment
   deletion, 10.10 changed lyric saving, 10.11 reworked encoding. The exact surface this phase
   configures sits behind a rule that lets Jellyfin's biggest releases through unattended (D-23).
3. `scripts/check-renovate.sh:22` tests for `renovate.json`, but the repo has `renovate.json5`. The
   script `exit 1`s before checking anything, so lines 26-173 have never executed. Line 81 repeats
   the same wrong filename in a message and becomes reachable the moment line 22 is fixed — fix both
   together or the fix moves the failure rather than removing it (D-25).

Purpose: this phase's controls are only durable if an upstream release cannot revert them without a
human seeing it, and the validator that would catch a Renovate config error has never run.
Output: ROADMAP.md and REQUIREMENTS.md carrying TRAN-01..09; one new packageRule; a working
`check-renovate.sh`.
</objective>
