#### 3. The ssh-to-atlantis ZFS route — `check-music-freeze.sh:123-131` (D-19 fail-closed, quota assertion D)

`zfs` is not resolvable inside unprivileged LXC 100. Copy this wrapper verbatim, renaming nothing:

```bash
# Delegate zfs to the Proxmox host when it is not resolvable locally. Read-only queries only.
ZFS_ROUTE="unavailable"
zfs_query() {
  if command -v zfs >/dev/null 2>&1; then
    zfs "$@"
  else
    ssh -o BatchMode=yes -o ConnectTimeout=5 "root@${ZFS_HOST}" zfs "$@"
  fi
}
```

And the **route must be established and reported in section 0**, so "could not look" is a FAILURE and
not a skip (`check-music-freeze.sh:173-182`):

```bash
if command -v zfs >/dev/null 2>&1; then
  ZFS_ROUTE="local"
  pass "zfs $(command -v zfs) — local"
elif zfs_query list -H -o name tank >/dev/null 2>&1; then
  ZFS_ROUTE="ssh:${ZFS_HOST}"
  pass "zfs delegated to root@${ZFS_HOST} (LXC 100 is unprivileged; the pool lives on the Proxmox host)"
else
  fail "zfs unreachable both locally and at root@${ZFS_HOST} — section 6 snapshot assertions cannot be made"
  TOOLS_MISSING=$((TOOLS_MISSING + 1))
fi
```

Then, at the point of use, the route is checked *before* the query so an unreachable host is a
distinct red (`check-music-freeze.sh:482-490`) — this is the exact shape D-19 asks for on the quota:

```bash
for snap in tank/media/Music@pre-project tank/downloads@pre-project; do
  if [[ "$ZFS_ROUTE" == "unavailable" ]]; then
    fence_fail "snapshot $snap unverifiable — no zfs route (see section 0)"

    pass "snapshot present: $snap (via $ZFS_ROUTE)"
```

#### 4. Docker mount enumeration — `check-music-freeze.sh:188-199` (basis for assertion B, D-18)

The estate's only `.Mounts` enumeration. Note the `|` field separator and its stated reason:

```bash
MOUNT_ROWS=""
if command -v docker >/dev/null 2>&1; then
  RUNNING_IDS="$(docker ps -q || true)"
  if [[ -n "$RUNNING_IDS" ]]; then
    # New logic - nothing in this repo enumerates .Mounts. '|' is the field separator because
    # bind-mount sources are absolute paths and ':' appears inside none of them but is the
    # docker-compose mapping separator, which makes ':' ambiguous when parsed back out.
    MOUNT_ROWS="$(docker inspect --format \
      '{{$n := .Name}}{{range .Mounts}}{{$n}}|{{.Source}}|{{.Destination}}|{{if .RW}}rw{{else}}ro{{end}}{{"\n"}}{{end}}' \
      $RUNNING_IDS 2>/dev/null | sed 's#^/##' | grep -v '^[[:space:]]*$' || true)"
  fi
else
  fail "docker not found — WRIT-01 cannot be verified on this host"
fi
```

For D-18, extend the template with `{{.Type}}` (research § *Code Examples* assertion B). Note
`docker ps -q` above is the **running** set; D-18's invariant is per-container on `jellyfin`, so
`docker inspect jellyfin` is correct there — but any *enumeration* in this phase must use
`docker ps -a` with **no status filter** (the `created`-state blind spot; see

#### 5. Free-space measurement — `spike03-image-headroom.sh:163-168` (assertion A, D-16/D-17)

`df -B1`, never `df -BG` (`-BG` rounds up, up to 1 GiB of optimism). This helper was introduced by
commit `b217ada` for exactly that reason:

```bash
avail_gb() {
  local b
  b="$(df -B1 --output=avail / 2>/dev/null | tail -1 | tr -dc '0-9')"
  [ -z "$b" ] && return 0
  printf '%s' "$(( b / 1073741824 ))"
}
```

Note `[ -z "$b" ] && return 0` yields an **empty** string, and every call site treats
`${before_avail:-unknown}` as unknown rather than zero. Preserve that: an unreadable `df` is UNKNOWN,
not "0 GiB free".

**The weaker precedent — `infra/lxc-mpe.tf:48-69`** (what D-07 cited):

```hcl
# ── Phase 1: ensure the dedicated ZFS dataset exists on the host ─────────────
# The mount_point below binds /mnt/fast/appdata/mpe, which must be a real ZFS
# dataset (raw bind of a non-dataset path fails EINVAL on an unprivileged LXC).
resource "null_resource" "mpe_dataset" {
  depends_on = [null_resource.host_setup]

  connection {
    type     = "ssh"
    host     = var.proxmox_host
    user     = var.proxmox_ssh_user
    password = var.proxmox_ssh_password
    timeout  = "2m"
  }

  provisioner "remote-exec" {
    inline = [
      "zfs list fast/appdata/mpe >/dev/null 2>&1 || zfs create -p fast/appdata/mpe",
      "chown ${var.apps_uid}:${var.apps_gid} /mnt/fast/appdata/mpe",
      "echo '--- MPE dataset ready ---' && zfs list fast/appdata/mpe",
    ]
  }
}
```

Two defects for this phase's purpose, both load-bearing:
1. **No `triggers`.** After the first apply the block is inert — a later `quota=` edit plans clean
   and does nothing. This phase's whole point is that the properties are code.
2. **No `set -e` as the first inline command.** Terraform concatenates `inline` into one script and
   reports the **last** command's status, so a failed `zfs set` here would be invisible.

**The precedent to copy — `infra/nfs-music-export.tf:139-186`:**

```hcl

# re-apply of the pair is a no-op.

    type     = "ssh"
    host     = var.proxmox_host
    user     = var.proxmox_ssh_user
    password = var.proxmox_ssh_password
    timeout  = "5m"
  }

  provisioner "remote-exec" {
    inline = [
      # WR-06: `set -e` FIRST, in every inline list in this file.
      # Terraform concatenates `inline` into one script and reports the
      # provisioner's success as that script's exit status — i.e. the LAST
      # command's. It does not inject `set -e`. Every load-bearing gate here
```

### `stacks/selfhosted/media/jellyfin.yaml` (compose service definition + in-band documentation)

**Analog: itself, lines 93-140.** D-21 names this explicitly. This is the estate's worked example of
"applied by API, explained in compose". Its structure, in order:

1. `NOTE (date):` — one sentence stating the invariant and that it is deliberate
2. A paragraph naming what it *looked* like before and why (so a future reader does not "fix" it)
3. `Classification:` — the term the assertion script uses, so the compose file and the check agree
4. `Why:` — where the control actually lives (the application layer, not the mount) + **date + plan
   number + APPLIED/PERMANENT status**
5. A numbered list of the exact settings, `old -> new`, each tagged with its decision id
6. A paragraph on the one that was *found* rather than decided, and why it matters more than it looks
7. What is deliberately **UNCHANGED**, and why (Movies/Shows keep theirs)
8. What is deliberately **left alone** (`SaveSubtitlesWithMedia`) — "not changed rather than changed blind"
9. `Why not <the rejected alternative>:` — one line
10. `What breaks if someone reverts this:` — the concrete consequence, with a number in it

```bash
drm_clients() {
  timeout 20 ssh -o ConnectTimeout=8 -o BatchMode=yes "root@${PROXMOX_HOST}" '
    ls /sys/kernel/debug/dri/*/clients >/dev/null 2>&1 || exit 3
    cat /sys/kernel/debug/dri/*/clients 2>/dev/null \

report_drm() {
```
