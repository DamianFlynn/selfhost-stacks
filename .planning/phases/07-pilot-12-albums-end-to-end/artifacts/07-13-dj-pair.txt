## Task 1 — PREDICTION: what `route-dj-album.sh --apply` will write into the files (measured on scratch copies)
Why this was measured: step (c) is `modify -a -M -y id:N albumtype=dj` with `import.write: yes`, so beets REWRITES
every tag of every item. An as-is import itself writes nothing (beets 2.12.0 importer/tasks.py:498:
`if write and (self.apply or self.choice_flag == Action.RETAG): item.try_write()` — ASIS is neither), so the
import leaves each file byte-identical to its staged copy. The modify is the first write.
Method: LXC 100 /root/phase07-0713/sim0713.py and sim0713b.py, run as `docker exec -i -u 568 beets-flask
/venv/bin/python -` with BEETSDIR=/config (the live config read, import.write True, id3v23 False). Each copies
chosen staged files to the container's /tmp/sim0713*/, builds an IN-MEMORY library (`Library(":memory:")` — never
/config/library.db, no beet CLI, no move), imports them as-is (Item.from_path + add_album), then does exactly what
`modify -a` does: `album.set_parse("albumtype","dj"); album.try_sync(write=True, move=False, inherit=True)`.
Raw frames read by mutagen before and after. Scratch removed after each run (printed True). Outputs:
/root/phase07-0713/sim0713.txt, sim0713b.txt. Files: P07 4200101, 4200102, 4200201; P08 01. Club Cuts;
P11 101, 102.

      `TXXX:MusicBrainz Album Type` frame. Cause, isolated in sim0713b: mediafile defines
      `albumtype = albumtypes.single_field()`, so both fields share ONE frame; `Item.write` passes both, in the
      order albumtype then albumtypes; the item's `albumtypes` is [] (an as-is item has none), and writing []
      after 'dj' deletes the frame. Control: `update({albumtype:'dj'})` alone -> frame 'dj';
      `update({albumtype:'dj', albumtypes:[]})` -> no frame. The plan's must-have "albumtype reads dj on the file
      itself" CANNOT be met by route-dj-album.sh as written. Routing is unaffected: the path rule reads the DB.
