<objective>
Give the estate's unowned project snapshots an owner, a purpose and a release condition, and prune
only what a mechanical rule says is redundant — through one operator gate (D-19, the operator's
"inventory AND prune", chosen over "inventory, destroy none").

Discretion exercised (CONTEXT: register location): the register lives at
`.planning/SNAPSHOT-REGISTER.md`, a project-level record, not under this phase's `artifacts/` —
snapshots outlive phases (the archive phase inserted by D-02 and Phase 9's batch fences will add
rows), and a register filed inside one phase is a record the next phase does not read.

Eligibility, made mechanical (the operator's stated standard): "strictly newer on the same dataset"
is necessary but not sufficient, because a newer snapshot holds the POST-change state and cannot
undo an older change. The register therefore also requires that nothing changed between the two:
`zfs get -H -p -o value written@<older> <dataset>@<newer>` returns `0` (bytes written between them)
— then the newer is byte-for-byte the same undo point and the register can NAME it as covering the
older's change. Age is not a criterion (D-19 rejected age: `@pre-phase5` is the oldest and most
load-bearing). "none recorded" is written as a could-not-look with the exact search run
(`DEF-06-52-02`, CONVENTIONS §14): silence reads as absence.

⛔ Scope fence: the only `zfs` verbs are `list`/`get` — and, only on the operator's explicit
answer, `destroy` of exactly the names they approve, one invocation per name. `zfs [r]ollback`
forbidden everywhere. `tank/downloads@pre-phase5` is never offered.
</objective>
