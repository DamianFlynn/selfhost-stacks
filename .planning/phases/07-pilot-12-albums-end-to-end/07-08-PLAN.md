behaviour flag and check that must move with it, so the estate can never sit half-granted (four
commits would be four chances). Deployment, behind the fence, is plan 07-09's gated act (E3).

Purpose and the decisions it carries:
- **`import.write` is FORCED, not chosen** (D-22): criterion 3 requires `ffprobe` to show the new
  tags on the file itself, impossible with `write: no`. E11's decision is therefore "keep `yes`,
  and name what bounds it", and D-21 (de-registering `01-auto`, whose `autotag: auto` watchdog reads
  the vendored config directly with `/downloads` `:rw`) is that bound. A reader who sees `yes`
  survive E11 must find this stated.
- **The old digest is preserved** because every CONF-01/02/05 proof was measured against a specific
  `config.yaml` object and the vendored-drift block compares the appdata copy (`DEF-06-21-01`); the
  register keeps those proofs attributable. C10: it has already moved once since the 06-04 proof,
  so the previous value is measured, not copied.
- **D-23:** `/media` stays `rw` after the phase with a standing named assertion. The accepted
  consequence is stated at the site: a rule enforced by policy is weaker than one enforced by
  mechanism (CONVENTIONS §4); from here the snapshot fence is the primary control.

**Interpretation recorded, not hidden — the dormant CLI arm.** D-22 item 1 grants
`/mnt/tank/media` `rw`. The runtime that imports is beets-flask (D-20). The dormant `beets`
container (`profiles: ["manual"]`, beets 2.13.1) must never open the real `library.db` (Phase 6
D-04), so it has no sanctioned write to make; granting it `rw` would create an unsanctioned second
writer and would turn `check-music-freeze.sh`'s census red the first time anyone starts it. This
plan grants `rw` to **beets-flask only**, keeps `beets.yaml`'s mount `:ro` with a dated note
answering its "rw is Phase 7's first act" comment, and keeps qhc's CLI-render arm asserting `ro`
(relabelled from D-05 to D-04/D-22). This is the stricter reading. Plan 07-09's gate presents it to
the operator before deploy; a `grant-both` answer there is a one-line amendment commit before
deploy.

(`assert_media_readonly`) and `FIXTURE_LIB_SHA256`, and `phase06-incremental-control.sh`'s
