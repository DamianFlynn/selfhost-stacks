1. The GC-13 comment justifies preserving `ARM1_FAILS`'s value on the grounds that *"the live arm-1
   summary line is a second consumer of it"*. `ARM1_FAILS` does have a live consumer, but
   `assert_beet_invocation_contract` **never runs live** — so the stated reason does not apply to
   the change it justifies.

   **A correction this plan inherits rather than rediscovers.** R3-07 says `/usr/bin/grep -c` gives
   the function "exactly two hits, the definition and one call site". Measured during planning it
   gives **four**: the definition, one call inside `run_self_test`, and **two comment mentions**.
   The finding's *conclusion* is unaffected and correct — exactly two of the four are code, and the
   code call is inside the self-test — but the census sentence is not, and a verification that
   pinned the number the review printed would fail on arrival. Count **comment-stripped**:
   `/usr/bin/grep -v '^[[:space:]]*#' scripts/check-beets-config.sh | /usr/bin/grep -c 'assert_beet_invocation_contract'`
   → **2**. That is the figure this plan gates on, and it is also the figure that survives you
   adding prose that names the function, which task 2 requires you to do.

   **The preserved value is correct; the reason given for preserving it is not.** That distinction
   is the whole finding and the correction must keep it.
2. Inside the function, the *correct* outcome (synthetic rejected) calls `cfg_fail`, while the
   *defective* outcome (checker BLIND) is a bare `echo -e`. Under `--self-test` that is fine, because
   `cfg_fail` routes to a per-case counter and the `ARM1_SYNTH_REJECTED` gate catches the blind arm.
   But the polarity is **inverted with respect to `FAILURES`**, so the moment anyone wires this
   function into the live path — an obvious next step, since a live run currently never checks the
   `-l`+`-c` source contract at all — a *correct* run increments `FAILURES` and a *blind* checker
   increments nothing.

**Dispositions, stated per finding and repeated in band:**
- **R3-08 is a CODE CHANGE**: remove the announcement nothing gates, and print what the gate reads.
- **R3-07 is a CLAIM CORRECTION PLUS A RECORDED PRECONDITION.** Do **not** wire the function into
  the live path in this plan, and do **not** re-polarise its arms while it is self-test-only. Wiring
  it live is a behaviour change to the live checker, it is not what the finding asks for, and it is
  outside a hardening round's brief. Record the precondition at the site so the person who does wire
  it cannot miss it.

**One decision this plan makes for the executor, because getting it wrong would manufacture a new
defect.** The review offers two fixes for R3-08: drop `expect_reds` from case 6 and print the two
gated values, **or** keep it and add `[[ $ARM1_FAILS -eq $expect_reds ]]` as a third conjunct. Take
the **first**. The second is worse than it looks: when the two existing conjuncts hold,
`ARM1_REAL_VIOLATIONS` is 0 and `ARM1_SYNTH_REJECTED` is 1, so `ARM1_FAILS` is necessarily 1 and the
third conjunct is **implied by the other two** — a gate that can never independently fail. That is a
vacuous assertion, which is the defect class this phase has spent two rounds removing (CR-01, GC-03,
GC-05). Adding one to close a finding about honest announcements would be a poor trade.
