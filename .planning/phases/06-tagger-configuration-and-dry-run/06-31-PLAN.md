<objective>
Close the four round-3 findings in `scripts/phase06-oracle.sh`: **R3-02**, **R3-03**, **R3-04** and
**R3-06**.

**R3-02 is the round's centrepiece and the review names it the strongest candidate for promotion to
Critical.** The self-test gate fires on `ST_FAIL != 0` or `REDS != 0`, and then prints
`ok "self-test: $ST_RUN case(s), every fail-closed branch behaved exactly as expected"`. `ST_RUN` is
*reported*, never *asserted* — a universal claim over a set whose size nothing pins. Drop
`self_test_fences` from the dispatcher (or let an early `return` inside it fire, or lose the calling
line to a rebase) and `ST_FAIL` stays 0, `REDS` stays 0, the script exits 0, and the banner still
says every fail-closed branch behaved as expected — over a set that no longer contains **the only
executed test of the `rm -rf` / `rm -f` receiving-side fences**. That is the entire GC-02 closure
becoming unguarded without one case going red. `check-beets-config.sh` added exactly this guard in
the same round, with the reasoning written out in band; the oracle is the file where the unpinned
harness certifies the destructive fences, and it is the file that did not get it.

**R3-03.** GC-15 quoted the sending side of both `dex_cmd sha256sum` calls and then wrote that the
local consumers are fine because "the remote shell REMOVES the `%q` quoting before `sha256sum` is
exec'd". Both halves are true and the conclusion does not follow: `sha256sum` prints
`<hash><SP><SP><path>` and does not escape a space in the filename, so `awk`'s default splitting
puts `/config/my` in `$2` and `library.db` in `$3`, `$2 == p` never matches, and the `-n` guard exits
3 UNKNOWN — **for exactly the input GC-15 was written to support.** It fails closed, which is why it
is a WARNING; but the knob stays undriveable, and "an undriveable branch is an unproven branch" is
this file's own stated reason for having the knob.

**R3-04.** The BEFORE block guards both hashes for emptiness and routes an empty one to `unknown();
exit 3`. The AFTER block does not, so an absent or unparseable second `sha256sum` line prints
`❌ layer 3: the real library.db CHANGED (<64-hex> -> )` — a measured RED asserted over a
could-not-look, with the arrow pointing at an empty string. It is the exact inverse of the GC-05
correction this same round spent two guards and two self-test cases making in the opposite
direction, and it lands on the one assertion whose whole job is to prove `-l` kept the real
`library.db` closed. A false red, not a false green.

**R3-06.** `self_test_fences`'s comment names three properties — no `rm`, no `touch`, no redirection
into a path — and says "three cases below assert exactly that". The three cases assert **one**
property (absence of the token `rm `) for three different fence strings. `touch` is unasserted. "No
redirection into a path" is not merely unasserted but false as written: every fence text contains
`>&2`.

**State the disposition per finding, in band.** R3-02, R3-03 and R3-04 are **code changes**. R3-06
is a **claim correction**: narrow the prose to what is executed. Do **not** widen the three cases to
make the sentence true — that is scope widening to rescue a comment, and it is the pattern this
round exists to stop.

Output: a pinned and driven case count, a layer-3 block that can measure a space-bearing path and
that routes both sides' could-not-looks to UNKNOWN, and a fence claim that describes its cases.
</objective>
