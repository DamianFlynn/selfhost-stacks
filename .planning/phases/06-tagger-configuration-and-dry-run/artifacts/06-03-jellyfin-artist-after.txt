*** FINDING — the one that matters for Phase 7 ***

  `PreferNonstandardArtistsTag` is a PROBE-TIME option. It changes what AudioFileProber does
  the next time it runs on a file. It is not a view-time transformation, so flipping it does
  not re-derive anything already in the database.

  A `POST /Library/Media/Updated` produces a Default-mode refresh (`ReportFileSystemChanged`
  -> `CreateRefresher` -> `item.ChangedExternally()`). A Default-mode refresh does not re-run
  the audio prober on a file whose modification time is unchanged — so the new option never
  gets a chance to act on the existing 1,244 items. This was measured twice, at album scope
  and at file scope, with the refresher confirming by name that it ran both times.

  The only mechanisms that would re-probe are:
    (a) the aggressive refresh mode — FORBIDDEN for this estate (it writes `.nfo` into the
        library even with SaveLocalMetadata off; Phase 1 measured 83 of 91), or
    (b) the file's mtime changing — i.e. beets actually writing the file, which is Phase 7,
        or
    (c) a newly imported file, which is also Phase 7 and is the case CONF-04 actually cares
        about: "new music downloads land in the library correctly tagged".

  (c) is the project's core value, and for (c) the option is now CORRECT AND IN PLACE BEFORE
  the first import rather than discovered afterwards. That is the useful half of this result.

  WHAT IS STILL OPEN, AND FOR WHOM:
    * CONF-04's Jellyfin read-back is PENDING. It is not "could not look" and it is not
      "nothing is wrong" — it is "the option is set and the evidence arrives with the first
      re-probe". It must NOT be recorded as passed.
    * An operator decision exists but was NOT taken autonomously, because taking it would
      mean issuing the forbidden endpoint: whether to accept a one-off aggressive refresh on
      the three pinned albums (cost: their `.nfo` rewritten, inside a phase whose premise is
      that it writes nothing) purely to obtain the proof earlier. The default — and what this
      plan did — is NOT to.
    * The task-3 assertion is therefore written as a DRIFT DETECTOR with both states pinned:
      green at the measured baseline, green at the post-re-probe target, red on anything else,
      and red immediately if any entity Name ever contains a `;`.
