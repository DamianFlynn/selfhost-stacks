line is a second consumer of it. The preserved value is correct; that reason is not. The counter
does have a live consumer, but assert_beet_invocation_contract never runs live, so the live
summary line consumes the counter and never sees this function's contribution to it. The sentence
is replaced with the true and narrower reason — the self-test's per-case bookkeeping and the live
summary share one counter, so changing it here would move a number in a path this change has no
business touching — and with a census RECIPE in place of a number to be taken on trust.

A correction this plan inherited rather than rediscovered. R3-07's own evidence line says the
function has "exactly two hits, the definition and one call site". Measured, a raw grep gave FOUR
before this plan: the definition, one call inside run_self_test, and two comment mentions. The
finding's conclusion is unaffected and correct — exactly two of the four were code, and the code
call is inside the self-test — but the census sentence printed the code-only figure as though it
were a raw grep count. That is the same class of self-referential measurement error this round is
closing, so it is corrected in band rather than silently, and a verification that had pinned the
number the review printed would have failed on arrival.
