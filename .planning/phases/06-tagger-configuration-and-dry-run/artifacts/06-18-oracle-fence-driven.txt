§ 0 — WHAT WAS WRONG
================================================================================
The file's own header claimed, of every `${VAR:-default}` knob:

    "every one of them can only make the verdict REDDER: a wrong host, a wrong
     container or a wrong output directory produces a refusal or an UNKNOWN,
     never a pass."

That was FALSE AS WRITTEN for two of the knobs, and the falsity was structural
rather than cosmetic.  SCRATCH and STAMP_REMOTE are not knobs on the verdict at
all — they are ARGUMENTS TO DESTRUCTIVE REMOTE COMMANDS:

    step 12   rm -rf $SCRATCH          inside the beets-flask container
    step 12   rm -f  $STAMP_REMOTE     on LXC 100

Both were interpolated unquoted.  `SCRATCH='/tmp/p6 /config'` word-split inside
the container into `rm -rf /tmp/p6 /config`, which deletes the real
`library.db`, the real `state.pickle` and the vendored config.  The
dirty-destination precheck could not stop it: with two words, `[ ! -e … ]` is an
ARGUMENT ERROR, not a refusal.

This needs a deliberately hostile environment variable, so it is HARDENING and
not an exploitable path.  But the sibling script written in the same phase,
`scripts/phase06-incremental-control.sh`, already had the right shape — a
literal `case` allow-list INSIDE the remote program (`:343`, `:473`) — and is
not vulnerable.  The oracle now has that shape too, at both layers.

§ 2 — CONTROL 2: THE PLAUSIBLE WRONG PREFIX
================================================================================
A fence that only catches the obviously hostile case is a fence against a
strawman.  `/var/tmp/p6` is the value someone would actually type by accident.

  $ SCRATCH=/var/tmp/p6 bash scripts/phase06-oracle.sh --self-test

  ✗ REFUSED: SCRATCH='/var/tmp/p6'.
    SCRATCH is an argument to an 'rm -rf' run inside the container, not a knob on the verdict, so
    it is fenced to a literal allow-list: exactly '/tmp/p6', or '/tmp/p6-' followed by one or more
    characters drawn from [A-Za-z0-9._-]. Nothing else is accepted, and nothing was sent.

  exit status: 2

Note also what the allow-list is NOT.  A bare `case "$SCRATCH" in /tmp/p6-*)`
would still admit `/tmp/p6-x /config` — the very shape control 1 exists to
refuse.  So the SUFFIX is separately constrained to `[A-Za-z0-9._-]`, which is
narrower than the glob and is what makes the glob safe.

§ 5 — "BEFORE ANY SSH": PROVEN BY OBSERVATION, NOT ASSERTED
================================================================================
The claim that the refusals happen before any remote call is the load-bearing
one — it is what makes driving them safe, and it is exactly the kind of claim
that is usually asserted rather than measured.  It is measured here.

METHOD.  `ssh` was replaced on PATH by a POISONED STUB that appends its own argv
to a log and exits 255.  It never execs the real client, so it CANNOT reach the
estate.  Before any control ran, `command -v ssh` was asserted to resolve to the
stub, and the run aborts if it does not (fail closed: "could not install the
stub" must not read as "nothing called ssh").

  ssh resolves to: <scratch>/bin/ssh   [poisoned stub: records, never connects]

RESULT ACROSS CONTROLS 1–4:

  Total ssh invocations recorded: 0
  --- contents of ssh-invocations.log ---
  --- end ---                                (the file is empty)

THE SAME HOSTILE VALUE AGAINST A MODE THAT DOES SSH.  `--self-test` is offline
by construction, so a zero on it alone would be weak evidence.  `--baseline`
reaches step 1 and issues a `docker inspect` over ssh, so it is the mode that
can discriminate:

  $ SCRATCH='/tmp/p6 /config' bash scripts/phase06-oracle.sh --baseline
      (poisoned stub on PATH)

  ✗ REFUSED: SCRATCH='/tmp/p6 /config'.
    … same refusal text …
  exit status: 2
  ssh invocations recorded: 0

AND THE COUNTER ITSELF IS CONTROLLED.  A zero proves nothing if the counter is
broken.  The same mode with an ALLOWED SCRATCH, pointed at TEST-NET-1
(192.0.2.1, RFC 5737, which is not this estate and is not routable):

  $ SCRATCH=/tmp/p6-gapclose LXC_HOST=192.0.2.1 bash scripts/phase06-oracle.sh --baseline

  ✓ sampled folders read from 06-SAMPLE.md: 10 folders, 174 audio files
  ✓ fixture and sample agree on the denominator: 174 lines / 174 files
  ⚠ UNKNOWN, not green: the container status of beets-flask came back empty (ssh exit 255). Nothing was read.
  exit status: 3
  ssh invocations recorded: 1
  --- contents of ssh-invocations.log ---
  SSH CALLED: -n -o BatchMode=yes -o ConnectTimeout=5 root@192.0.2.1 timeout 300 docker inspect -f '{{.State.Status}}' beets-flask
  --- end ---

So: the counter increments when the fence passes, and stays at zero when the
fence refuses.  The refusal precedes the first remote call, observed rather than
argued.  Note also the shape of the failure when ssh cannot connect — UNKNOWN
and exit 3, "could not look", never a pass.

  (Both `--baseline` invocations above ran ONLY against the poisoned stub and

§ 6 — WR-08: THE APOSTROPHE, AND THE -printf FORMAT'S BYTE IDENTITY
================================================================================
THE DEFECT.  Three sites built `sh -c 'find <printf %q path> …'`.  `%q` quotes
for BASH, and bash quotes an apostrophe as `\'` — which TERMINATES the
single-quoted program the result was embedded in.  A folder named
`Guns N' Roses - Greatest Hits`, an entirely ordinary shape for this corpus,
produced a remote SYNTAX ERROR that reads as an infrastructure fault.  Measured:

  $ sh -c 'LC_ALL=C find /…/Guns\ N\'\ Roses\ -\ \$Greatest -type f'
  bash: -c: line 1: unexpected EOF while looking for matching `''
  exit 2

THE FIX.  The program text now carries NO PATH AT ALL.  Paths are passed as
POSITIONAL PARAMETERS of the remote `sh -c` and referenced as "$1" inside it.
`%q` is still used — on the ARGUMENTS, where the result lands in a bash WORD,
which is the one context `%q` is correct for.  Helper: `remote_sh_c`.

  sh -c $'LC_ALL=C find "$1" -type f -printf "%p\t%s\t%T@\n"' sh /…/Guns\ N\'\ …

THE ONE SITE DELIBERATELY LEFT ALONE.  `find $NEWER_ARGS -newer $STAMP_REMOTE
-type f` lands in a BASH WORD, not inside an `sh -c` program.  `%q` is correct
there and changing it would have broken a working site.  Verified unchanged.

THE -printf FORMAT IS BYTE-IDENTICAL.  `manifest_compare` and
`normalise_transcript` both key on the field layout, and the committed
174-destination artifact's comparability depends on it.  Proven, not assumed, by
stubbing `find` with a program that prints its own argv and running the OLD and
the NEW command through the same shell:

  find argv, OLD:
    0000040    /   m   u   s   i   c   /   p   l   a   i   n  \n   -   t   y
    0000060    p   e  \n   f  \n   -   p   r   i   n   t   f  \n   %   p  \t
    0000100    %   s  \t   %   T   @  \n  \n
  find argv, NEW:
    0000040    /   m   u   s   i   c   /   p   l   a   i   n  \n   -   t   y
    0000060    p   e  \n   f  \n   -   p   r   i   n   t   f  \n   %   p  \t
    0000100    %   s  \t   %   T   @  \n  \n
  RESULT: find argv is BYTE-IDENTICAL before and after

  (Worth recording because it is counter-intuitive: the format has ALWAYS
   carried a REAL tab and a REAL newline, not the two-character sequences `\t`
   and `\n` — `printf` resolved those escapes while building the string.  The
   new code spells them as `$'\t'` / `$'\n'` for exactly that reason.)

§ 7 — IN-06: THE IN-CONTAINER TEMP PATHS
================================================================================
The container's `/tmp` is world-writable and the names beneath `$SCRATCH` were
fixed (`lib.db`, `overlay.yaml`, `state.pickle`).  A stale root-owned leftover
turns a read into a BLIND; a pre-placed SYMLINK at a predictable name is
followed by the `>` redirections, so the instrument writes or reads something
other than what it believes (T-06-94).

They now carry the run's PID: `lib.$$.db`, `overlay.$$.yaml`, `state.$$.pickle`.

`SCRATCH` ITSELF IS DELIBERATELY UNCHANGED and still defaults to `/tmp/p6`.
The dirty-destination precheck, the cleanup assertion, the fence's own
allow-list and the committed 06-11 artifacts all quote `/tmp/p6` by name;
uniquifying the directory would have falsified all four at once.  Uniquifying
only its CONTENTS also keeps every generated path inside the allow-list by
construction — a `mktemp` that wandered outside `/tmp/p6*` would trip the fence
this plan just installed.
