3. IN-10 — THE WIDENED PATH COUNT, DRIVEN AS A PAIR
====================================================================================================
The PAIR is the point. Widening a pattern and only proving the NEW case is how a widening becomes
a regression, so the old single-album case is driven alongside and must be unchanged.

The two classifiers were run over identical synthetic transcripts. OLD is the pinned form this
plan removed (`grep -q 'Skipped 1 paths\.'`); NEW is what `classify_reoffer()` now does
(`grep -qE 'Skipped [0-9]+ paths\.'`):

transcript              OLD (pinned to 1)  NEW (any count)   effect
----------------------  ----------------  ----------------  ------
Skipped 1 paths.        not-offered       not-offered       unchanged (no regression)
Skipped 2 paths.        indeterminate     not-offered       FIXED: was indeterminate -> now not-offered
Skipped 17 paths.       indeterminate     not-offered       FIXED: was indeterminate -> now not-offered

WHY THAT MATTERED. `indeterminate` is routed to BLIND by the caller, so before this change a
multi-album SRC_FOLDER did not make the control fail — it made the control stop discriminating
while still appearing to run, for exactly the case the offered SRC_FOLDER override invites. That
is the worst shape a negative control can take.

WHAT WAS NOT WIDENED. Only the COUNT. Section 6/7 above drives the three outcomes that must not
move: an `Album: ` line still means `offered`, both markers at once still means `contradictory`,
and an unrecognised or EMPTY transcript still falls through to `indeterminate`. An empty
transcript classifying as `not-offered` would have been a vacuous pass; it does not.

STRUCTURAL CHANGE. The classifier was lifted out of `run_arm` into `classify_reoffer()`. This was
not cosmetic: while it was inline it could only be reasoned about, never fed an input. The drive
above and section 6/7 both call the real function in the shipped file.

A COLLISION WORTH RECORDING. Putting the pair into `--self-test` (rather than only into this
artifact, which is all the plan asked for) initially tripped the plan's own IN-10 guard — "no
`Skipped 1 paths` literal remains anywhere in the file" — because the FIXTURE spelled the count.
Caught by running the guard, not by reading it:

    IN-10: the hard-coded path count survives

The guard was right to fire and was not relaxed. The fixture now passes its count as a `printf`
ARGUMENT (`printf 'Skipped %s paths.\n' "$f"`, in a loop over 1, 2 and 17), so the only place a
count can still be written literally in this file is a MATCH PATTERN — which is exactly what
IN-10 forbids. The self-test coverage is kept and the guard keeps its teeth.

The user-facing `blind` message in `run_arm` was reworded from "neither 'Skipped 1 paths.' alone"
to "neither a 'Skipped N paths.' line alone" for the same reason: it is a message a reader will
take as the rule, and it must not describe a rule the code no longer applies.

4. IN-08 — THE RED-vs-UNKNOWN PRECEDENCE
====================================================================================================
DECISION (house convention, decided in plan 06-19): A BLIND INSTRUMENT OUTRANKS A MEASURED RED.

Reason: this estate's standing rule — CLAUDE.md and README § Health Checks — is that "could not
look" is kept distinct from "nothing is wrong" and is never folded into any other verdict.
Reporting a measured red while an instrument was blind asserts a cause the run did not establish.

Before: this script consulted `failed` first; `scripts/phase06-oracle.sh` consulted `UNKNOWNS`
first. Two instruments written in one phase, disagreeing, so no reader could infer the convention.

After — the two now agree, and the condition ordering is identical:

  scripts/phase06-incremental-control.sh:588   if [ "$unknown" -ne 0 ]; then   -> exit 2 (UNKNOWN)
  scripts/phase06-incremental-control.sh:592   if [ "$failed"  -ne 0 ]; then   -> exit 1 (FAIL)

  scripts/phase06-oracle.sh:2394               if [ "$UNKNOWNS" -ne 0 ]; then  -> exit 3 (UNKNOWN)
  scripts/phase06-oracle.sh:2398               if [ "$REDS"     -ne 0 ]; then  -> exit 1 (RED)

The NUMBERING still differs between the two scripts (here UNKNOWN is 2 and usage/refusal is 3;
in the oracle UNKNOWN is 3 and usage/refusal is 2). That is pre-existing, is documented in both
headers, and was deliberately NOT changed by this plan — renumbering an instrument whose exit
codes are already cited in committed evidence would invalidate that evidence to fix a cosmetic
inconsistency. What IN-08 reports is the PRECEDENCE disagreement, and the precedence now matches.

Neither condition's meaning nor its exit code changed. Only which is consulted first.

The convention is now WRITTEN DOWN in this script's EXIT CODES block (23 lines, bounded by a
`# ====` delimiter), naming `scripts/phase06-oracle.sh` as the sibling. The oracle half — stating
it there and naming this script back — belongs to plan 06-19 (wave 7), which owns
`scripts/phase06-oracle.sh`; this plan does not touch that file. Until 06-19 lands, the
convention is implemented in both and stated in one.

5. IN-02 — THE DEAD CLASSIFIER: DECISION AND REASON
====================================================================================================
DECISION: DELETED.

`remote_is_blind()` tested `RE_RC` in {124, 2, 255} and NOTHING CALLED IT. Every caller instead
tests `[ "$RE_RC" -ne 0 ]`, which is strictly WIDER — it also catches 1, 125 (docker could not
run), 126 (not executable) and 127 (command not found).

Routing the callers through the function was the other option the plan allowed, and it was
rejected: adopting the narrow test would have stopped four non-zero statuses from being classified
as blind. That is a REGRESSION DRESSED AS A CLEANUP, on an instrument whose whole value is failing
closed. Adding an explicit "non-blind non-zero" arm at every call site to preserve today's
behaviour would have been more code expressing exactly what `-ne 0` already expresses.

So the wider inline test stays and the dead NAME is gone, with a comment at the old site recording
why there is no helper and the rule for any future one: it must be at least as wide as `-ne 0`,
and it must be called.

  occurrences of the identifier, before: 1   (the finding's signature: defined once, never called)
  occurrences of the identifier, after : 0

Note the comment left behind deliberately does NOT spell the identifier, so the `grep -c` guard
keeps reading 0 rather than drifting back to the 1 that names the defect.

8. A DEFECT IN THIS PLAN'S OWN VERIFY COMMAND, FOUND AND FIXED  [Rule 1 deviation]
====================================================================================================
06-20's task-2 verify contained a FALSE-RED GENERATOR and would have failed against a correct
file. The shape is the one 06-15 and 06-18 each hit earlier in this wave:

    awk "/EXIT CODES/,/^# =/" "$f" | grep -qiE "outranks|wins" || { echo "...not stated"; exit 1; }

under `set -o pipefail`. `grep -q` exits on its first match, `awk` takes SIGPIPE, and pipefail
propagates 141 — so the `||` branch fires exactly when the convention IS stated. Measured, on the
shipped file, with the convention present:

    $ grep -ciE 'outranks|wins' <extracted block>     -> 5 matches   (the text IS there)
    $ grep -c 'phase06-oracle' <extracted block>      -> 2 matches   (the sibling IS named)
    $ set -o pipefail; awk ... | grep -qiE "outranks|wins"; echo $?   -> 141   (reported as ABSENT)

Running the plan's verify verbatim against the finished file printed:
    IN-08: the precedence convention is not stated     VERIFY2-RC=1

A SECOND defect compounded it: the range `/EXIT CODES/,/^# =/` was unbounded, because the script
had no `^# =` line at all, so awk emitted 933 lines — guaranteeing the SIGPIPE. And because the
phrase "EXIT CODES" is also referenced from two body comments, a plain awk range restarts at each
mention, so simply adding one delimiter is not sufficient on its own.

FIXED BY STRENGTHENING, NOT WEAKENING — three changes, all of which make the assertion sharper:
  a) a `# ====` delimiter now closes the EXIT CODES block in the script, so the block is a real,
     bounded object (23 lines) rather than "everything to EOF";
  b) the extraction takes only the FIRST block and stops, so later cross-references cannot reopen
     the range;
  c) the extracted block is written to a file and grepped there, so no pipeline carries a verdict.
     This is the same rule the script itself already follows for its remote commands (CLAUDE.md,
     README § Health Checks: a pipeline must never carry the verdict).
  d) an added assertion that the block is non-empty and under 60 lines, so a future removal of the
     delimiter is caught instead of silently restoring the unbounded range.

The corrected command is recorded in 06-20-SUMMARY.md and was driven red by mutations B and C
above. Task 1's verify was left semantically identical but hardened the same way (it greps a
comment-stripped temp file rather than piping); it passed both as written and as hardened.
