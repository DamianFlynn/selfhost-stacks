§ 1  R4-09 — the layer-3 parser, probed as a DETACHED COPY over synthetic sha256sum output
================================================================================================

DISPOSITION: R4-09 IS A CODE FIX. Four consumers changed from

    LC_ALL=C awk -v p="$REAL_LIB_DB" '{ ... rest == p ... }'
to
    LC_ALL=C p="$REAL_LIB_DB" awk '{ ... rest == ENVIRON["p"] ... }'

`awk -v var=value` runs *value* through awk's escape processing before the program sees it, so a
knob containing a backslash was compared in a form the operator never typed. An environment
assignment is passed through verbatim and read with ENVIRON.

WHAT THIS BUYS, BOUNDED. The old form already failed CLOSED: a mangled comparison yields an EMPTY
hash, which the `[ -n "$LIB_SHA_*" ] || { unknown ...; exit 3; }` guards route to could-not-look —
never to a green tick and never to a false RED. This buys correctness for a backslash-bearing
knob, not a new safety property, which is why the review graded it Info and not a Warning. It also
does NOT disturb R3-03's deliberate refusal of GNU sha256sum's backslash-ESCAPED OUTPUT form:
ENVIRON changes how the REQUESTED path arrives, not how the PRINTED line is read.

--- the probe harness -------------------------------------------------------------------------
Detached copies of both parser forms, over ONE non-empty fixture in a `mktemp -d` that carries
every case. Writing the negatives into the same file as the positives is deliberate: a refusal
over an EMPTY fixture proves nothing, which is `self_test_vacuity`'s own opening rule.

    new_parse() { LC_ALL=C p="$1" awk '{ rest = $0; if (sub(/^[0-9a-f]+  /, "", rest) && rest == ENVIRON["p"]) print $1 }' "$2"; }
    old_parse() { LC_ALL=C awk -v p="$1" '{ rest = $0; if (sub(/^[0-9a-f]+  /, "", rest) && rest == p) print $1 }' "$2"; }
