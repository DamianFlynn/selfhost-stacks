§ 1  R4-09 — the layer-3 parser, probed as a DETACHED COPY over synthetic sha256sum output
================================================================================================

DISPOSITION: R4-09 IS A CODE FIX. Four consumers changed from

    LC_ALL=C awk -v p="$REAL_LIB_DB" '{ ... rest == p ... }'
to
    LC_ALL=C p="$REAL_LIB_DB" awk '{ ... rest == ENVIRON["p"] ... }'

`awk -v var=value` runs *value* through awk's escape processing before the program sees it, so a
knob containing a backslash was compared in a form the operator never typed. An environment
assignment is passed through verbatim and read with ENVIRON.

WHAT THIS BUYS, BOUNDED. The old form already failed CLOSED: a mangled comparison yields an EMPTY
hash, which the `[ -n "$LIB_SHA_*" ] || { unknown ...; exit 3; }` guards route to could-not-look —
never to a green tick and never to a false RED. This buys correctness for a backslash-bearing
knob, not a new safety property, which is why the review graded it Info and not a Warning. It also
does NOT disturb R3-03's deliberate refusal of GNU sha256sum's backslash-ESCAPED OUTPUT form:
ENVIRON changes how the REQUESTED path arrives, not how the PRINTED line is read.

--- the probe harness -------------------------------------------------------------------------
Detached copies of both parser forms, over ONE non-empty fixture in a `mktemp -d` that carries
every case. Writing the negatives into the same file as the positives is deliberate: a refusal
over an EMPTY fixture proves nothing, which is `self_test_vacuity`'s own opening rule.

    new_parse() { LC_ALL=C p="$1" awk '{ rest = $0; if (sub(/^[0-9a-f]+  /, "", rest) && rest == ENVIRON["p"]) print $1 }' "$2"; }
    old_parse() { LC_ALL=C awk -v p="$1" '{ rest = $0; if (sub(/^[0-9a-f]+  /, "", rest) && rest == p) print $1 }' "$2"; }

--- the fixture, shown with `sed -n l` so the escapes are unambiguous --------------------------

(The backslash-continuations are `sed -n l`'s 80-column wrapping, not part of the data. Line 3
begins with a literal `\` — GNU sha256sum's escaped form. Line 5 is a digest with no path.)

--- PROBES 1..4, the shipped ENVIRON parser ---------------------------------------------------

Probe 4 requests `config/my library.db` — the fixture's line 1 path ENDS WITH it, so a suffix
test would return the digest. Exact equality returns empty.

--- PROBE 5, the same property from the other side --------------------------------------------
  requested /config/my library.db returned [aabb…8899]; the /srv/… line carries [1111…1111]

The fixture also carries `/srv/config/my library.db`, whose path ends with the probe-1 request.
The parser returned line 1's digest and never the /srv line's, so it picked the EQUAL line rather
than the suffix-matching one. R3-03 refused a suffix test by name because it converts a false

THIS PAIR IS THE WHOLE OF R4-09. The same requested path, the same fixture, the same program
apart from how the value arrives. `awk -v` turned the two-character `\s` into `s` before the
comparison and the line went unmatched; ENVIRON compared the path as written. The old form's
empty answer is the fail-closed behaviour described above — it routes to `unknown` and exit 3,
which is why this is a residual and not a false green.

§ 2  R4-10 — the cleanup gap at R3-04's two `exit 3` arms
================================================================================================

DISPOSITION: R4-10 IS A CLAIM CORRECTION AND NOTHING ELSE. NO CODE CHANGED. NO `trap` ADDED.

The review's own grading is that this is a PRE-EXISTING CLASS, not a new one, and that leaving
state behind on a could-not-look is arguably the right call for a forensic instrument. The defect
is that the gap was nowhere stated in band. It is now stated at the arms, in three graded parts:

  1. the class is pre-existing and shared with the two `exit 3` arms immediately above
     (`capture_manifests after … || exit 3` and `rsh_classify "the layer-3 hashes after the run"
     … || exit 3`). R3-04 increased the COUNT of such exits; it did not introduce the behaviour.
  2. the forensic rationale: the container scratch IS the evidence of what the run saw, and a
     cleanup firing on an unexplained exit destroys the record of why the instrument went blind.
  3. what is left behind, named: the container scratch at `$SCRATCH` and the host stamp at
     `$STAMP_REMOTE`. The operator command that clears the scratch is CITED BY ANCHOR — the
     step-1 precheck's `'nonempty '*` refusal arm, the one beginning "already exists inside the
     container and is not empty" — rather than duplicated, because two copies of a destructive
     command line in one file is exactly how GC-02's fences drifted apart in this very file.

WHY NO TRAP. `scripts/phase06-oracle.sh` has no `trap` anywhere, deliberately. A cleanup trap
would fire on EVERY `exit 3`, including the forensic ones point 2 exists to protect — a behaviour
change to the live path smuggled in under a comment-accuracy fix, in a round whose entire subject
is claims outrunning code. The verify block asserts the trap count is still zero:
