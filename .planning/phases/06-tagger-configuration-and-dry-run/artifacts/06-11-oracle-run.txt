§ 2  THE POSITIVE CONTROL — EVALUATED BEFORE THE DIFF, AND GATING IT
================================================================================

A transcript that proves nothing can still read as a pass by printing many lines
and exiting 0 (T-06-55).  Five conditions were evaluated BEFORE the diff.  Had
any failed, the verdict would be "UNKNOWN, not green", exit 3, and the diff would
NOT have been evaluated at all.  That is not hypothetical: it is what happened on
run 1 of 5 (§ 6.1).

  1. every payload line parses as a ' -> ' pair (or the two-line narrow form)
     unparsed payload lines ........................... 0        PASS
     A `--pretend` transcript fails this trivially and that is the mechanical
     discriminator: its lines are SOURCE paths, `lookup_candidates` never runs,
     and no destination is ever computed (D-33).

  2. the pair count EQUALS the sampled audio-file count — not "at least"
     pairs parsed ..................................... 174
     06-SAMPLE.md Files column sum ..................... 174     PASS

  3. `(N already in place)` is 0, READ EXPLICITLY
     beets logs it as `Moving 174 items.` on STDERR — the count is embedded in a
     log.info fragment, not printed as a standalone stdout line
     [beets/ui/commands/move.py@v2.12.0:94-107].  Read from there:
     Moving N items ................................... 174
     (N already in place) ............................. 0       PASS
     No parenthetical is present, and beets appends the fragment ONLY when
     num_unmoved > 0, so this is a POSITIVE zero from the same code path — not an
     absence of evidence.  On an in-place import nothing can be in place, so any
     other value would mean the run measured something other than what it claims.

  4. the transcript contains the substring '/media/Music/'
     .................................................. present  PASS

  5. the N in `Moving N items` equals the pairs parsed  174 == 174  PASS
     Added by this plan.  A transcript truncated in transit satisfies all four of
     the controls above.

  SGR-coloured lines in the raw transcript ............ 0
     `ui.color: no` is set, so none arrived coloured.  The normaliser strips SGR
     anyway (§ 6.2) and reported 0, which is the strip finding nothing to do
     rather than the strip not having run.

§ 6  THE FOUR FIRST-RUN FAILURES OF THE INSTRUMENT, AND WHAT WAS CHANGED
================================================================================
Recorded here because T-06-54 requires that a run which did not pass first time
says so, and because all four share one property: EACH PRODUCED A CONFIDENT,
GREEN-LOOKING ANSWER WHILE MEASURING THE WRONG THING OR NOTHING AT ALL.  None of
them was a defect in the `paths:` stanza or in 06-EXPECTED-TREE.txt.  The fix in
every case is in scripts/phase06-oracle.sh, commit c0b7123.

§ 6.1  RUN 1 — `import.duplicate_action: skip` DROPPED A WHOLE SAMPLED FOLDER.
  Symptom: 164 destination pairs against 174 sampled files.  Exit 3, UNKNOWN, and
  THE DIFF WAS NOT EVALUATED — the control did exactly its job.
  Cause: the S1 stratum deliberately drew TWO rips of Benson Boone / American
  Heart (24-bit FLAC and MP3).  That is the whole reason the stratum exists: it
  is the one predicted %aunique{} firing.  `skip` refused the second album, so
  the collision the fixture exists to test was removed from the library.
  Fix: `duplicate_action: keep` — imports both, deletes nothing.  The three
  alternatives are all wrong here: `remove` deletes source files with no prompt
  (rc6's own default, Pitfall 3), `merge` rewrites the album, and `ask` under
  `-q` falls back to skipping.
  Note this cuts both ways: `skip` was itself added in 06-09 as a Rule-2 safety
  deviation against `remove`.  Safe and faithful are different properties, and
  `keep` is the only value that is both.

§ 6.2  RUN 1 — `beet move -p` COLOURS ITS OUTPUT, SO NOTHING COULD EVER MATCH.
  Symptom: `/m<ESC>[1;32media/M<ESC>[39;49;00music/` — SGR runs interleaved
  THROUGH both paths by `colordiff` [beets/ui/commands/move.py@v2.12.0:57].
  Consequences, all three of which read as something other than what they were:
    * a coloured destination never equals a fixture line — 174 diff failures that
      would have looked like 174 path-template defects;
    * a coloured SOURCE never joins to the `beet ls -f` field view — CONF-03
      would have returned COULD NOT LOOK on all 174 rows;
    * `grep -q '/media/Music/'` returns NOTHING over a coloured transcript, so
      positive control 4 would have fired for a reason that is not a defect.
  Fix: `ui.color: no` in the overlay (at the source), AND normalise_transcript
  strips SGR into a `.clean` file regardless, so a transcript that arrives
  coloured by some other route still normalises to the same verdict.  The literal
  trailing space on the source half of the narrow form — `f"{color_source} \n
  -> {color_dest}"`, unconditional — is stripped with it, address-restricted to
  lines carrying no ' -> ' so that a DESTINATION really ending in a space would
  stay visible as the path-rule finding it would be.

§ 6.3  RUN 1 — THE `(N already in place)` CONTROL COULD NEVER FIRE.
  Symptom: the script reported "(N already in place): 0 [line ABSENT]".
  Cause: `move_items` builds the count as a fragment and hands it to log.info —
  `Moving 164 items (3 already in place).` on STDERR, embedded in one line.  The
  old predicate looked for a standalone `(N already in place)` line on stdout.
  That predicate CANNOT MATCH REAL OUTPUT.  It returned 0 and passed vacuously.
  This is the fifth instance in Phase 6 of a predicate that cannot match reading
  as a clean negative.
  Fix: read_unmoved() parses the log line; its ABSENCE is a COULD NOT LOOK, never
  a zero.  That also yields control 5 for free (§ 2.5).

§ 6.4  RUN 2 AND RUN 3 — TWO DEFECTS IN THE D-18 LEDGER.
  (a) Run 2: 60 `failed` records, all twelve S6 files, all five fields:
      "No such file or directory: '/home/beetle/Music/Katy Perry/…'".
      Cause: beets 2.12.0 stores an item path RELATIVE to the library directory
      when it sits underneath it, and re-absolutises it against `lib.directory`
      on read [beets/library/models.py@v2.12.0:130; Library._migrations carries a
      RelativePathMigration].  `Library(db)` alone falls back to platformdirs'
      user music path.  The affected stratum is exactly the one drawn FROM the
      library — i.e. exactly the files Phase 7 will re-tag.  Items under
      /downloads are outside the directory, stored absolute, and read correctly
      either way, which is why only S6 broke.
      Fix: `Library(db, directory=/media/Music)`, plus a self-test case that
      walks the payload's AST and requires the `directory=` keyword.
  (b) Run 3: 327 of 870 records reported as PROPOSED CHANGES, exit 1, RED.
      Cause: mediafile reports an absent tag as None, while beets' typed model
      reports the SAME absence as that field's own null.  Read off the engine:
        bpm Integer null 0 · comments String null '' · genres DelimitedString
        null [] · initial_key MusicalKey null None
      All 327 were None -> the field's null.  Not one had a non-empty `old`.
      Fix: both-sides-absent is marked `noop` AND flagged `null_equivalent`, the
      nulls are read off Item._fields at RUNTIME rather than hard-coded, the raw
      `old` and `new` stay in every record, and a real value becoming null stays
      a RED (driven by its own self-test case).

  --self-test grew 56 -> 73 cases across these fixes.  Every new branch is driven,
  and every new predicate was confirmed able to FAIL against a planted positive
  before its clean result was believed.
