PART 1 — GC-01: the size sweep that establishes the ceiling
================================================================================================

The shipped shape was, at scripts/check-beets-config.sh:554 and :567 (pre-fix line numbers):

    if printf '%s' "$raw" | grep -qF -- "$forb"; then

under this file's `set -euo pipefail` (:111). `grep -q` exits the instant it matches; `printf` is
still writing; `printf` takes SIGPIPE and exits 141; `pipefail` hands 141 to the PIPELINE; the
`if` therefore evaluates FALSE. Direction: a substring that IS present is reported ABSENT — a
false GREEN over a live condition, not a false red.

Driven at increasing input sizes with the forbidden substring on LINE 1, both forms, both grep
paths reachable from a bash script on this workstation (both resolve to /usr/bin/grep):

PART 2 — GC-01: the fix, and the self-test case that discriminates it
================================================================================================

Fix, at both sites (scripts/check-beets-config.sh):

    if grep -qF -- "$forb" <<<"$raw"; then

A here-string feeds grep from a temporary file. There is no writer to take SIGPIPE, no pipeline
for `pipefail` to propagate from, and the `if` reads grep's own status. `-F` is kept (the
substrings are literals) and the `--` end-of-options guard is kept (a substring beginning with `-`
must not be read as a flag). `LC_ALL=C` was deliberately NOT added: multibyte behaviour is
unchanged by this fix and changing two things at once would have destroyed the measurement.

`set +o pipefail` around the test was rejected: turning the option off weakens every other
statement in the same scope to buy one test.

New self-test case 7: `synthetic_correct_dump` prefixed by one top-level key whose double-quoted
scalar opens with the literal `Compilations` and is padded with `x` past the ceiling. Measured
raw size, asserted in band rather than assumed:

    case 7 precondition: raw dump is 71013 bytes, above the 65536-byte pipe-buffer ceiling

An under-65536 result is a self-test FAILURE, not a silent skip — a case that quietly shrinks
below the ceiling is a case that has stopped testing anything.

PART 3 — GC-13: case 6's two outcomes, counted independently
================================================================================================

`assert_beet_invocation_contract` reports THREE outcomes through ONE counter:

    real source violation                  -> cfg_fail -> ARM1_FAILS++
    synthetic negative CORRECTLY rejected   -> cfg_fail -> ARM1_FAILS++
    synthetic negative NOT rejected (BLIND) -> bare echo -> no increment

Case 6 compared that sum against the single expected total `1`. So "one real violation" plus
"the checker is blind" summed to 1 and the case reported `1 red, as expected`. Two faults
cancelled into a pass.

The fix counts them separately — ARM1_REAL_VIOLATIONS and ARM1_SYNTH_REJECTED, both re-initialised
per call, both carrying an UNKNOWN sentinel of -1 at script level so a gate reached without the
function having run FAILS rather than passing on a zero — and case 6 requires
`ARM1_REAL_VIOLATIONS == 0 AND ARM1_SYNTH_REJECTED == 1`. `run_case`'s identical-looking
`ARM1_FAILS -eq $expect_reds` comparison is deliberately LEFT ALONE: every red it counts comes
from the same pure function over one synthetic dump, so there the total is the whole outcome.
ARM1_FAILS keeps exactly the value it always had, because the live arm-1 summary line
(`arm-1 assertion failures:`) is a second consumer of it.

SIZE CLASS
  bounded    — the input cannot approach 64 KiB by construction (a single value, one command
               string, one mount-option list)
  unbounded  — it grows with the estate, so today's margin is not a control

FAILURE DIRECTION — the thing a reader needs and will not otherwise get. It depends entirely on
the SENSE of the test:
  POSITIVE assertion (`… || fail`, or match -> pass) — a 141 fires the failure branch when the
      file is CORRECT. A false RED. Noisy, self-announcing, not dangerous.
  INVERTED assertion (`if … ; then fail`) — a match IS the failure, so a 141 makes the `if` false
      and the assertion reports PASS at the precise moment it should have failed. A false GREEN.
      THIS is the dangerous half, and it is the defect class this whole gap closure exists to
      remove.
  CLASSIFY  — no verdict either way; a 141 mislabels or duplicates rather than passing or failing.
