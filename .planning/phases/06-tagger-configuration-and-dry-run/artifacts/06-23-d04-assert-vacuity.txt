HOW THE LADDER WAS DRIVEN — no hand transcription
-------------------------------------------------
The D-04 verdict ladder is pure local shell once the ssh returns, so it was extracted
VERBATIM out of `scripts/quick-health-check.sh` and run over a fixture supplied in
place of the ssh output. Extraction:

    awk '/D04_HITS=\$\(printf/{f=1} f && /^fi$/{exit} f' <copy-of-the-script>

(The `f &&` guard is load-bearing: `^fi$` occurs 17 times earlier in the file, so a
bare `/^fi$/{exit}` extracts nothing. Measured, not assumed — the first attempt
returned 0 lines.)

The harness then sets only the knobs the block reads, at their DEFAULT values
(D04_EXEMPT_BASELINE=5, D04_DOC_BASELINE=2, D04_OVERRIDDEN=0, EXIT_CODE=0), assigns
the fixture to D04_OUT, and sources the extracted ladder. The code under test is the
real code, byte for byte; only its input is synthetic.

PART 1 — GC-03: THE ASSERTED SET CAN BE EMPTY, AND THE BLOCK TICKED GREEN OVER IT
================================================================================

THE COUNTER SUBTLETY, MEASURED RATHER THAN REASONED
---------------------------------------------------
All five D-04 counts are produced by `printf '%s\n' "$SET" | grep -c '^HEAD:'`, and
`printf '%s\n' ""` emits a single BLANK line, not nothing. The plan flagged this as a
place where a guard could be written against a condition that is never true. Measured:

    $ EMPTY=""
    $ printf '%s\n' "$EMPTY" | grep -c '^HEAD:'      ->  0
    $ printf '\n'            | grep -c '^HEAD:'      ->  0
    $ CNT=0; while IFS= read -r l; do [ -z "$l" ] && continue; CNT=$((CNT+1));
      done <<< "$EMPTY"; echo $CNT                   ->  0

So `D04_N_ASSERT` IS genuinely 0 on an empty asserted set — the blank line does not
survive the `^HEAD:` anchor — and `-eq 0` is the correct condition to guard on. The
`while … <<< "$EMPTY"` loop confirmed at ZERO iterations, which is why `D04_BAD`
stays 0 and the ladder falls through to its green condition.

THE FIXTURE
-----------
GC-03's own scenario, built mechanically rather than by hand: take the REAL scan of
this repository's HEAD (199 lines) and remove the three asserted invocations, exactly
as deleting or reshaping them would:

    $ grep -vF 'beet_exec "${BEET_BIN}' raw.txt > fixture-allexempt.txt

    removed:
      HEAD:scripts/check-beets-config.sh:892:    beet_exec "${BEET_BIN} -l ${THROWAWAY_DB} -c ${OVERLAY} config -d"
      HEAD:scripts/check-beets-config.sh:908:    beet_exec "${BEET_BIN} -l ${THROWAWAY_DB} -c ${OVERLAY} config -p -d"
      HEAD:scripts/check-beets-config.sh:919:      beet_exec "${BEET_BIN} -l ${THROWAWAY_DB} -c ${OVERLAY} config -d -c"

    fixture: 196 lines -> executable 5, exempt 5, asserted 0.

Note what this fixture does NOT trip: raw is 196 (not 0, so guard 1 passes), raw 196 ≠
stripped 95 (so guard 2 passes), executable is 5 (not 0, so CONDITION K passes), the
exempt count is 5 = its pin, and the doc count is 2 = its pin. Every existing guard is
satisfied. That is the whole finding.

--------------------------------------------------------------------------------

independent guards. To show the second is load-bearing on its own, the arm was deleted
from the post-fix ladder (mutant, 83 lines) and the all-exempt fixture re-run:

code honestly, though: it is 0, because the green condition can only withhold a tick,
it cannot raise a red. That is exactly why the ARM is the primary fix and the green
condition is belt and braces, not the other way round.
