SECTION 1 — R3-01: the five surviving raw interpolations, before and after
=========================================================================
GC-17 (plan 06-26) rendered four overridable knobs through `printf '%q'` and stated in band that
FOUR was the total. Grep disagreed: five more knobs still crossed into a string a remote shell
parses. Four of the five failed CLOSED on a space; the fifth, EXTCONF_PATH, used a hand-escaped
`"` wrapper around the path variable inside a single-quoted remote `sh -c` — the construction
GC-17's own prohibition paragraph forbids by name, sixty lines above it in the same comment block
and three hundred lines above the site.

GRADING, kept as the review wrote it and not inflated: this is a WARNING, not a Critical.
EXTCONF_PATH is an operator-set environment knob with a safe default, it is ADDITIVE (any
non-default value already forces EXIT_CODE=1, so it can never produce a green tick), and the
injection consequence is STATIC REASONING THAT WAS NOT EXECUTED. What makes it a finding is that
round 2 declared the class closed while a documented-forbidden instance of it survived.

  D03_FLASK_CONTAINER    -> docker inspect … --format

READ THE SECOND EXTCONF_PATH BLOCK CLOSELY — it is the one that justifies changing the SHAPE of
that site rather than just giving it a `_Q`. The BEFORE program text

    cat "/config/x";cat /etc/hostname;#"

is TWO commands to the container's /bin/sh, not one path. A `_Q` rendering alone would not have
fixed this: `%q` renders for a bash WORD, and this value lands inside the TEXT of a single-quoted
program, which is the one context `%q` is not correct for. Only the positional form removes the
path from the program text entirely. This is the same reasoning scripts/phase06-oracle.sh's
remote_sh_c() states at its own definition (WR-08 / GC-11).

Reminder of the bound, so this artifact does not read as an incident report: the value above is
one an OPERATOR would have to set deliberately. It was never set, the string above was never
sent, and the default `/config/extended.conf` is unaffected by the change.
