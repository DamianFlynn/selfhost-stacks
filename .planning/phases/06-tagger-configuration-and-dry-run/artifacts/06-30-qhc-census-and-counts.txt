READ THE SECOND EXTCONF_PATH BLOCK CLOSELY — it is the one that justifies changing the SHAPE of
that site rather than just giving it a `_Q`. The BEFORE program text

    cat "/config/x";cat /etc/hostname;#"

is TWO commands to the container's /bin/sh, not one path. A `_Q` rendering alone would not have
fixed this: `%q` renders for a bash WORD, and this value lands inside the TEXT of a single-quoted
program, which is the one context `%q` is not correct for. Only the positional form removes the
path from the program text entirely. This is the same reasoning scripts/phase06-oracle.sh's
remote_sh_c() states at its own definition (WR-08 / GC-11).

Reminder of the bound, so this artifact does not read as an incident report: the value above is
one an OPERATOR would have to set deliberately. It was never set, the string above was never
sent, and the default `/config/extended.conf` is unaffected by the change.


SECTION 2 — R3-05: the thirteenth notice's counts, re-measured
==============================================================
R3-05 is a CLAIM CORRECTION ONLY. No behaviour changed, no code moved, no fourteenth notice was
added, and the header count did not move.

Both greps run with /usr/bin/grep by ABSOLUTE PATH. The operator's zsh aliases grep to ugrep, and
a bare `grep` in a script is BSD grep on this workstation; neither gives the same answer reliably.

  HEADER COUNT  (the durable one — this is what "the Nth notice" means):
      /usr/bin/grep -c '^# ⚠️  EXIT-CODE BEHAVIOUR CHANGE[D]' scripts/quick-health-check.sh

  RAW COUNT     (every occurrence of the shared phrase anywhere in the file, including inside
                 notices that quote it):
      /usr/bin/grep -c 'EXIT-CODE BEHAVIOUR CHANGE[D]' scripts/quick-health-check.sh

Both recipes are written with the final letter BRACKETED. `CHANGE[D]` is a valid grep pattern that
matches the real occurrences, while the recipe text itself is not an occurrence — so a recipe
written in band, or repeated here, does not perturb the number it asks you to measure. Do not
"fix" the brackets.

MEASUREMENTS (dated observations, 2026-09-23 — NOT pins):

  before plan 06-30:   headers 13   raw 17   delta 4
  after  plan 06-30:   headers 13   raw 17   delta 4

The header count did NOT move, which is the assertion that matters: plan 06-30 added no fourteenth
notice. The raw count did not move either, because the recipes written into the thirteenth notice
use the bracketed form and are therefore not occurrences of the phrase they measure. That is the
whole reason for the brackets, demonstrated rather than argued.

WHY THE RAW COUNT IS DELIBERATELY NOT PINNED ANYWHERE. The same reason 06-DISPOSITIONS-GAP.md

The header count is durable because a notice header is a deliberate, countable act; the raw count
is a side effect of prose. Count the headers. Run the recipe for the raw figure when you need it.
