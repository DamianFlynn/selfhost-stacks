PART 1 — R4-03: THE DASH DRIVE, BOTH DIRECTIONS, WITH A POSITIVE CONTROL
================================================================================
Method: a standalone harness in a `mktemp -d` emits a synthetic program that reproduces the trap
shape of the real in-container program over a real `mktemp`-minted scratch path of the same
template, runs it under /bin/dash, delivers a signal after 1 s, and reports the wait status, the
scratch path's survival, and whether the program ran past the signal. Two families are driven:

    mf       reproduces write_prog_manifest's MANDIR trap   (mktemp -d, rm -rf)
    taghist  reproduces write_prog_taghistory's THPROG trap (mktemp,    rm -f )

DELIVERY WITNESS — why this harness reports an extra column.
Each program prints, at phase 2, whether its scratch path still exists. Without that column
"the trap absorbed the signal" and "the signal was never delivered" are INDISTINGUISHABLE: both
present as exit 0 with the scratch gone by the EXIT trap. `scratch-at-phase2=GONE` on a signalled
run and `PRESENT` on the control is the proof the signal arrived.

`set -m` IN THE HARNESS IS LOAD-BEARING. POSIX requires a shell without job control to start a
background command with SIGINT and SIGQUIT set to SIG_IGN, and a signal inherited as ignored
cannot be trapped. The first run of this drive, without `set -m`, reported SIGINT as
"ran past the signal, exit 0" for BOTH shapes — a non-delivery that would have read as
"the defect reproduces" and "the fix does not work" from the same artefact. Recorded because it
is exactly the class of false reading this round exists to stop.

THE SINGLE-QUOTE CONSTRAINT, AND WHY IT RELAXED. The old predicate lived inside a trap body,
which is a single-quoted string, so `""` and not `''` was required for the empty pattern — an
inner single quote would have terminated the body. The predicate now lives in a shell FUNCTION
defined outside any trap, so that constraint no longer binds it. It was nevertheless left
byte-identical: changing `""` to `''` would have been a gratuitous edit to the one fence round 4
certified, and dash treats the two patterns identically anyway. The constraint still binds the
four trap bodies themselves, and none of them contains a single quote.

PART 4 — R4-04: WHAT THIS ARTIFACT DOES **NOT** PROVE
================================================================================
THE DRIVE PROVES THE HANDLER SHAPE. IT PROVES NOTHING ABOUT DELIVERY IN THE CONTAINER.

Established, and grep-confirmable in the file:
  * the transport is `ssh … "timeout $REMOTE_TIMEOUT docker exec -i -u beetle $CONTAINER sh -s…"`
  * a POSIX shell does not run its EXIT trap on an uncaught signal
  * on the shape shipped, a delivered INT/TERM/HUP was absorbed and the program continued (above)
  * on the shape shipped, an untrapped SIGPIPE ran no trap and leaked the minted path (above)

NOT established, and deliberately not tested (this phase makes no estate contact):
  * that `timeout` delivers SIGTERM to the **in-container** shell. `timeout` signals the
    `docker exec` CLIENT on LXC 100, and `docker exec` is not known to forward signals to the
    exec'd process. If that holds here, the `TERM` arm never fires for these programs at all.

Believed, on reasoning of the SAME grade as the line above — NOT an upgrade over it:
  * when the client dies the daemon tears the exec's streams down, and the in-container shell
    takes EPIPE/SIGPIPE on its next write to stdout. Both programs write to stdout. This is why
    `PIPE` joined the list. It is a candidate `FIXED (undriven)` row, exactly as R3-09 was.

NEITHER TRAP HAS EVER BEEN OBSERVED FIRING INSIDE `beets-flask`. The driving condition is a live
`--arm a` / `--arm b` pair under a deliberately short `REMOTE_TIMEOUT`, checking the container's
`/tmp` afterwards for surviving `/tmp/p6-mf.*` and `/tmp/p6-taghist.*` names. That attaches to
the EXISTING Phase 7 entry criterion **E12**; no new criterion is invented, and DEF-06-34-04 /
DEF-06-34-06 already sit there.

SIGKILL remains untrappable and is still a genuine residual, consistent with DEF-06-34-06. What
changed is that the round-3 framing — "widening the list SHRINKS the window" — under-described
the defect: on the non-terminal handlers the signal was ABSORBED, not narrowed.
