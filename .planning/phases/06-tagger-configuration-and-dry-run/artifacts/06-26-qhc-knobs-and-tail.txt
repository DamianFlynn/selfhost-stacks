Each knob is rendered ONCE with `printf '%q'` beside its own override-contract
block, and it is the RENDERED form that is interpolated:

    1449:    DRIFT_REPO_ROOT_Q=$(printf '%q' "$DRIFT_REPO_ROOT")

NOT DONE, deliberately: no quote was hand-escaped inside any command string. A
`\"` wrapper survives a space but not a quote and not a `$`, and a half-measure
that looks like a fix is worse than the raw interpolation it replaces.

UNCHANGED, deliberately: the shape of every `ssh` call, every `RC=$?` line
directly beneath it (the "no local pipe before capturing the status" discipline),
and the semantics of every remote command.

THREE SITES — naming GC-17 and GC-11. `printf '%q'` renders for bash: a
single-line path with a space becomes a backslash escape any POSIX shell accepts;
a value containing a NEWLINE becomes bash ANSI-C `$'…'` quoting, which requires
root's login shell on 172.16.1.159 to be bash. It is. And a non-bash shell fails
LOUDLY with a syntax error and a non-zero status — landing in each block's
could-not-look arm — not quietly with a mangled command. Fail-closed; the same
grading GC-11 gave the identical dependency in phase06-oracle.sh's remote_sh_c().

1.4 ⚠️ THE PLAN'S OWN TASK-1 VERIFY METHOD IS WRONG. REPORTED, NOT ABSORBED.
--------------------------------------------------------------------------------

The plan asserts, for each of the four tokens:

    test "$(grep -v '^[[:space:]]*#' … | grep -cF 'cd $D04_REPO_ROOT')" -eq 0

`grep -F` matches a SUBSTRING. `cd $D04_REPO_ROOT` is a PREFIX of the fixed
line's `cd $D04_REPO_ROOT_Q`. So the plan's own verify reports 1 — i.e. FAILS —
on a CORRECTLY fixed file. Measured on the fixed file:

    the plan's method, verbatim (it expects 0):
      cd $DRIFT_REPO_ROOT        -> 1
      cd $D03_REPO_ROOT          -> 1
      cd $D04_REPO_ROOT          -> 1
      bash $CONSUMERS_SCRIPT     -> 1

    corrected method — require the token NOT to be followed by `_Q`, i.e. add the
    trailing separator that makes it a whole token:
      'cd $DRIFT_REPO_ROOT '     -> 0
      'cd $D03_REPO_ROOT '       -> 0
      'cd $D04_REPO_ROOT '       -> 0
      'bash $CONSUMERS_SCRIPT '  -> 0

METHOD WRONG, CONCLUSION RIGHT. The fix is what the plan asked for; the
instrument could not see it. The corrected method is the one recorded here and in
the SUMMARY's verification table. This is the fifth plan in this round whose
verify carried a wrong premise, which is itself the finding worth keeping.
