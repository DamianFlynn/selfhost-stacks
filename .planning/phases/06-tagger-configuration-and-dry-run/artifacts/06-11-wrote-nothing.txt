VERDICT: the dry run WROTE NOTHING, on all three layers, with no layer reporting
"could not look".

  This plan writes nothing into /mnt/tank/media and nothing into
  /mnt/tank/downloads.  Both are PROVEN below, not assumed.

  The vocabulary throughout is THREE-OUTCOME and never two:
      identical  /  CHANGED  /  COULD NOT COMPARE
  "could not look" is kept distinct from "nothing is wrong" (CLAUDE.md § Health
  Checks).  A `diff` that exits >= 2 writes to stderr and leaves STDOUT EMPTY;
  read as `d="$(diff …)"; [ -z "$d" ]`, that empty stdout reports as "identical
  before and after".  manifest_compare() refuses to make that mistake.

LAYER 1 — LIBRARY, STRUCTURAL.  /media IS MOUNTED RW=false.
================================================================================
Read from the RUNTIME (`docker inspect`), NEVER from the compose file.  The
compose file is the intent; the inspect output is the fact, and only one of them
is what the kernel enforces while the run happens.

  docker inspect --format '{{range .Mounts}}{{.Source}}|{{.Destination}}|{{if .RW}}rw{{else}}ro{{end}}{{"\n"}}{{end}}' beets-flask

  /mnt/fast/appdata/arrs/beets/config/beets-flask/config.yaml|/config/beets-flask/config.yaml|ro
  /mnt/fast/appdata/arrs/beets/logs|/logs|rw
  /mnt/tank/downloads|/downloads|rw
  /mnt/tank/media|/media|ro
  /mnt/fast/appdata/arrs/beets/config|/config|rw
  /mnt/fast/appdata/arrs/beets/config/config.yaml|/config/config.yaml|ro

  ASSERTION: the mount whose Destination is `/media` carries RW=false.
  RESULT: HELD.  RW=false.  (D-05.)

  This is the only control in this document that CANNOT FAIL OPEN.  Note also
  what the assertion does when no /media mount is enumerated at all: that is a
  COULD NOT LOOK and exits 3 — it is NOT "/media is read-only", because nothing
  was inspected and so nothing is known.

  ⚠ /mnt/tank/downloads is mounted rw, which is why layers 2 and the -newer
  sweep exist.  The 174 sampled audio files across ten folders are 162 under
  /downloads (writable) and 12 under /media (read-only).  Only `write: no`,
  `copy: no`, `move: no` and the checksum manifests separate a dry run from a
  real one on the writable side.

catches content; together they also catch ADDITIONS and DELETIONS, because a
vanished or a new path changes both listings.  A count would catch none of that.

================================================================================
WHY THE DRY RUN COULD HAVE WRITTEN, AND WHAT STOPPED IT
================================================================================
Three trust boundaries, from the plan's threat model, and what held each:

  dry run -> /mnt/tank/downloads (rw)
      Only `write: no` / `copy: no` / `move: no` in the `-c` overlay and a
      checksum manifest separate a dry run from a real one.  All three keys are
      stated explicitly — `copy: no` does NOT imply `move: no`, they are
      independent keys and copy=no with move=yes is a MOVE.  Layer 2 is what
      proves it rather than trusting it.  Note the vendored /config/config.yaml
      sets `import.write: yes` as PHASE 7 behaviour, so EVERY Phase 6 invocation
      must override it; this one did.

  throwaway library -> real library.db / state.pickle
      `-l` does not redirect `statefile:`.  The overlay names both.  Layer 3 is
      what proves the redirect worked.

  a duplicate album -> deletion
      rc6's own default for `import.duplicate_action` is `remove`, which deletes
      duplicates with NO PROMPT, and the sample deliberately contains two rips of
      the same album.  The overlay sets `keep`, which imports both and deletes
      nothing.  Layer 2's sha manifest over both folders is the proof that
      nothing was removed: 190 files before, 190 after, identical content.
      (This plan changed that key from `skip` to `keep`; see 06-11-oracle-run.txt
      § 6.1.  `skip` was also non-deleting, but it dropped ten files from the
      measurement.)
