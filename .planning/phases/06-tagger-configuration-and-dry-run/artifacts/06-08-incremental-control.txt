WHY `statefile` IS NAMED SEPARATELY FROM `library`
  `-l` does NOT redirect `statefile:`. `ImportState.__init__` reads
  `config["statefile"].as_filename()` and there is NO CLI flag for it
  [SOURCE: beets/importer/state.py@2.12.0]. An arm run with `-l` alone would have
  written the REAL /config/state.pickle and silently poisoned `incremental` for the
  real library. Every invocation here sets `library`, `statefile` AND `directory`.

WHY `write: no` IS NOT OPTIONAL
  /downloads is mounted rw on this container, and the repo's committed config.yaml sets
  `import.write: yes` as PHASE 7 behaviour. Every Phase 6 invocation must override it.
  Section 6 below is the assertion that it held.

WHY THE SKIP IS DETERMINISTIC AND OFFLINE
  `_summary_judgment()` returns APPLY only when the recommendation is `strong`, else it
  returns `quiet_fallback` [SOURCE: beets/ui/commands/import_/session.py@2.12.0:328-360].
  Both overlays set `plugins: []`, so no metadata source is enabled, no candidate can be
  produced, and the recommendation can never be `strong`. The skip therefore does not
  depend on MusicBrainz being reachable or on what MusicBrainz happens to return today.
  A control whose outcome moves with a third party's database is not a control.

================================================================================

`bash scripts/phase06-incremental-control.sh --self-test` exits 0. It needs no ssh and
no docker, and it drives EVERY refusal and EVERY blind branch — a fail-closed instrument
that is never seen to fail closed is an assumption, not a control.

  1/5  the taghistory classifier, over REAL pickles, using the SAME probe source the
       container runs (not a paraphrase of it):
         populated taghistory                 -> populated
         readable EMPTY taghistory            -> empty
         ABSENT state file                    -> absent      (NOT "empty")
         unpicklable state file               -> unreadable  (UNKNOWN, not green)
         pickle that is not a dict            -> unreadable
         dict with no taghistory key          -> unreadable
         no marker line at all                -> unreadable
  2/5  the one-key overlay control:
         the real pair (one key apart)        -> accept
         a pair differing in TWO keys         -> refuse
         a pair with a stray whitespace edit  -> refuse   <- a diff-line count alone
                                                             would have PASSED this
         a pair with no differing key         -> refuse
         a missing overlay file               -> could-not-look (not accept)
  3/5  the preflight refusals, driven for real against real directories:
         a root outside the two throwaway roots       -> refuse
         a DIRTY destination (leftover entry present) -> refuse
         a clean destination, unreachable source      -> could-not-look (not accept)
  4/5  the three-outcome manifest comparison: identical / differs / could-not-look,
       including two EMPTY manifests -> could-not-look, so nothing passes vacuously.
  5/5  the source fence, including a `..` walk out of the allow-prefix and a path
       pointing at the real library.

10. NOTES, CORRECTIONS AND ONE INSTRUMENT DEFECT
================================================================================

(a) THE PLAN'S tmpfs PREMISE IS WRONG, IN THE SAFE DIRECTION.
    The threat register (T-06-39) and the plan's text say the container's /tmp is tmpfs
    on LXC 100 and that trees left there consume host RAM. MEASURED 2026-09-21: the
    container's /tmp is on the docker OVERLAY — `df /tmp` inside the container reports
    `overlay 126G 95G 25G 80% /`, and `mount` shows no tmpfs at /tmp. LXC 100's own /tmp
    IS tmpfs (that is the 1.1 GB EPG incident), but a `docker exec` never touches it.
    So the RAM hazard does not apply as written. The real, smaller hazard is the 126 G
    ext4 root with 25 G free — the same filesystem six stacks already write to silently.
    Cleanup is still required and was still done; the reason is disk, not RAM.

(b) `--pretend` WAS USED FOR EXACTLY ONE QUESTION, AND THE PROHIBITION IS IN THE SCRIPT.
    Step 4 asks "is the folder still OFFERED?". `--pretend` answers that and reaches
    neither `save_history()` nor `save_progress()` — both are called only from
    `finalize()` [SOURCE: beets/importer/tasks.py@2.12.0:310-319], which the pretend
    path never reaches — so using it to read the state cannot mutate the state being
    read. D-33's prohibition on using it as a TREE oracle is written into the script's
    own header: it prints SOURCE paths and no destination, so a long transcript says
    nothing about where files would land. The tree oracle is `beet move -p`, whose lines
    contain ` -> `.

(c) THE SKIP REACHING finalize() IS NOT AN ASSUMPTION.
    `manipulate_files` calls `task.finalize(session)` OUTSIDE its `if not task.skip:`
    block [SOURCE: beets/importer/stages.py@2.12.0:288-314, read out of the running
    container, not out of a changelog]. Arm A's populated taghistory is the runtime
    confirmation.

(d) AN INSTRUMENT DEFECT IN THE PLAN'S OWN VERIFICATION LINE, RECORDED NOT SILENTLY FIXED.
    The plan's verification says:
      grep -n 'timeout \$REMOTE_TIMEOUT.*|' scripts/phase06-incremental-control.sh
      returns only lines whose command string contains `pipefail` or ends in `grep -q`.
    It returns two lines — but only because `.*|` also matches the `||` in
    `|| RE_RC=$?`. Neither line contains a PIPE. Both redirect stdout and stderr to
    files and read the exit status explicitly on the same line. The check's intent
    (no unguarded pipeline carrying a verdict) is satisfied; the regex is what is loose.
    Recorded rather than worked around, because a future reader will run the same grep.

    Related, and the reason it matters here: the container's /bin/sh is dash
    [MEASURED 2026-09-21: /bin/sh -> dash], which does NOT support `set -o pipefail`.
    That is why the remote programs contain no pipeline whose failure could be
    swallowed, and why they are shipped on stdin with their arguments as positional
    parameters rather than interpolated into a command line.

(e) NO ARM WAS RETUNED. Both arms produced their expected outcome on the FIRST run of
    the committed script. The mechanics had been established beforehand in a throwaway
    probe (which is where finding (a) and the never-created-statefile finding in
    section 3 came from); no overlay was adjusted after seeing an arm's result. A
    control tuned until it agrees with the plan is not a control.
