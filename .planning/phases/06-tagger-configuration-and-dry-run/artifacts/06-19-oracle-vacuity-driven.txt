4.  WR-01 — THE PROBE, AND THE PIPELINE IT REPLACES
================================================================================

  The old shape, and the one line in the file that broke the file's own house
  rule at :201-202 ("THE CONTAINER'S /bin/sh IS dash AND HAS NO `pipefail`. So
  no command sent INTO the container carries a pipeline at all"):

      [ ! -e "$1" ] && echo absent || ls -A "$1" | head -n 1

  The new shape, SCRATCH_PROBE_PROG, defined with the remote layer so the
  self-test can drive it:

      if [ ! -e "$1" ]; then echo absent; exit 0; fi
      if [ ! -d "$1" ]; then echo notadir; exit 0; fi
      out=$(find "$1" -mindepth 1 -maxdepth 1) || exit 4
      if [ -z "$out" ]; then echo empty; exit 0; fi
      nl="
      "
      printf "nonempty %s\n" "${out%%$nl*}"

  WHY IT CANNOT SILENTLY EXIT 0 ON AN UNREADABLE DIRECTORY (the comment the
  plan asked for is at the definition in the script):

    * There is NO PIPELINE, so there is nothing that can launder a status.
    * `find` on a directory it cannot read writes a diagnostic to stderr and
      returns NON-ZERO.  That non-zero is exactly the status `| head` threw
      away.
    * It is read by `||` ON THE SAME LINE, because the only command in that
      assignment is the command substitution and POSIX specifies such an
      assignment's exit status IS the substitution's.
    * The probe exits 4, `docker exec` propagates it, `rsh` records it in
      RSH_RC, and the call site's first guard refuses on it.
    * THE ANSWER IS ALWAYS A WORD — absent / empty / notadir / "nonempty
      <entry>".  Emptiness of stdout is no longer evidence of anything, and an
      unrecognised word falls to a `*)` arm that REFUSES rather than guessing.
    * stderr is deliberately NOT redirected, so find's own diagnostic reaches
      the operator and explains the exit 4.

  DRIVEN, five states, local /bin/sh, no container (scratchpad `probe-test.sh`,
  and the same five cases live in `--self-test` § WR-01):

      nosuch     rc=0 out=<absent>
      emptydir   rc=0 out=<empty>
      full       rc=0 out=<nonempty …/full/overlay.yaml>
      afile      rc=0 out=<notadir>
      noread     rc=4 out=<>

  THE DRIVEN RED — the OLD shape over the SAME fixtures.  This is the finding
  itself, measured rather than argued:

      nosuch     rc=0 out=<absent>
      emptydir   rc=0 out=<>
      full       rc=0 out=<lib.db>
      noread     rc=0 out=<>            <-- IDENTICAL to emptydir

  `noread` and `emptydir` are byte-identical in both status and output under
  the old shape.  The precheck had no way to tell them apart, which is why it
  printed the green line for both.

  1.  WR-01 INSIDE THE CONTAINER.  The probe's program TEXT is driven, locally,
      by `--self-test` over all five states including the unreadable one, and
      the old shape is driven red beside it.  What is NOT driven:

            measurement;

        (c) a $SCRATCH unreadable BY `beetle` SPECIFICALLY inside the container.
      CONDITION THAT WOULD DRIVE IT: a container with `/tmp/p6` present and

      actually leaves, reached by `docker exec -u root beets-flask mkdir -m 700
      /tmp/p6` before a `--run`.  It is a REFUSAL PATH, so if the construction
      is wrong it can only refuse a run that would otherwise have proceeded —
      redder, never greener.

  2.  THE FOUR NEW REFUSALS FROM A REAL ORACLE RUN.  WR-02's empty manifest,
      WR-06's blind report, IN-12's empty field view and IN-09's zero DJ count

      phase's committed sample can reach — which is precisely why all four sat
      undetected.

  3.  THE DOUBLED UNKNOWN FOR AN EMPTY fields.tsv.  The decision in § 2 is
      driven at the FUNCTION level (report_multi_artist returns 2 on an empty
      file; the field-view read returns 2 on the same file), but the two

      that needs a live run whose `beet ls` returns nothing.

  4.  `assert_field_view`'s BAD-COLUMN arm FROM A REAL PATH CONTAINING A TAB.
      Driven synthetically with a five-column row.  The behaviour is unchanged
      from the inline code it replaces; only the empty-input arm is new.

  5.  THE `notadir` ARM at the dirty-destination precheck.  Driven at the
      program level (a regular file answers `notadir`); the CALL SITE's
      precheck_fail for it has never fired.  CONDITION: `$SCRATCH` existing as
      a regular file inside the container.

  6.  THE `*)` UNRECOGNISED-ANSWER ARM.  Unreachable while the probe and the

  7.  THE EXIT-CODE NUMBERING DIFFERENCE between the two sibling scripts.  Not
