11. DEFECTS FOUND IN THIS PLAN'S OWN <verify> BLOCKS, AND THE MEASUREMENTS
--------------------------------------------------------------------------------

All five merged gap-closure plans in this phase found defects in their own plan's
verify blocks, and 06-19 called it systemic. 06-17's carried two. Both were
FIXED BY STRENGTHENING, never by relaxing the assertion they were meant to make.

  V-1  TASK 1's NEVER-SUMMED GREP IS CASE-SENSITIVE AND FIRED A FALSE RED.
       As written:  grep -qE "never (be )?summed|NEVER summed"
       The file's dominant emphasis register is FULL CAPS — "KEEP THIS HEADING
       LITERAL", "READ-ONLY BY CONTRACT", "UNKNOWN, not green" — so the clause
       was written "ARE NEVER SUMMED INTO ONE CONF-04 ANSWER", and the pattern's
       three alternatives do not include it. OBSERVED FIRING against correct
       content:

           $ grep -nE "never (be )?summed|NEVER summed" scripts/check-music-consumers.sh
           (no output, rc=1)
           $ grep -niE "never (be )?summed" scripts/check-music-consumers.sh
           139:#     (c) THE JELLYFIN AND THE MA VERDICT ARE STILL SEPARATE AND ARE NEVER SUMMED ...

       This is cross-plan warning #7, the local/remote case-sensitivity split,
       appearing in a purely local form. The evidence that it is an oversight
       rather than intent: the grep IMMEDIATELY BEFORE it on the same line
       already carries -i.
       FIX: -i, plus the two clauses the plan's acceptance criterion names but
       its verify never checked (not-a-failure, not-green), plus a requirement
       that all three live INSIDE the header comment block rather than anywhere
       in the file, plus a byte-exact check on the green banner text and a count
       of 2 on the pending-branch exit-status comments.

  V-2  TASK 2's `printf | grep -q` IS A LATENT 141-PROPAGATOR, ~17% FROM FIRING.
       As written, twice:  printf "%s\n" "$s" | grep -q ...   under set -o pipefail
       This is cross-plan warning #1. It does NOT fire today — measured, not
       assumed, with a pattern matching the FIRST line so `grep -q` is guaranteed
       to close the pipe immediately:

           $ printf '%s\n' "$s" | grep -q '^' ; echo rc=$?
           rc=0
           $ printf '%s\n' "$s" | grep -qE 'CONSUMERS_RC" -eq 3' ; echo rc=$?
           rc=0

       It survives for a reason that is an accident of size rather than a
       property of the construct — the comment-stripped stream fits inside the
       pipe buffer, so the writer never blocks and never observes the closed
       pipe:

           $ grep -v "^[[:space:]]*#" scripts/quick-health-check.sh | wc -c
           54526                       <- against a 65,536 B macOS pipe ceiling

       scripts/quick-health-check.sh has GROWN ON EVERY PLAN OF THIS PHASE. When
       the stripped stream crosses 64 KB this assertion begins firing its FAILURE
       branch exactly when the file is correct. Removed rather than left as a
       time bomb.
