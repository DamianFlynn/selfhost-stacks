DEVIATIONS — TWO OF MY OWN INSTRUMENTS WERE DEFECTIVE, AND BOTH ARE LEFT VISIBLE
--------------------------------------------------------------------------------
DEVIATION 1 — the in-script pre-state API probe was a silent no-op.
  Stage A's script called `docker exec beets-flask /venv/bin/python - <<'PY'` WITHOUT `-i`.
  Without `-i` docker does not attach stdin, so python read EOF from `-` immediately, printed
  nothing and exited 0. The transcript shows section A3 with its route lines and then no
  output at all — which reads like an empty result but is really "could not look".
  The pre-state recorded above is therefore NOT from that probe. It is from the interactive
  route-discovery probe run a few minutes earlier in the same session, before stage A
  created anything, which returned `{"items":[],"next":null}` on BOTH
  `/api_v1/session/` and `/api_v1/dbfolder/`. That is a genuine pre-state and it is what is
  quoted. Stages B and C use `docker exec -i` and produced output correctly.
  This is 02.1-06's Debug-liveness bug in a new costume: an instrument that cannot speak
  returns the same silence as an instrument reporting nothing wrong.

DEVIATION 2 — the poll loop's instrument-2 predicate asked the wrong question, and reported
  a FALSE NEGATIVE for the whole 242 s bound. The loop counted occurrences of the folder NAME
  inside the `/api_v1/session/` response body. A session record carries only `folder_hash`;
  it never carries the path. So the count was structurally pinned at 0:

      elapsed=0s    log_matches=2  api_matches=0
      elapsed=10s   log_matches=2  api_matches=0
      ...  (25 polls, identical) ...
      elapsed=232s  log_matches=2  api_matches=0
      bound 240 s exceeded at elapsed=242s
      LOG_HIT=1  API_HIT=0

  The loop's own summary line therefore says `API_HIT=0`. IT IS LEFT IN THE TRANSCRIPT ABOVE
  WITH THAT FAILURE VISIBLE, because the defect is the useful part. `api_matches=0` was
  "my predicate cannot match" — not "the API has no session". The very next read, at B4,
  returned `items: 1` against the same endpoint at the same instant.
  Resolved in stage C by joining on the real key (`session.folder_hash == dbfolder.id`), and
  corroborated by instrument 3, whose `task.toppath` carries the path literally.
  CARRY-FORWARD: before polling an API for a string, confirm the schema actually contains
  that string. A poll predicate that cannot match is indistinguishable from a dead service.

Neither deviation changed a fact. Both changed how long it took to see one, and the second
would have been reported as "the inbox did not fire" by anyone who stopped at the loop's
summary line.
