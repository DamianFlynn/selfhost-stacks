READING OF SECTION 2, stated so the capture is not over- or under-claimed.

1. THE DEFAULT CASE IS BYTE-IDENTICAL BEFORE AND AFTER for DASH_RESOLVE_IP, and differs for the
   drift pairs only by the now-unnecessary quote characters. `printf '%q'` leaves a word with no
   metacharacters untouched. So this change is a no-op on every real run, which is exactly what a
   correctness fix to an override path should be.

2. THE SPACE CASE SURVIVES BOTH WAYS FOR THE DRIFT PAIRS — argc=4 before and after, same $3. That
   is not a contradiction of R4-01: the ⛔ paragraph says in terms that a hand-escaped wrapper
   "survives a space but not a quote and not a $". The space case is precisely the case the old
   shape handles. It is captured anyway as the control that proves the harness is faithful.
   For DASH_RESOLVE_IP the space case DOES split before the fix, adding a stray `evil.example`
   argument to curl — which is why curl fails loudly there rather than quietly.

3. THE QUOTE CASE IS THE ONE THAT MATTERS, and it is decisive:
       BEFORE: argc=2, and the path argument is EMPTY.
   The embedded `"` terminates the wrapper early, the remote shell re-parses the remainder as
   command text, and `_drift_pair` is called with two arguments instead of four — so `$3` is unset
   and the `sha256sum "$3"` inside the function body hashes nothing. AFTER: argc=4 and the full
   path arrives intact, quote and all.

4. THE BOUND, UNCHANGED AND NOT INFLATED. None of this can produce a green tick. Any non-default
   DRIFT_APPDATA_ROOT already forces EXIT_CODE=1 at the override guard, and a broken remote command
   lands in the could-not-look arm. There is no privilege crossing: the operator who can set the
   knob already has root on LXC 100. THE DEFECT R4-01 REPORTS IS THE CLAIM — round 3's sentence
   saying the forbidden-shape class was closed — NOT AN EXPLOIT.

SECTION 3 — R4-08: THE WIDENED CENSUS RECIPE
================================================================================

DISPOSITION: CLAIM CORRECTION ONLY. The recipe lives in a comment. No executable line changed in
task 2, no call site moved, and no `_Q` rendering was added by it. Widening code to make the old
recipe complete would have been the exact inversion this round exists to stop.

THE CHANGE. The census block's SECOND grep went from requiring a literal `-n`:

    OLD:  /usr/bin/grep -n  'ssh -n \$SSH_OPTS'         scripts/quick-health-check.sh
    NEW:  /usr/bin/grep -nE 'ssh (-n )?\$SSH_OPTS'      scripts/quick-health-check.sh

The FIRST grep (the knob-definition pattern) is byte-unchanged — the review does not fault it and
re-deriving it would be scope creep.

--------------------------------------------------------------------------------
3a. WHAT THE WIDENING BOUGHT — hit counts, old pattern vs new

    $ /usr/bin/grep -c  'ssh -n \$SSH_OPTS'        scripts/quick-health-check.sh
    18
    $ /usr/bin/grep -cE 'ssh (-n )?\$SSH_OPTS'     scripts/quick-health-check.sh

Two more. Those two are exactly the sites IN-02 / R4-08 names:

    $ /usr/bin/grep -nE 'ssh (-n )?\$SSH_OPTS' scripts/quick-health-check.sh | /usr/bin/grep -F 'bounded_ssh'

    1106:if ! bounded_ssh "$PROBE_TIMEOUT" ssh $SSH_OPTS root@172.16.1.159 'command -v timeout >/dev/null 2>&1' 2>/dev/null; then

THE BOUND, from the review and stated in band as well: NEITHER OF THOSE TWO SITES INTERPOLATES A
KNOB TODAY. Both pass a literal host and a literal remote command. So nothing in the file was
wrong. The RECIPE was wrong — it was offered as the durable replacement for a wrong number while
under-counting its own haystack by two.

--------------------------------------------------------------------------------
3b. THE RECIPE IS STILL NOT AN OCCURRENCE OF WHAT IT MEASURES — CHECKED, NOT ASSUMED

The recipe is a comment inside the file it greps, so it must not match itself. This was verified by
RUNNING the widened pattern, because it carries more literal text than the one it replaced:

    $ /usr/bin/grep -nE 'ssh (-n )?\$SSH_OPTS' scripts/quick-health-check.sh | /usr/bin/grep '^[0-9]*:[[:space:]]*#'
    (no output)  exit 1

Zero comment lines among the hits. All 20 are code. The recipe line itself does not match because
the ERE requires `ssh ` followed by an optional literal `-n ` and then `$SSH_OPTS`, while the
recipe line has `(` and a backslash in those positions.

THIS CHECK CAUGHT A REAL SELF-MATCH DURING EXECUTION, recorded because the near-miss is the point.
The first draft of the in-band explanatory paragraph QUOTED the two newly-covered call sites
verbatim in order to describe them. That paragraph then matched the widened pattern, and the run
above returned it as a comment-line hit — the recipe counting its own documentation, which is the
CR-01 / GC-03 shape this phase has already shipped twice. The paragraph was rewritten to describe
those two sites in PROSE instead, and the check was re-run clean. The prose now says so in band, so
the next person to document a pattern inside the file it matches meets the warning.

    VACUITY GUARD, run first and not optional: the hit set is 20, not empty. An empty hit set would
    have satisfied the "zero comment lines" test trivially.
