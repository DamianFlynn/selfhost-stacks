READING OF SECTION 2, stated so the capture is not over- or under-claimed.

1. THE DEFAULT CASE IS BYTE-IDENTICAL BEFORE AND AFTER for DASH_RESOLVE_IP, and differs for the
   drift pairs only by the now-unnecessary quote characters. `printf '%q'` leaves a word with no
   metacharacters untouched. So this change is a no-op on every real run, which is exactly what a
   correctness fix to an override path should be.

2. THE SPACE CASE SURVIVES BOTH WAYS FOR THE DRIFT PAIRS — argc=4 before and after, same $3. That
   is not a contradiction of R4-01: the ⛔ paragraph says in terms that a hand-escaped wrapper
   "survives a space but not a quote and not a $". The space case is precisely the case the old
   shape handles. It is captured anyway as the control that proves the harness is faithful.
   For DASH_RESOLVE_IP the space case DOES split before the fix, adding a stray `evil.example`
   argument to curl — which is why curl fails loudly there rather than quietly.

3. THE QUOTE CASE IS THE ONE THAT MATTERS, and it is decisive:
       BEFORE: argc=2, and the path argument is EMPTY.
   The embedded `"` terminates the wrapper early, the remote shell re-parses the remainder as
   command text, and `_drift_pair` is called with two arguments instead of four — so `$3` is unset
   and the `sha256sum "$3"` inside the function body hashes nothing. AFTER: argc=4 and the full
   path arrives intact, quote and all.

4. THE BOUND, UNCHANGED AND NOT INFLATED. None of this can produce a green tick. Any non-default
   DRIFT_APPDATA_ROOT already forces EXIT_CODE=1 at the override guard, and a broken remote command
   lands in the could-not-look arm. There is no privilege crossing: the operator who can set the
   knob already has root on LXC 100. THE DEFECT R4-01 REPORTS IS THE CLAIM — round 3's sentence
   saying the forbidden-shape class was closed — NOT AN EXPLOIT.
