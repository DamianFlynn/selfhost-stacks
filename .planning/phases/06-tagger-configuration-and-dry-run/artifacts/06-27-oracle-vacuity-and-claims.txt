THE FIRST HARNESS WAS WRONG AND IS RECORDED RATHER THAN QUIETLY FIXED. It called

incremented in a child and discarded: the first run reported `REDS=0 UNKNOWNS=0`
for EVERY case, including the ones that had just printed a red tick. The counter
is the half GC-05 is about, so that harness measured nothing. Corrected by
sending run_assert's output to a FILE and reading it back, leaving the counters
to move in the harness's own shell. Same defect class as the `OUT=$(eval …)` trap
this round recorded twice already.
