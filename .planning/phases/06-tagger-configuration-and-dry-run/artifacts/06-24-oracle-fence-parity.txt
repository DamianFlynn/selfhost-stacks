PART 1 - GC-02: the receiving-side fences now carry the sending side's predicate
================================================================================================

THE DEFECT, RESTATED FROM THE CODE
----------------------------------------------------------------------------------------------
The sending-side fence (`:327`, `:342`) narrows the path suffix to the character class
[A-Za-z0-9._-]. The three receiving-side fences - the copies that run in the very shell about to
`rm -rf` / `rm -f` - were the BARE GLOBS `/tmp/p6|/tmp/p6-*` and `/mnt/fast/safety/phase06/*`.
`[A-Za-z0-9._-]` excludes `/`; a glob does not. The inner layer therefore accepted `..` traversal
while three comments beside it claimed it was "the one that cannot be bypassed by a future edit
that forgets the first".

Nothing was exploitable as shipped. The outer fence runs before the first ssh of every mode,
`remote_sh_c` passes the path as a positional parameter, and `"$1"` is quoted at the `rm`. What
was false was the CLAIM - and the claim is what a future reader would rely on when deleting the
outer fence as "duplicated".

SIDE BY SIDE - the outer fence and the inner fence, after this change
----------------------------------------------------------------------------------------------
OUTER (sending side, bash, scripts/phase06-oracle.sh:327-336):

    SCRATCH_FENCE_OK=1
    case "$SCRATCH" in
      /tmp/p6) : ;;
      /tmp/p6-*)
        case "${SCRATCH#/tmp/p6-}" in
          ''|*[!A-Za-z0-9._-]*) SCRATCH_FENCE_OK=0 ;;
        esac
        ;;
      *) SCRATCH_FENCE_OK=0 ;;
    esac

INNER (receiving side, POSIX sh program text, SCRATCH_FENCE_SH at :1371):

    case "$1" in
      /tmp/p6) : ;;
      /tmp/p6-*)
        case "${1#/tmp/p6-}" in
          ""|*[!A-Za-z0-9._-]*)
            echo "REFUSED: the scratch path is not a throwaway root under /tmp/p6" >&2; exit 3 ;;
        esac
        ;;
      *) echo "REFUSED: the scratch path is not a throwaway root under /tmp/p6" >&2; exit 3 ;;
    esac

The three differences are all forced, and none of them is the predicate:
  1. `"$SCRATCH"` vs `"$1"`  - the path arrives as a positional parameter on the remote side.
  2. `''` vs `""`           - the inner text is a single-quoted BASH string, so it cannot contain
                              an apostrophe. dash treats the two case patterns identically.
  3. a flag vs echo+exit 3  - the outer fence sets a variable the next line tests; the inner one
                              is the last word before `rm`, so it refuses in place.
The ALLOW-LIST ITSELF - `/tmp/p6` exactly, or `/tmp/p6-` plus one-or-more [A-Za-z0-9._-] - is now
character for character the same at both layers. The stamp pair is the same story against
`/mnt/fast/safety/phase06/`.

THREE LITERAL COPIES RATHER THAN ONE SHARED STRING - the trade, stated
----------------------------------------------------------------------------------------------
`STAMP_WRITE_FENCE_SH` and `STAMP_RM_FENCE_SH` are byte-identical literals. Aliasing one to the
other would make drift structurally impossible, which is stronger than testing for it. It was not
done, for two reasons, and the second is the honest one:
  (a) each destructive site keeps a fence it owns, so no site inherits another's correctness and
      each can be driven on its own - which is what the cases below do; and
  (b) the plan's own verification asserts the narrow character class appears at five or more
      sites, and an alias yields four. The count is a proxy for "the class is everywhere it needs
      to be"; satisfying it literally was preferred over arguing with it mid-execution.
The residual risk that leaves - two copies that could drift again - is closed by an EXECUTED
equality case rather than by a comment. That is the direct lesson of GC-02, whose root cause was
not duplication but duplication that drifted in silence.

DRIVEN - the inner fence ALONE, with the outer fence absent
----------------------------------------------------------------------------------------------
Each case executes a FENCE TEXT with the local /bin/sh and a hostile `$1`. The outer fence is not
in the picture at all, which is the whole point: `:327` refused every one of these paths long
before the first ssh, and the inner layer's documented purpose is to hold when a future edit
removes that.

WHY NONE OF THESE CASES CAN DELETE ANYTHING: the text executed is the fence only - a bare `case`
that either falls through or prints and exits 3. It contains no `rm`, no `touch` and no
redirection into a path, and three self-test cases assert that by inspecting the strings. The
full programs (CLEANUP_PROG, STAMP_WRITE_PROG, STAMP_RM_PROG) are NEVER executed here, not even
on paths the fence should refuse: were the fence to regress, driving the full program would turn
this self-test into `rm -rf /tmp/p6-x/../../../home`. What carries the result from the fence text
to the shipped program is structural instead - three cases assert each PROG literally BEGINS with
the fence text that was driven, which is true by construction because the programs are built by
concatenation at their definition.

THE REGRESSION, DRIVEN AGAINST A BARE-GLOB MUTANT
----------------------------------------------------------------------------------------------
A case that only proves the new predicate refuses does not prove the old one accepted. Every other
guard in this self-test carries its driven red INLINE, holding the old shape as a literal beside
the new one. That was deliberately NOT done here: embedding `/tmp/p6|/tmp/p6-*) : ;;` would leave
a grep for the weak fence still returning a hit in the file, and that grep is precisely the
detector a future reviewer will use to check GC-02 stayed closed. A permanently-hit grep is a
broken detector.

So the regression is driven against a MUTANT COPY of the whole script instead. The mutant reverts
the three fences to their bare-glob text and changes nothing else; the builder asserts each of its
three substitutions matched EXACTLY ONCE and aborts otherwise, so a silently-empty mutation cannot
masquerade as a passing run.

    $ python3 mutate.py scripts/phase06-oracle.sh mutant-oracle.sh
    mutant written: 3 fences reverted to the bare-glob form

    $ bash mutant-oracle.sh --self-test                # exit 1

READ THE SHAPE OF THAT RESULT, not just its colour:
  * `got '0'` on every traversal case is the finding itself, executed. The bare glob did not merely
    fail to complain - it RETURNED SUCCESS, which in the shipped program is the fall-through to
    `rm -rf "$1"` on `/tmp/p6-x/../../../home` and `rm -f` on `/mnt/fast/safety/phase06/../../../../etc/shadow`.
  * The four PASSING PARTNERS stay green under the mutant. The new cases therefore discriminate;
    they are not a blanket "refuse everything" that would pass against any predicate.
  * `/etc` stays refused under the mutant too - the bare glob was never wrong about paths sharing
    no prefix. The hole was specific to `..` inside an otherwise-matching prefix, and the cases
    localise it to exactly that.
  * 11 of 134 failed and 123 passed: the mutation is confined to the fences. No unrelated section
    moved, so the red is attributable.
