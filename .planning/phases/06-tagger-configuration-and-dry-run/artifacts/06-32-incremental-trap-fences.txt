1. R3-09 — THE TWO TRAP LINES, BEFORE AND AFTER
--------------------------------------------------------------------------------
Anchors, not line numbers: grep `mktemp -d /tmp/p6-mf` and `mktemp /tmp/p6-taghist`
and read down to the trap under each.

  write_prog_manifest()   — BEFORE (as 06-25/GC-08 shipped it)
    trap 'case "${MANDIR:-}" in /tmp/p6-mf.*) rm -rf "$MANDIR" ;; esac' EXIT

  write_prog_manifest()   — AFTER TASK 1 (signal list widened; the fence itself
                            is still the prefix-only one, and task 2 replaces it)
    trap 'case "${MANDIR:-}" in /tmp/p6-mf.*) rm -rf "$MANDIR" ;; esac' EXIT INT TERM HUP

  write_prog_manifest()   — AFTER TASK 2 (final; § 2 covers the fence change)
    trap 'case "${MANDIR:-}" in
            /tmp/p6-mf.*) case "${MANDIR#/tmp/p6-mf.}" in ""|*[!A-Za-z0-9._-]*) : ;; *) rm -rf "$MANDIR" ;; esac ;;
          esac' EXIT INT TERM HUP

  write_prog_taghistory() — BEFORE
    trap 'case "${THPROG:-}" in /tmp/p6-taghist.*) rm -f "$THPROG" ;; esac' EXIT

  write_prog_taghistory() — AFTER TASK 1
    trap 'case "${THPROG:-}" in /tmp/p6-taghist.*) rm -f "$THPROG" ;; esac' EXIT INT TERM HUP

  write_prog_taghistory() — AFTER TASK 2 (final)
    trap 'case "${THPROG:-}" in
            /tmp/p6-taghist.*) case "${THPROG#/tmp/p6-taghist.}" in ""|*[!A-Za-z0-9._-]*) : ;; *) rm -f "$THPROG" ;; esac ;;
          esac' EXIT INT TERM HUP

THE SIGNAL BEHAVIOUR IS STATIC REASONING ABOUT POSIX sh, NOT EXECUTED AGAINST
THE CONTAINER. The review says the same of its own finding, and this phase does
not contact the estate, so nothing here proves that a `timeout` expiry inside
beets-flask now runs the trap. What IS established locally:

  * both programs are delivered through the `timeout`-wrapped transport —
    grep `docker exec -i -u beetle` returns the remote_exec line
    `timeout $REMOTE_TIMEOUT docker exec -i -u beetle $CONTAINER sh -s$qargs`,
    with the bound defaulting to 120 at `REMOTE_TIMEOUT="${REMOTE_TIMEOUT:-120}"`;
  * `timeout` sends SIGTERM at expiry, which an exit-only trap does not catch;
  * SIGKILL cannot be trapped at all, so the widening shrinks the window rather
    than closing it. That limit is stated in band beside the manifest trap, not
    only here.

2. R3-10 — THE PREDICATE, DRIVEN OFFLINE, IN BOTH DIRECTIONS
--------------------------------------------------------------------------------
Driven as a standalone `sh` snippet, NOT as a trap, with NO rm, rmdir or unlink
of any kind in the drive file: each case prints WOULD-REMOVE or REFUSED instead
of removing anything. Interpreter /bin/sh on Darwin 27.0.0 (the workstation),
from the scratch directory /tmp/p6-32-drive.T18Pzmx9 minted with `mktemp -d`.
Nothing was written into the repo working tree.

The OLD predicate driven is the prefix-only shape 06-25 shipped. The NEW
predicate is the two-stage one: prefix match, then a remainder that must be
non-empty and free of any byte outside the class [A-Za-z0-9._-] — a class that,
unlike a glob, does not match `/`. Verbatim output:

  == MANIFEST FENCE  prefix=/tmp/p6-mf. ==
  old=WOULD-REMOVE  new=REFUSED       input=[/tmp/p6-mf.a/../../../home]
  old=WOULD-REMOVE  new=WOULD-REMOVE  input=[/tmp/p6-mf.660lOc4t]
  old=REFUSED       new=REFUSED       input=[]
  old=WOULD-REMOVE  new=REFUSED       input=[/tmp/p6-mf.]

  == TAGHISTORY FENCE  prefix=/tmp/p6-taghist. ==
  old=WOULD-REMOVE  new=REFUSED       input=[/tmp/p6-taghist.a/../../../home]
  old=WOULD-REMOVE  new=WOULD-REMOVE  input=[/tmp/p6-taghist.le9WmqTd]
  old=REFUSED       new=REFUSED       input=[]
  old=WOULD-REMOVE  new=REFUSED       input=[/tmp/p6-taghist.]

Read row 1 and row 2 together, on both fences. Row 1 is the input the fence
exists to refuse, and the OLD fence accepted it — a fence that was never driven
against the input it exists to refuse is a fence nobody has tested. Row 2 is the
positive control: a REAL name, minted here by `mktemp -d /tmp/p6-mf.XXXXXXXX`
and `mktemp /tmp/p6-taghist.XXXXXXXX`, still removable — which is the failure
mode a fence tightened without a positive control usually ships. Row 4 is the
quieter one: the bare prefix with nothing after it was accepted by the old shape
and is refused now, because the remainder is empty.

Both minted names were removed after the drive, OUTSIDE it, with a plain
`rmdir` and a plain `rm -f`, so the drive file itself stayed non-destructive.

THE DEFECT WAS LATENT, NOT REACHABLE, and the record says so rather than
dramatising it: MANDIR and THPROG are only ever `mktemp` output, and `mktemp`
will not emit a traversal. What this closes is the INCONSISTENCY — two sibling
files stating two different rules for the same job — and the OVERSTATED CLAIM
beside the manifest trap, which read "so it can never remove anything else".
That absolute is gone; the comment now states what the predicate actually gives
and cites scripts/phase06-oracle.sh as the sibling carrying the same rule.

`""` and not `''` for the empty pattern, for the reason GC-02's comment records
in the sibling file: the trap body is a single-quoted string, and an inner
single quote would terminate it. dash treats the two patterns identically.

3. THE GATE `bash -n` CANNOT GIVE — sh -n OVER BOTH EXTRACTED HEREDOC BODIES
--------------------------------------------------------------------------------
Both traps live inside `<<'REOF'` heredocs that are written to a file and piped
into a container shell. `bash -n` on the outer script parses the heredoc as
DATA, so a malformed multi-line trap would pass `bash -n`, pass `--self-test`
(which drives neither program), and fail only on the estate — the one place this
phase is not allowed to go. Both bodies were therefore extracted with awk and
parsed as POSIX sh:

  awk '/^write_prog_manifest\(\)/{f=1;next}   f&&/^REOF$/{exit} f'  -> manifest.sh
  awk '/^write_prog_taghistory\(\)/{f=1;next} f&&/^REOF$/{exit} f'  -> taghist.sh

  file          lines   predicate occurrences   sh -n
  ------------  ------  ----------------------  -----------
  manifest.sh      65            1              PASS (rc 0)
  taghist.sh       31            1              PASS (rc 0)

The occurrence count matters as much as the parse: it asserts the predicate is
in the IN-CONTAINER program text, not merely somewhere in the outer file. Both
extractions are non-empty, which is itself an assertion — a silently empty
extraction would make `sh -n` pass vacuously.

Outer-file gates, for completeness: `bash -n` clean and `--self-test` exit 0
after BOTH tasks, seven announced sections and no eighth.
