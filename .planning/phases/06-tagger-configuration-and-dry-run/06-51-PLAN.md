<objective>
Bring the deployed instruments on LXC 100 into step with the repository, under a real pre-flight,
with `--ff-only`, and **without redeploying anything**.

Purpose: `DEF-06-45-05` item 2 records that `/mnt/fast/stacks` on LXC 100 carries **pre-06-44
prose**, so any live `quick-health-check.sh` run today measures the wrong file. `06-VERIFICATION.md`

`quick-health-check.sh` row reads "COULD NOT LOOK (execution)". This plan closes it.

Output: one captured transcript and one `DEF-` entry.

**Why this is `autonomous: false` and why the care is proportionate.** LXC 100 (`172.16.1.159`) is
the Docker host for ~103 containers. A `git pull` of shell scripts is a small act with a large
blast radius if it becomes anything else. Two specific hazards bind this plan:

  1. **The host tree may not be what anyone assumes.** This estate has a recorded Renovate
     deploy-drift problem — merged PRs never touch the host — and round 5 already found one
     claim about the host's checkout state (that it was pre-Phase-6 with no `ARTIST_PROOF_ROWS`)
     **measured FALSE**. The pre-flight measures; it does not assume.
  2. **A pull of scripts must not become a redeploy of 90+ services.** No compose verb is issued by
     any task in this plan, and the running container set is fingerprinted before and after — on
     **name, image AND status** — to prove it.

**D-R6-H3 — the operator's decision on the pre-flight cleanliness gate. Locked; implement both
halves.** The host's working tree was measured on `172.16.1.159` at plan time and is **not empty**:

```
?? stacks/selfhosted/monitoring/prometheus.yaml.bak
?? stacks/selfhosted/wrappers/monitoring.app.yaml.disabled
```

Two **untracked** files — `.bak`/`.disabled` debris. Neither can block a fast-forward, neither
appears in the incoming diff, and host HEAD `ee82fb2` **is** an ancestor of local HEAD (20 commits
behind). As previously written, this plan's STOP condition made "a `git status --porcelain` with any
output" a halt, so the round's one live-estate plan would have halted at its first gate for a reason
unrelated to its purpose. The decision is:

  **(a) The cleanliness test becomes `git status --porcelain --untracked-files=no`.** A
  **tracked-modified** file remains a hard STOP — that is the state a pull could silently overwrite,
  and the gate stays fail-closed on exactly that. An **untracked** file (`??`) is a **recorded,
  reportable NON-blocker**: it is captured, shown to the operator, and does not halt the plan.

  **(b) The two files above are REMOVED from the host working tree before the fast-forward.** This
  is a host write, so it is fenced like every other host write in this round: both paths named in
  full, both asserted untracked immediately before removal, exactly those two paths removed with no
  glob and no `-r`, and a before/after `git status --porcelain` captured into the dated artifact.
  **It must not be a `git clean` invocation of any form** — `git clean -fd` takes whatever else is
  untracked at that moment, which is precisely the unbounded blast radius this plan exists to avoid.

**Scope fence.** No compose verb. No service restart. No `beet` invocation. No Jellyfin or
Music Assistant API call. No CONF-04 work. No `zfs` write of any kind — the snapshot decision is
plan 06-52's and is deliberately not bundled here. The **only** host-side file removals permitted
are the two named paths above; the only `docker` verb permitted is `ps`.

**The `HEAD --` rule, stated once and binding on every byte-identity criterion in this plan.** A
bare `git diff --exit-code <path>` compares the working tree against the **index**, not a commit.
With an edit *staged* it exits **0** — driven: `git diff --exit-code protected.txt` exits 0 while
`git diff --exit-code HEAD -- protected.txt` exits 1. This plan stages and commits while it runs.
**Every byte-identity guarantee here is written `git diff --exit-code HEAD -- <path>`.**
