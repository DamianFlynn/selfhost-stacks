<objective>
Bring the deployed instruments on LXC 100 into step with the repository, under a real pre-flight,
with `--ff-only`, and **without redeploying anything**.

Purpose: `DEF-06-45-05` item 2 records that `/mnt/fast/stacks` on LXC 100 carries **pre-06-44
prose**, so any live `quick-health-check.sh` run today measures the wrong file. `06-VERIFICATION.md`
names this as an outstanding operator action rather than a phase gap, and it is the reason its
`quick-health-check.sh` row reads "COULD NOT LOOK (execution)". This plan closes it.

Output: one captured transcript and one `DEF-` entry.

**Why this is `autonomous: false` and why the care is proportionate.** LXC 100 (`172.16.1.159`) is
the Docker host for ~103 containers. A `git pull` of shell scripts is a small act with a large
blast radius if it becomes anything else. Two specific hazards bind this plan:

  1. **The host tree may not be what anyone assumes.** This estate has a recorded Renovate
     deploy-drift problem — merged PRs never touch the host — and round 5 already found one
     claim about the host's checkout state (that it was pre-Phase-6 with no `ARTIST_PROOF_ROWS`)
     **measured FALSE**. The pre-flight measures; it does not assume.
  2. **A pull of scripts must not become a redeploy of 90+ services.** No `docker compose up`,
     `restart`, `down`, `pull` or `recreate` is issued by any task in this plan, and the running
     container set is fingerprinted before and after to prove it.

**Scope fence.** No `docker compose` verb. No service restart. No `beet` invocation. No Jellyfin or
Music Assistant API call. No CONF-04 work. No `zfs` write of any kind — the snapshot decision is
plan 06-52's and is deliberately not bundled here.
</objective>
