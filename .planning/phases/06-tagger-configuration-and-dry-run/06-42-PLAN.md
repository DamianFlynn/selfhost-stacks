<objective>
Measure what the re-probe did, and prove it did nothing else.

Two questions, answered separately and never merged: (1) did the three pinned tracks move from
their 2026-09-20 Jellyfin baselines (0/4, 1/2, 1/2) to their targets (4/2/2), as N distinct
browseable `ArtistItems` entities with distinct Ids and no `;` in any entity Name? and (2) did the
refresh write anything into the library, move any row nobody touched, or disturb any option?

This plan takes the measurement. It does not decide what the measurement means for CONF-04 — that
is 06-43's job, behind an operator gate — and it does not edit a single document.

Purpose: turn the drive into evidence.
Output: one committed artifact, `06-42-conf04-reprobe-after.txt`.

⛔ THE HARD FENCE still binds: the aggressive per-item "replace all metadata" refresh mode is
FORBIDDEN. If the rows have not moved, this plan records that they have not moved. It does not
re-refresh, it does not widen the mode, and it does not touch any further file.

⚠ FAIL-CLOSED AND HALT. If any safety assertion in task 2 fails — a `.nfo` hash that moved, a
`zfs diff` entry that is not one of the three touched files, a changed D-34 option, a changed
freeze field — this plan STOPS and hands back with the rollback command recorded. It does NOT roll
back on its own: a `zfs rollback` of a live shared dataset is an operator decision, not an
executor's, and the snapshot is the whole reason there is time to ask.
</objective>
