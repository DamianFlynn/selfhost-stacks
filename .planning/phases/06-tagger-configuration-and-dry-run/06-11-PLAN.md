**The sequence is fixed by the script and must not be short-circuited:** copy the real `library.db` to the throwaway path inside the container; take the BEFORE manifests over every sampled source folder plus the real `library.db` and `state.pickle`; take the stamp outside the mounts; import the sample as-is into the throwaway with `--set albumtype=dj` on the DJ rows; run `beet -c <overlay> move -p`; take the AFTER manifests; then evaluate.

**Evaluate the positive control BEFORE the diff.** If any of these fails, the verdict is `UNKNOWN, not green` and the diff must NOT be reported as a pass:
- every oracle line contains ` -> ` (or the two-line narrow-terminal form);
- the destination-line count **equals** the sampled audio-file count from `06-SAMPLE.md`;
- the `(N already in place)` line reads 0 on an in-place import — record N explicitly;
- the output contains `/media/Music/`.
A `--pretend` transcript fails the first of these trivially. That is the discriminator, and it must be shown to have been applied rather than assumed.

**Then the diff.** `diff` the normalised, `LC_ALL=C`-sorted destination list against `06-EXPECTED-TREE.txt`. **Zero lines of difference is the pass.** On any difference, print the diff in full and in both directions so a missing line and an extra line are distinguishable, and do not adjust `06-EXPECTED-TREE.txt` to make it pass. If the tree was wrong, that is a finding about the **config**, fixed in a commit against plan 06-01's file with the reason recorded, after which both the expected tree and the run are regenerated — and the artifact records that the first run failed and why. A tree edited to match its own output is not an oracle.

**Then the three-layer wrote-nothing proof, into its own artifact.**
- Layer 1: `docker inspect beets-flask` shows `/mnt/tank/media` `RW=false`. From the runtime, not the compose file.

Record which library the oracle ran against, by name and sha256, and assert it matches the one `06-EXPECTED-TREE.txt`'s header names. The `%aunique{}` count is only meaningful with that label attached.

**Clean up** `/tmp/p6` inside the container and assert it is gone; `/tmp` is tmpfs on LXC 100.

**D-18 — the protected-field ledger**, written to `artifacts/06-11-dj-fields.ndjson`, one record per (file, field), in the `normalise-dj-tags.py` shape: `path`, `field`, `rule`, `old`, `new`, plus `noop: true` when `old == new`, plus `failed` records carrying the exception for anything that could not be read. A refusal is a record, never a skip and never an "unchanged" — a preview that silently omits a file the run would refuse is not a preview.

Cover all five fields with the right instrument for each:
- `bpm` (ID3 `TBPM` / Vorbis `BPM`), `initial_key` (`TKEY` / `INITIALKEY`), `genres` (`TCON` / `GENRE`) and `comments` (`COMM` / `DESCRIPTION` before `COMMENT`) are real beets fields — compare the throwaway library's item values against the source file's tags.
- **`EnergyLevel` is neither a beets field nor a mediafile field.** beets never reads it, never writes it, and mutagen preserves frames it did not touch — so `TXXX:EnergyLevel` survives any beets import unless `scrub` runs. The correct instrument is a **raw ID3 frame-set comparison**, with the offset set to 0 for MP3 and to the `id3 ` chunk data offset for a WAV. Without the offset the check reads `RIFF` at offset 0 for every WAV and returns silently — a vacuous pass. A beets query for `EnergyLevel` returns nothing and reads as clean; the ledger must not use one.
- Fold case for Vorbis keys. FLAC casing is inconsistent in this corpus (`GENRE`/`Genre`/`genre`, `COMMENT`/`comment`) and a naive key comparison shows spurious differences.
- Note in the artifact that no WAV in this estate carries BPM, key or energy, so the WAV branch has nothing to report on those three — and that **having nothing to report is different from not having looked**, which is why the branch runs and records a zero rather than being skipped.
- Note the second disagreement class for WAV that beets cannot fix: `mediafile` writes only the ID3 chunk, so a pre-existing `LIST/INFO` `IGNR`/`ICMT` remains and will silently disagree. The normaliser already reports this class as `info_iprd` for album; the same class exists for genre and comment.

**CONF-04's write side, shown in the dry run.** For the S6 multi-artist row, record what the import would write: the `artist` value (MusicBrainz join phrases concatenated verbatim) and the `artists` list. This is D-23's "shown in the dry run", as amended by D-34.

**Register the OQ-2 gap explicitly, in the artifact, so it is not left unowned.** `--set albumtype=dj` is a `beet import` CLI flag backed by `import.set_fields`, and rc6's `InboxFolderSchema` carries only `path`, `name`, `auto_threshold` and `autotag` — there is **no per-inbox field-setting mechanism**.
