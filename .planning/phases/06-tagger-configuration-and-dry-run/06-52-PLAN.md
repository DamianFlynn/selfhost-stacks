<objective>
Settle `DEF-06-45-01`: whether `tank/media/Music@pre-06-41-conf04-reprobe` is released or kept.

Purpose: that snapshot is round 5's **only undo** for its three writes. `DEF-06-45-01` deliberately
did not bundle its release into the round's closure, "so that a later tidy-up does not read 'the
round is over' as 'the fence can go'." Its stated release condition has two clauses — the round's
outcome accepted (it now is: `negative-carry-e6`, 2026-09-24T14:30:37Z) **and** Phase 7's pilot
fence planned, so the estate is never without an undo across the boundary. The second clause is
the one this plan must actually evaluate rather than assume.

Output: one captured decision record and one `DEF-` entry.

**Why this is its own plan and its own gate.** Destroying a snapshot is irreversible and
instantaneous. It is bundled with nothing — not with the git sync (plan 06-51), not with the round
record. `hold` is an outcome this plan can reach **without failing**: if the reasoning lands on
"recommend holding", the plan succeeds by recording that, and `DEF-06-45-01` stays open with a
sharper revisit condition than it had.

**Scope fence.** The only `zfs` verb this plan may issue on any branch is **`zfs list`**, a read —
unless the operator explicitly answers `release`, in which case exactly one `zfs destroy` of exactly
one named snapshot is permitted. **`zfs rollback` is forbidden on every branch** and is not offered
as an option: rolling back a live shared dataset discards whatever Jellyfin, Music Assistant or the
operator has written since, and it is not an executor's command to run. `tank/downloads@pre-phase5`
is **not touched** on any branch — different fence, different owner (D-32, Phase 7 entry criterion
E4). No CONF-04 work of any kind: no re-probe, no mtime touch, no refresh, no checkbox move.
