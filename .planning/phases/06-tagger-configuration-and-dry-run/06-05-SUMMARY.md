## Decisions Made

1. **The Phase 1 snapshot is a counting instrument only.** Measured: 4,746 of its `unsorted` paths and 44 of its `music` paths no longer resolve — Phase 5's `Vol NNN` split and its `_FAILED_` renames. Drawing eligibility from it would have sampled folders that no longer exist at the paths recorded. It still reproduces `unsorted` 7,451, `dj-mixes` 764 and `media/Music` 1,244 exactly against a live pass, so it is kept as the cross-check.
2. **Predicates are evaluated on beets' own fields, read by `mediafile` inside `beets-flask` (2.12.0).** An ffprobe tag key is a *different quantity* from the field a `paths:` query tests. See Issues below — this was not a theoretical concern.
3. **Stratum precedence mirrors the config's rule precedence** (`S4 → S5 → S6 → S7 → S2 → S3 → S1`), so no folder is assigned to a stratum whose path rule it never reaches.
4. **The drawn `%aunique{}` collision is kept, not substituted.** The plan's substitution rule is scoped to the numeric-id case, and this one is separated by `label`. Substituting it out would have left D-16's "every folder where it fires is reported" list empty, which is a weaker artefact than a real, predicted, asymmetric firing.
5. **`06-EXPECTED-TREE.txt` sits at the phase root**, with the reason in the file: everything under `.planning/**/artifacts/` is an output recorded afterwards; this is an input to the run it judges. The `^#` strip contract is written into the file so plan 06-08's `phase06-oracle.sh` has an unambiguous format.
6. **Rule 2 (`albumtype:=dj disctotal:2..`) is left unexercised rather than hand-picked into the sample.** Both drawn DJ folders carry no `disctotal`. Seven `dj-mixes` folders in the population do carry `disctotal = 2` and are named in 06-SAMPLE.md; plan 06-11 should assert rule 2 over one of them as a class assertion.

## Issues Encountered

- **`max_filename_length: 0` does not mean "no truncation".** `config.yaml`'s comment on that key says it does. Measured against beets 2.12.0: `util.get_max_filename_length()` returns `min(statvfs NAME_MAX, MAX_FILENAME_LENGTH = 200)` when the key is `0`, so the effective limit is **200 characters per path component**. Nothing in the sample is near it (longest component 65 chars), so the oracle is unaffected — but a later plan reading that comment as "unlimited" would mis-diagnose a truncated path as a template defect. Recorded in `06-EXPECTED-TREE.txt`'s header. **`config.yaml` was not edited** — it is plan 06-01's file and is not in this plan's `files_modified`; the correction is flagged for 06-13.
- **`_tmpl_unique`'s empty-library branch is a trap worth knowing about.** If the ambiguous set has size **0** (the item's album is not in the library at all), the disambiguator loop's `len(disam_values) == len(ambiguous_items)` test is `0 == 0` and it breaks on the **first** disambiguator, `albumtype` — so it can append ` [album]` or ` [dj]` instead of nothing. It does not fire for `beet move -p`, because a `move` operates on items that are already in the library and the set is therefore at least 1. Named here because a future plan that evaluates the template against an unimported item will hit it.
- **`beets` is not importable as `python3 -c "import beets"` in the container** — it lives in `/venv`, so every read of the running code went through `/venv/bin/python`. Recorded because 06-PATTERNS.md notes no script in this repo runs `docker exec` and this is the first shape.
- **Two helper files had to cross the container boundary through the appdata config bind mount** (`/mnt/fast/appdata/arrs/beets/config/`). They were moved to the fence immediately afterwards and the directory re-listed to confirm it is back to its 10 entries, so the vendored-file drift check that plans 04-10/04-11 build has nothing new to see.
