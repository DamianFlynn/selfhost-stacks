<objective>
Close the two round-3 findings in `scripts/phase06-incremental-control.sh`: **R3-09** and **R3-10**.
Both are INFO, both are one-token fixes with a real consequence, and both are instances of the
pattern this round exists to stop — a fence whose comment is stronger than its code.

**R3-09.** GC-08's argument for moving cleanup onto a trap is correct: every BLIND arm exits early
and the old trailing `rm -f` sat after the last one, so a could-not-look left all three files
behind. But both traps are registered on `EXIT` only, and a POSIX shell runs an `EXIT` trap on
normal termination and on `exit` — **not** on an uncaught `SIGTERM`. These programs are `sh -s`
delivered through `timeout $REMOTE_TIMEOUT docker exec`, and a bound expiry is a routine, expected
outcome for a manifest over a large tree. The residue is then exactly what GC-08's own comment names
as the worse case: *"a MINTED leftover is worse litter than a fixed one, because nobody knows its
name."* The fixed names at least self-limited to three; minted ones accumulate one per timed-out
run, in a `/tmp` the same header describes as mode 1777.

**R3-10.** GC-02's entire content, in the sibling `phase06-oracle.sh`, is that a shell glob `*`
matches `/` while the character class `[A-Za-z0-9._-]` does not — so `/tmp/p6-x/../../../home`
passed a bare-glob fence and would have reached `rm -rf`. In the **same round**, this file
introduced two fresh fences of exactly the bare-glob shape, both adjacent to `rm -rf` / `rm -f`, and
the comment beside one claims it *"can never remove anything else"*. `/tmp/p6-mf.a/../../../home`
matches `/tmp/p6-mf.*`.

**This is latent, not reachable**, and the plan must say so rather than dramatise it: `MANDIR` and
`THPROG` are only ever `mktemp` output and `mktemp` will not emit a traversal. The finding is the
**inconsistency plus the overstated claim** — two sibling files stating two different rules for the
same job, one of them in a commit whose stated lesson was that a fence with a stronger comment than
code is how the real fence eventually gets deleted as duplicated.

**Disposition, per finding: both are CODE CHANGES, and R3-10 additionally corrects a claim.** Do not
widen either program's scope beyond the traps and the sentence beside them.

One structural note that shapes the verification. Both traps live inside `<<'REOF'` heredocs that
are written to a file and then piped into a container shell. **`bash -n` on the outer script does
not parse them.** A malformed multi-line trap would therefore pass `bash -n`, pass `--self-test`
(which drives neither program), and fail only on the live estate — which is the one place this phase
is not allowed to go. So the verification extracts both heredoc bodies and runs `sh -n` over them.
</objective>
