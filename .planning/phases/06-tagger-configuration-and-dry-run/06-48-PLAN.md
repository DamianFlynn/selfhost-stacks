<objective>
Correct `DEF-06-45-04`'s non-detecting recipe by **driving** the corrected form, and settle the
bracketing convention's scope question that `06-VERIFICATION.md` recorded as an Info observation
"for a future round". This is that round.

Purpose: `artifacts/06-43-conf04-verdict.txt` SECTION O publishes recipe `(O-a)` as
`/usr/bin/grep -cF "Full[R]efresh"`. `-F` makes the brackets literal, so the command searches for
the mitigation form and is structurally incapable of matching the real token. The `0` it published
is TRUE of the estate — re-measured with `-cE`, every round-5 artifact reads 0 — but it was **not
earned by the command printed beside it**. A true number from a vacuous instrument is the worst
shape there is, because it survives review. Separately, the forbidden mode's literal token now
appears **twice** in `ROADMAP.md` prose, up from once before round 5, and the convention's scope has
only ever been `artifacts/`. That is a decision waiting to be made, and an undecided convention
drifts in whichever direction the next writer happens to push it.

Output: one driven artifact and two `deferred-items.md` entries.

**Scope fence.** `artifacts/06-43-conf04-verdict.txt` is a **dated record and is deliberately left
unedited** — `DEF-06-45-04` says so explicitly, and editing a dated artifact to make a later reading
true is the retro-fitting this phase forbids. The correction lands as a new, driven artifact plus a
`DEF-` entry that supersedes and closes `DEF-06-45-04`. This plan does **not** touch `ROADMAP.md`
(`06-50` owns it), does **not** touch `REQUIREMENTS.md`, does **not** touch any script, and drives
**no** CONF-04 work of any kind.

**The `HEAD --` rule, and why the dated artifact needs MORE than `HEAD --`.** A bare
`git diff --exit-code <path>` compares the working tree against the **index**, not a commit. With an
edit *staged* it exits **0** — driven: `git diff --exit-code protected.txt` exits 0 while
`git diff --exit-code HEAD -- protected.txt` exits 1. This plan stages and commits while it runs, so
the blind state is the likely one. **Every byte-identity guarantee in this plan is written
`git diff --exit-code HEAD -- <path>`.** For `06-43-conf04-verdict.txt` that is still not enough on
its own: a modification *already committed during execution* moves `HEAD` too, and the guarantee
this plan actually owes is **immutability across the whole plan**, not cleanliness at the end of it.
So the dated artifact additionally carries a **base-commit anchored** comparison — capture the full
base commit hash at the start and compare `git show <base>:<path>` against the final file. That is
the one comparison neither staging nor an intermediate commit can satisfy falsely.
</objective>
