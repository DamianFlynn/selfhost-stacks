<objective>
Round 4's record. Plans 06-35 through 06-38 closed the ten findings in `06-REVIEW-GAP3.md`; this
plan supplies the part a fix commit cannot — a statement of what happened to **each** finding, wired
where the next reader will find it.

The discipline is round 3's, one level in, and the reason is written in `06-DISPOSITIONS.md`: *a
finding recorded where the next phase does not read is a finding nobody owns.* Round 2 existed
because round 1 was declared closed before anyone read its own diff. Round 3 existed because round 2
closed several classes partially while claiming completeness. **Round 4 exists because round 3 did
the same thing** — and found, in round 3's own diff, four more live instances of a shape the file's
own ⛔ paragraph forbids, eleven lines below that paragraph, under a sentence declaring the class
closed. **The recursion stops by recording honestly, not by recording nothing.**

**Five things this plan must get right, each because the alternative has already gone wrong here:**

1. **Do not use the SDK's state or roadmap verbs.** `gsd-sdk query state.*` and `roadmap.*`
   corrupted both files repeatedly in this project — truncating STATE.md sentences mid-line and
   blanking the ROADMAP Phase 6 Notes cell on all three invocations in one session. Edit both files
   **by hand** with Write, and `git diff` each before committing.
2. **This is a record, not a re-close.** No `/gsd-verify` is run and no verification result is
   claimed. No requirement checkbox moves. **CONF-04 is not closed** — its Jellyfin half is still
   OPEN and Phase 7 entry criterion **E6** still owns the discharge. The phase is **not** declared
   complete; that is the verifier's call.
3. **Carry the ID-alias mapping, prominently.** Round 4's report uses `WR-01 … WR-06` and
   `IN-01 … IN-04`, **the same namespace round 1 used**, and round 1's IDs are cited in band across
   all four scripts — seven `WR-01` in `quick-health-check.sh`, two `WR-02` and six `WR-06` in
   `phase06-oracle.sh`. The fix plans therefore wrote `R4-01 … R4-10` in band. **Without the mapping
   table, half of round 4's record becomes unresolvable**, and a future grep for `WR-02` returns
   round 1's finding in a file where round 4's also landed.
4. **Record the refusals as loudly as the fixes.** Round 4's plans refused at least two things a
   reader might expect: adding a cleanup `trap` to `phase06-oracle.sh` (it has none anywhere, by
   design, and one would run on the forensic `exit 3` arms too), and touching
   `ST_PLANNED_CASES=7` in `check-beets-config.sh` during the count audit. A refusal that is not
   written down reads as an oversight, and the next round re-opens it.
5. **Do not touch `06-VERIFICATION.md`.** It is **stale** — it records round 1's closure on
   2026-09-22 with `status: passed` and `gaps_remaining: []`, before rounds 2, 3 and 4 existed. It
   is not this round's gap source and it is not this round's to correct. Say so in the register, so
   the next reader who finds a passing verification over a phase with four gap-closure rounds knows
   which document is out of date.
