<objective>
Close the oracle's remote-command-construction findings: WR-07 (env-overridable paths interpolated unquoted into `rm -rf` / `rm -f` on the remote side), WR-08 (`printf '%q'`-quoted paths embedded inside single-quoted remote `sh -c` strings), IN-06 (predictable fixed temp paths) and IN-11 (no cleanup, and an unexplained refusal).

Purpose: the oracle's header states that *"every knob below is `${VAR:-default}` and every one of them can only make the verdict REDDER: a wrong host, a wrong container or a wrong output directory produces a refusal or an UNKNOWN, never a pass."* Two of the knobs are not knobs on the verdict at all — they are arguments to destructive commands built by string interpolation into a remote shell. `SCRATCH='/tmp/p6 /config'` word-splits inside the container into `rm -rf /tmp/p6 /config`, deleting the real `library.db`, `state.pickle` and the vendored config; the dirty-destination precheck does not stop it, because with two words the `[ ! -e … ]` test is an argument error rather than a refusal. This needs a deliberately hostile environment variable, so it is hardening rather than an exploitable path — but the header's claim is false as written, and the sibling script written in the same phase already shows the right shape: `phase06-incremental-control.sh` hard-fences its two roots with a literal `case` INSIDE the remote program and is not vulnerable.

WR-08 rides along because it is the same defect family — a path crossing a quoting boundary it was not quoted for — and because it silently narrows what the oracle can be pointed at: a folder named `Guns N' Roses - …`, an entirely ordinary shape for this corpus, produces a remote syntax error that looks like an infrastructure problem.

Output: one instrument, hardened, with the fence driven by a hostile value and the apostrophe case proven by a fixture.
</objective>
