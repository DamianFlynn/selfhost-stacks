GC-05 is the substantive one. The four vacuity guards this phase added or touched do not agree on
what a vacuous assertion *is*. `manifest_compare`'s empty guard, `report_multi_artist`'s and
`assert_field_view`'s all return **2**, which `run_assert` routes to `unknown()` and an exit 3.
`assert_dj_count`'s zero arm — and its neighbour `assert_no_compilations`'s — return **1**, which
routes to `bad()`, `REDS++` and an exit 1. But this file states at its own head that *"a blind
instrument wins over a measured red"* and that *"could not look is never folded into another
verdict"*. A sample holding no S5 files is precisely a could-not-look about the `albumtype:=dj`
path rule: the run never evaluated it. Returning 1 asserts a measured failure of a rule the run did
not exercise, and it also makes that verdict **outrank nothing** — the precedence block immediately
below says UNKNOWN outranks RED, so a run that is both vacuous here and blind elsewhere reports the
blindness and loses the vacuity entirely. The guards' own messages say `VACUOUS, not a pass` — the
right words attached to the wrong code. The justification 06-19 gave ("the guard its neighbour has
had from the start, returning the same code") is accurate, and it propagates the neighbour's
misclassification rather than fixing it, which is why both must move together.

GC-15: two `rsh "$(dex_cmd sha256sum "$REAL_LIB_DB" "$REAL_STATE_PICKLE")"` sites. `dex_cmd` renders
its arguments with `"$*"` — no `printf '%q'`, no `remote_sh_c` — and both values are `${VAR:-default}`
knobs, so a value with a space, a quote or a `$` word-splits or expands on the far side. These are
the last two path interpolations in the file that WR-08's stated rule does not cover, and this is a
bash **word** context, where `%q` is exactly right.

file, grep-verified during planning. Both findings are real; only the label was crossed. Do not go
looking for GC-15 in `quick-health-check.sh`.

GC-12: (a) a `UNKNOWNS=0` reset at the end of `self_test_vacuity`'s WR-06 section is dead — the
self-test gate consults only `ST_FAIL` and `REDS`. Harmless, but it is a counter written and never
read, in the section whose subject is counters that are never read. (b) The gate fires on
`ST_FAIL != 0` **or** `REDS != 0` but prints `%s of %s case(s) FAILED` with `ST_FAIL`, so a run
