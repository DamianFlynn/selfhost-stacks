Two subcommands, genuinely separable — the reap list is *written to a file* by `inventory` and
*read from that file* by `prune`, so the operator approval gate sits between two processes, not
between two branches of one:

`inventory` (READ-ONLY BY CONTRACT — contains no `docker rmi`, no `docker image prune`, no `rm`
against anything but its own previous output):
  - Print the run banner: hostname, UTC date, `FLOOR_GB`, `OUT_DIR`, and `mode: inventory (read-only)`.
  - Record `df -h /` and the `Avail` field in GiB as `BEFORE_AVAIL_GB`.
  - Record `docker system df` verbatim into the output.
  - Build the **referenced-image set** from `docker ps -a --format '{{.Image}}'` with **NO
    `--filter status=...`**. State inline why: the estate has a documented `created`-state blind
    spot (dispatcharr and teleport were down six weeks behind a green check) and a `created`
    container has never run, so a status-filtered query does not see it and its image would be
    reaped. Also resolve each container's `Image` via `docker inspect --format '{{.Image}}'` to
    capture image IDs for containers referencing a tag that has since moved — union both sets.
  - Build the **present-image set** from `docker images --format '{{.Repository}}:{{.Tag}}\t{{.ID}}\t{{.Size}}'`.
  - Reap candidates = present-image set minus referenced-image set, minus an explicit
    `KEEP_PATTERNS` allow-list containing `sentriz/wrtag`, `lscr.io/linuxserver/beets`,
    `metasauce/beets-flask`, `redis` and any `<none>:<none>` parent of a referenced image.
    Dangling `<none>:<none>` images with no referencing container ARE candidates.
  - Write the candidate list — one `REPOSITORY:TAG<TAB>ID<TAB>SIZE` per line — to `$REAP_LIST`,
    and print it to stdout with a total reclaimable size and a candidate count.
  - Summary block prints `root filesystem avail: <N> GiB   (floor <FLOOR_GB> GiB)`, `containers
    seen (docker ps -a, unfiltered): <N>`, `images present: <N>`, `reap candidates: <N>`,
    `reclaimable: <N> GiB`. Exit 0 always — `inventory` reports, it does not assert.

`prune` (⚠️ MUTATES live state):
  - Refuse with exit 2 if `$REAP_LIST` does not exist, naming the path and telling the operator to
    run `inventory` first. **Refusal, not a fallback.**
  - Re-derive the referenced-image set exactly as `inventory` does and **re-check every line of
    `$REAP_LIST` against it**. If any listed image is now referenced, abort with exit 1 naming it —
    a container may have been created between approval and prune.
  - `docker rmi` each approved line by image ID, one at a time, collecting failures rather than
    aborting on the first. **Never `docker image prune -a`, never `docker system prune`** — state
    that prohibition in the header as the load-bearing design decision.
  - Re-read `df -h /`. Print `AFTER_AVAIL_GB` and the delta.
  - EXIT-CODE CONVENTION, stated in the header: `0` = pruned and `AFTER_AVAIL_GB >= FLOOR_GB`;
    `1` = pruned but still below the floor, or a `docker rmi` failed; `2` = usage error or missing
    reap list.
  - Idempotent: a second `prune` finds every listed image already absent, reports
    `already reclaimed`, changes nothing, and still asserts the floor.

Do not add a `read -r` confirmation prompt — no script in `scripts/` has one; the approval gate is
the subcommand split plus Task 2's checkpoint.
