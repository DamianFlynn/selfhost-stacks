<objective>
Run D-13's bake-off: wrtag's `metadata` binary against the mutagen script, one normalisation job,
two tools, same folders, same before-state, same scoring instrument.

**The prediction, stated honestly before the run because staging a result is worse than a wrong
prediction.** `cmd/metadata/main.go`'s `cmdWrite()` builds one literal `map[string][]string` and
applies it to **every** path in the invocation via `iterFiles`. There is **no `-dry-run`, no diff,
and no field-to-field move primitive**; the only flags are `-log-level`, `-properties` for reads, and
`-index`/`-type`/`-desc`/`-mime-type` for images. A per-folder `artist`/`album` remap therefore needs
one `metadata read` plus one `metadata write` per file, in a shell loop, writing blind. Against a
Python+mutagen script whose `--dry-run` is the default and emits a reviewable diff, on a project
whose standing rule is *"verify with a second independent instrument before you write it down"*,
that is close to decisive.

**Run it anyway, and run it properly.** D-13 asks for it; it is cheap; and there are two ways the
prediction could be wrong that matter. First, `metadata write` calls
`tags.WriteTags(path, t, 0)` — flag `0`, **not** `tags.Clear` — which means it should **merge**
rather than replace, and would therefore not silently drop `TKEY` or `EnergyLevel`. That is read
from source and research assumption **A3** flags it as unconfirmed at the taglib layer, so confirm
it empirically. Second, `metadata`'s `go.senan.xyz/taglib` backend may handle the **134 WAV files**
better than mutagen does, whose WAV/ID3 support is materially weaker than its FLAC/MP3 support —
which would be a genuine, unanticipated reason to prefer it for one stratum.

D-13 is explicit that whichever wins becomes the normalisation tool **regardless of which engine
wins the main decision**.

Purpose: an engine that can also repair wrong tags is a materially different proposition from one
that can only fetch fresh ones. That is what D-12's falsified "No facility" claim opened up, and
this settles how much it is actually worth.
Output: `03-NORMALISER-BAKEOFF.md` and the D-13 verdict written into `03-DECISION.md`.
</objective>
