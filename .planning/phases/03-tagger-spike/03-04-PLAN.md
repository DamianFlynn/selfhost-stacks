<objective>
Stand up the throwaway beets container that hosts axis one's measurements, and prove — not assume —
that both metadata plugins are loaded.

Three constraints shape this plan. **D-03:** `stacks/selfhosted/arrs/beets/beets.yaml` and
`stacks/selfhosted/music/wrtag.yaml` are not edited; both were deliberately frozen in Phase 1 behind
`restart: "no"` + `profiles: ["manual"]`, and the spike measures rather than half-deploys a decision
nobody has made. **D-20:** nobody holds `rw` on `/mnt/tank/media/Music` during Phases 1–3 — this
container mounts Music not at all, which is stronger than `:ro`. **OD-6:** both Python artefacts run
*inside* this container, because LXC 100 has `python3` 3.13.5 with no `pip3`, no `python3-venv`, a
missing `ensurepip` (so `python3 -m venv` fails outright) and `EXTERNALLY-MANAGED` present (so PEP
668 blocks system pip) — a host-resident script importing `mutagen` is impossible.

**D-02** fixes the version: beets is measured at **2.13.1**, not the installed `2.5.1-ls295`, for
symmetry with D-01 — both engines measured at what would actually be deployed. 2.13.1 also carries
what later phases depend on: album-level YAML in the `edit` plugin, `beet modify` `+=`/`-=`, and
`importsource` for resumable imports.

One further principle, applied at the mount layer rather than in an after-the-fact check: **a plan
that only reads gets no write handle on what it reads.** The sample is the phase's whole substrate,
and the estate's safety model here should not depend on `find -newer` noticing a mistake after it has
happened. `raw/` is never written by any plan, so it is `:ro` everywhere. `normalised/` is written by
exactly one plan (03-05's `--apply`), so it is `:ro` everywhere else, and that one plan gets its own
service. This is the same argument the phase already makes for the library itself: absence of the
capability beats detection of its use.

Purpose: every number in criteria 1 and 2 comes out of this container, and a customised `plugins:`
list that omits `musicbrainz` silently disables autotagging while presenting as "no match found".
That failure mode must be closed by assertion before any measurement runs.
Output: a throwaway compose file and spike beets config in the phase directory, a running
`beets-spike` container (and a defined-but-normally-down `beets-spike-rw` writer service), and a
recorded `beet config -d` proving both plugins loaded.
</objective>
