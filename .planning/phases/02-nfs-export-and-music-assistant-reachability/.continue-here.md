## Precondition before ANY plan in this phase runs

atlantis (`172.16.1.158`) must be healthy. Check first, do not assume:

```bash
ssh root@172.16.1.158 'uptime -s; cat /proc/pressure/io; dmesg -T | grep -c amdgpu_hmm_invalidate_gfx'
```

**Do not use load average as the health bar.** Load is the *symptom* of this failure, it lags, and a
freshly rebooted host reads near 0 for several minutes whether or not the fault is fixed — it gives a
false green exactly when you most want a true one. The direct instruments are:

| Instrument | Healthy | At the halt |
|---|---|---|
| `/proc/pressure/io` → `full avg300` | near 0 | **96.22** |
| `dmesg -T \| grep -c amdgpu_hmm_invalidate_gfx`, **this boot** | 0 | 8 lines / 4 events |
| `uptime -s` | must be *after* the recovery | unchanged at 2026-08-18 09:50 |

Check `uptime -s` first: if the boot stamp has not moved, no recovery has occurred and the other
readings describe the same wedged kernel regardless of what load says.

Also confirm LXC 100's sshd sends a **banner** (`ssh root@172.16.1.159`), not merely accepts TCP —
it accepted TCP throughout the incident while unable to fork a shell.

**`pct exec 100 -- …` is not a reliable fallback.** It works for short commands and hangs on anything
touching `/proc` or systemd (corrected in `e8f3fe7`). Read a hang there as a symptom of the wedge,
not as a bad command of your own.

## Flagged for 02-04 before it is authored

**`192.168.90.31` is an unstable address and should not be pinned.** Plans 02-01 and 02-04 pin
Jellyfin at `192.168.90.31:8096`. That subnet is real — it is the `t3_proxy` Docker bridge from
`stacks/selfhosted/traefik/compose.yaml` — but:

| Service | Network | Static? |
|---|---|---|
| Jellyfin | `iot_macvlan` `172.16.1.76` | **yes** (`jellyfin.yaml:70`) |
| Jellyfin | `t3_proxy` `192.168.90.x` | **no static assignment** |
| Traefik | `t3_proxy` `192.168.90.254` | yes (`traefik.yaml:38`) |

Only Traefik pins itself on that bridge. Jellyfin's `192.168.90.x` address is whatever Docker IPAM
hands out, so it can move on any stack redeploy, image update or host reboot. `check-music-consumers.sh`
is meant to be the **long-lived** detector of MA/consumer regressions (D-21, D-56) — pinning it to a
DHCP-ish bridge address means it breaks silently, in a repo that already has a documented Renovate
deploy-drift problem and a six-week silent outage on record.

Use the Docker DNS name (`jellyfin`) on the shared network instead of an IP literal. That keeps the
plan's host-residency property — the name resolves only from inside LXC 100's Docker networks, so the
"same request from the workstation fails" assertion still holds — while being stable. `172.16.1.76`
is the fallback if a literal is required, but it is LAN-reachable and so weakens host-residency.

Not yet confirmed against the live container (LXC 100 unreachable at time of writing) — treat as a
risk to verify, not a measured fact.
