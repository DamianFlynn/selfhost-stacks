<objective>
Author the Terraform that defines the read-only NFSv4 export of `/mnt/tank/media/Music` to the Home
Assistant NUC. **This plan writes code only — it does not apply it.** Plan 02-03 applies and proves.

Purpose: CONS-01 says the export is "defined in Terraform", and CLAUDE.md's Infrastructure Rules make
Terraform authoritative for host resources. Splitting authoring from applying keeps this plan's blast
radius at zero — nothing here touches a host running 78+ containers — and lets `terraform validate`
plus a plan diff be the automated gate.

Output: `infra/nfs-music-export.tf` (new), plus `ha_nuc_ip` and the temporary-export enable flag in
`infra/variables.tf`, and verification commands in `infra/outputs.tf`.

**This plan satisfies CONS-01's "defined in Terraform" half and, with 02-03, is independently
shippable** (D-52): a `ro` export that nothing consumes yet is harmless and complete. If the phase
stalls after plan 03, the estate is strictly better off.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Terraform state → public git | `infra/terraform.tfstate` is committed to a public repo; anything interpolated into a resource lands there |
| `/etc/exports.d/` → kernel export table | The file this code writes becomes NFS's access-control decision for a 34 GB library |
| any LAN host → atlantis:2049 | Installing `nfs-kernel-server` opens 2049/tcp (and 111 via `rpcbind`) on all interfaces |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information disclosure | The export's host specification | mitigate | Single-host spec — `var.ha_nuc_ip` with **no netmask and no wildcard**. A `/24` or `*` fails CONS-01. Task 2's acceptance criteria assert the exact option list. |
| T-02-02 | Elevation of privilege | `sec=sys` trusts client-asserted uids, so a client can claim uid 0 | mitigate | `all_squash` maps every uid including 0 to `anonuid=${var.apps_uid}`. This supersedes the `root_squash`/`no_root_squash` question entirely. |
| T-02-03 | Tampering / Denial of service | A writable export would let any reader corrupt or delete 34 GB of curated library | mitigate | `ro` at the export layer. The tree is `0777` and knfsd does not export NFSv4 ACLs, so mode bits are all a client sees — server-side `ro` is the only real control, and Route B has no client-side `ro` option at all.
