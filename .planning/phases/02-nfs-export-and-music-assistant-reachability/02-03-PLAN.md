<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Terraform (workstation) → atlantis root over SSH | An apply executes arbitrary commands as root on a host running 78+ containers |
| any LAN host → atlantis:2049 | Now open for the first time; access control is the export table alone |
| atlantis kernel export table → `/mnt/tank/media/Music` | The only thing standing between a mounting client and 34 GB of curated library |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information disclosure | Any LAN host mounting the export | mitigate | Task 2 asserts the exact single-host string from `exportfs -v` and explicitly fails if the client field is `*` or a CIDR. |
| T-02-02 | Elevation of privilege | A client claiming uid 0 under `sec=sys` | mitigate | Task 2 asserts `all_squash`, `anonuid=568` and `anongid=568` are present in the live kernel export table, not merely in the file. |
| T-02-06 | Elevation of privilege | `no_root_squash` present | mitigate | Two gates both fire in this plan: the apply's own `remote-exec` assertion (would have failed Task 1), and Task 2's independent `exportfs -v` grep. |
| T-02-03 | Tampering | The export being `rw` | mitigate | Task 2 asserts `ro` in `exportfs -v`. **The definitive test is plan 02-05's Stage 4b**, which bypasses the client-side `ro` — asserting `ro` in the table here is necessary but not sufficient, and this plan does not claim otherwise. |
| T-02-13 | Denial of service | The M1 simulation leaves the dataset unmounted or unexported | mitigate | Task 2's restore step is part of the same task, and its acceptance criteria require `exportfs -v` to show the Music line again and `mountpoint -q` to succeed before the task is done. | T-02-08 | Information disclosure | 2049 now listening on all interfaces | accept | Access control is the export table's single-host restriction, not a firewall.
