<objective>
Take the QUAL-01 before-state snapshot over the whole import candidate set, and prove the comparison
mechanism works by running the diff script against the snapshot itself.

This is the plan the roadmap says must happen **now**: "once content has been staged or imported,
the before-state can no longer be recovered, and Phase 7's diff has nothing to compare against."
Phase 5 depends on this having completed; so does Phase 7's QUAL-02 gate.

**Ordering decision (open question resolved).** The capture runs **before** the ownership
normalisation in plan 01-08, and the reasoning is worth stating because the obvious argument is the
wrong one.

`ffprobe` output records neither `uid:gid` nor mode, and the D-01 key is computed over the encoded
audio bitstream with `-c copy`. A recursive `chown`/`chmod` therefore cannot perturb either the key
or a single recorded field — the snapshot is provably *invariant* under the ownership work, so
ordering cannot change its content. Because ordering is free on content, it is decided on risk
instead: the capture runs before the first mutating operation this phase performs on the library, so
the only field-level record of what the tags were predates every write the phase makes. The ZFS
snapshot from plan 01-02 already covers the tree, but `zfs rollback` is an all-or-nothing revert of
the whole dataset; a field-level record that predates the mutation is a strictly finer instrument
and costs nothing to have.

The cost accepted is that plan 01-08's `chown` waits behind a multi-hour read. That is acceptable:
the only consumer of the decided `uid:gid` is Phase 2's export, which runs in parallel and does not
gate on Phase 1 completing.

Output: `pre-project.ndjson.gz`, its `.done` ledger and its `.failed` list, all inside the fence,
plus a recorded self-diff exit 0.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| capture job → 140 GB of source content across two ZFS datasets | A read-only job of this size running for hours as root; a write bug here damages content whose only field-level record is the file this job is producing |
| capture output → `/mnt/fast/safety` | The fence has no ZFS snapshot behind it |
| capture job → host memory | `/tmp` is tmpfs; ARC pressure from a 140 GB sequential read is real |
| snapshot file → Phase 7 | Everything QUAL-02 will conclude rests on this file being complete and honest about its gaps |

| T-01-20 | Denial of Service | Long-running job killed by a dropped ssh session, losing hours of work | mitigate | Run detached under tmux/screen/nohup; the `.done` ledger makes a re-run resume rather than restart. Proven in plan 01-03 Task 3 |
