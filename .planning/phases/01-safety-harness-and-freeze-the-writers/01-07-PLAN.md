<objective>
Turn off the beets settings that destroy tags, in every beets config in the estate — and make the one
that matters most survive a container rebuild.

SAFE-01's word is *every*. The roadmap is explicit that this covers "the repo ones **and** the
on-host `/config/scripts/beets-config.yaml`". That on-host file is what `audio.bash` actually uses on
every SABnzbd music download, it is not in git, and it is the confirmed cause of the 1 Aug and 8 Aug
ingest skips — it declares `plugins: embedart` and nothing else, and since beets 2.4.0 MusicBrainz is
a plugin, so that config has no metadata source at all.

Purpose: `scrub` strips tags, `lastgenre` overwrites genre, and `embedart` rewrites files — all three
firing automatically on import. Against a 34 GB library that is already correctly tagged and 97 GB of
backlog carrying irreplaceable DJ metadata, an automatic scrub is the fastest way to make this
project unrecoverable. Turning them off is cheap; leaving them on is the failure mode QUAL-01 exists
to detect only after the fact.

Purpose (second): vendoring the SABnzbd config is what makes the change durable. The precedent in
this estate is the SABnzbd post-processing guard, which only survives container rebuilds because
`scripts_init.bash` is vendored — restoring the stock setup silently reverts the guard and lets
failed downloads be post-processed into the library. Version-controlling this file pays off again in
Phase 4, when its `plugins` line is stripped from a known state rather than a guessed one.

Output: three beets configs corrected, the SABnzbd one vendored and bind-mounted with provenance, and
a recorded enumeration proving no fourth config was missed.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host appdata → git repository | A file that has lived only on the host is being committed for the first time; whatever is in it becomes permanent history on a repository that gets pushed |
| beets config → library files | These three settings authorise automatic, irreversible tag mutation on every import |
| repo copy → appdata copy → container | Three representations of the same file that can silently diverge |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-01-38 | Information Disclosure | Discogs user token or other credential committed to git in the vendored config | mitigate | Task 1 is a blocking screening gate before anything is written; the repo copy carries a placeholder and the real value stays in appdata or the stack `.env`. Acceptance criterion greps the committed file for token, api_key, password and secret |
| T-01-39 | Tampering / destruction | `scrub.auto`, `lastgenre.auto` or `embedart.auto` left on | mitigate | All three set explicitly to `no` in every config, present even where the plugin is absent, and verified by reading the file from inside the running container rather than from the host |
| T-01-40 | Tampering | Setting reverted by a container rebuild | mitigate | The file is bind-mounted from appdata and vendored in the repo with a dated NOTE stating what breaks on revert — the same mechanism that keeps the SABnzbd post-processing guard alive |
