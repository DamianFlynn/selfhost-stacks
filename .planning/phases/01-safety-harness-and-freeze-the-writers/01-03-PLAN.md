<objective>
Ship both halves of QUAL-01's mechanism: the before-state tag snapshot tool, and the diff tool that
proves the comparison works.

The roadmap's sixth success criterion is that a trial diff of the snapshot against itself returns
zero differences — "proving the comparison mechanism works before it is trusted to prove anything."
That gate is unmeetable unless the diff tool exists now (D-04), and Phase 7's QUAL-02 gate consumes
the same script unchanged. Building only the capture half would leave Phase 7 to invent a comparison
at the moment it most needs a trusted one.

Purpose: the library is not empty. A file can pass every check in CONS-04 — it lands, `ffprobe`
reads it, both consumers show it — while having *lost* fields it arrived with. That is a regression
shaped like a success, and at backlog scale it is unrecoverable. This plan builds the only thing
that can detect it.

Output: `scripts/snapshot-music-tags.sh` and `scripts/diff-music-tags.sh`, both committed at mode
0755. This plan authors and unit-proves them on a handful of files; plan 01-04 runs the full
~140 GB capture.

**No Python.** `find . -name "*.py"` returns zero results anywhere in this repository outside
`.git`. Do not scaffold a Python project for D-01 through D-05. Both tools are `ffmpeg`/`ffprobe`
plus `jq` plus `gzip` pipelines and belong in `scripts/*.sh` under the existing convention.
</objective>

following the `setup-mpe.sh` header and strictness convention with ALL-CAPS constants.

Constants: `FENCE=/mnt/fast/safety/music-pre-project`, `OUTDIR=${FENCE}/tags`, and the four scan
roots — `/mnt/tank/downloads/complete/nzb/unsorted`, `/mnt/tank/downloads/complete/nzb/dj-mixes`,
`/mnt/tank/downloads/complete/nzb/music`, and `/mnt/tank/media/Music`. That is D-02's scope: roughly
9,764 files and 140 GB in one full read. The library files are included despite re-importing them
being out of scope, because an import writing to a colliding destination path can degrade them and
they have no other recovery path.

Accept a positional argument naming the output basename (default `pre-project`), plus a `--roots`
override for testing on a small subtree, plus a `--limit N` for a bounded trial run. The three
artifacts are then `${OUTDIR}/<basename>.ndjson.gz`, `${OUTDIR}/<basename>.done`, and
`${OUTDIR}/<basename>.failed`. All three live inside the fence (D-03: one file, placed inside the
fence). Never write to `/tmp`.

**The key (D-01).** For each file, compute the audio-stream hash with `ffmpeg` reading the file,
mapping only the audio stream, copying rather than decoding, and writing the `md5` muxer to stdout.
`-c copy` is load-bearing: the point is to hash the encoded bitstream so that tag rewrites do not
perturb it. Strip the muxer's `MD5=` prefix and store the bare hex digest as the field `audio_md5`.
Path is recorded as an attribute (`source_path`), never as the key — Phase 5 moves release folders
into `_inbox` and Phase 7's import writes a new `ALBUMARTIST/Album/NN Title` path, so a path-keyed
snapshot would have zero matching rows by the time the Phase 7 diff runs.

**The record (D-05, D-03).** For each file emit exactly one NDJSON line: a JSON object carrying at
minimum `audio_md5`, `source_path`, `size_bytes`, `mtime_epoch`, and `ffprobe` — the **complete**
`ffprobe` output with quiet log level, JSON print format, `-show_format` and `-show_streams`, so
format tags *and* per-stream tags are both captured. Do not select a field list; `TKEY` and
`EnergyLevel` must fall out automatically. Assemble the line with `jq` so quoting and unicode in tag
values cannot corrupt the stream. Append the line to the gzip output as it is produced — gzip
supports concatenated members and `zcat` reads them transparently — so an interrupted run leaves a
salvageable file rather than a truncated one.

**Resumability (D-02, planner discretion resolved).** The mechanism is a companion completed-paths
ledger, not a re-scan of the NDJSON:

  - After a file's NDJSON line is successfully flushed, append its absolute source path as one line
    to `<basename>.done`.
  - On start, if `<basename>.done` exists, load it once into an associative array and skip any path
    already present. Do **not** decide skip-or-not by decompressing and parsing the NDJSON: the
    NDJSON is gzipped and keyed by audio hash, so answering "have I already done this path" from it
    would mean reading the whole file on every restart, and the cost grows with progress.
  - A file whose `ffmpeg` or `ffprobe` invocation exits non-zero is appended to `<basename>.failed`
    with its exit code and is **not** written to `.done`, so a re-run retries it. Report the failed
    count at the end and print the path to the failed list.
  - Print progress in the `pg-migrate.sh` banner style: a banner per scan root, and a periodic
    counter line every 100 files giving processed / skipped-as-done / failed / remaining.

The script must be safe to interrupt with Ctrl-C or a dropped ssh session at any point and safe to
re-run immediately: state that explicitly in the `Idempotent:` header line, and prove it in Task 3
of plan 01-04.

Guard the preconditions in the `pg-migrate.sh` guard-then-SKIP shape: abort with a clear message if
`ffmpeg`, `ffprobe`, `jq` or `gzip` is missing, and abort if `OUTDIR` does not exist — that
directory is created by `freeze-music-apply.sh fence` in plan 01-02, and its absence means the
fence has not been built, which means this capture would have nowhere protected to land.

Commit at mode 0755.
  </action>

  <files>scripts/diff-music-tags.sh</files>

  <action>
Create `scripts/diff-music-tags.sh`, taking two positional arguments: a BEFORE snapshot and an AFTER
snapshot, each a gzipped NDJSON file produced by `snapshot-music-tags.sh`. Usage line and exit 2 on
wrong argument count.

Join the two datasets on `audio_md5`. That is the whole reason D-01 chose an audio-stream key: the
before row was captured at `/mnt/tank/downloads/complete/nzb/unsorted/<folder>/<file>` and the after
row will be at `/mnt/tank/media/Music/<ALBUMARTIST>/<Album>/NN Title.<ext>`, and only a key computed
over the encoded bitstream matches across that move and rename.

Flatten each side's tag set into a comparable `key=value` map before comparing. Merge the
`format.tags` object with the tags of each audio stream, prefixing stream tags so a format tag and a
stream tag of the same name cannot silently collapse. Normalise tag names to a single case for
comparison but report the original casing, because container formats differ in how they case the
same logical field.

Emit five categories, each as its own numbered section with a count and then the rows:

  1. **MATCHED** — `audio_md5` present on both sides.
  2. **MISSING_AFTER** — present in BEFORE, absent from AFTER. This is the file-level loss case.
  3. **NEW_AFTER** — present in AFTER, absent from BEFORE.
  4. **FIELDS_DROPPED** — per matched file, tag keys present in BEFORE and absent in AFTER. This is
     the QUAL-02 gate: net metadata loss.
  5. **FIELDS_GAINED** and **FIELDS_CHANGED** — per matched file, keys added, and keys present on
     both sides with a differing value.

Report per-file rows as tab-separated `audio_md5`, `source_path` (BEFORE side where it exists),
field name, before value, after value — truncating long values to a stated width so a terminal run
stays readable, with a `--full` flag that disables truncation for machine consumption.

Support `--summary-only` to print just the six counts, and `--json` to emit the whole result as one
JSON object so Phase 7 can gate on it programmatically rather than by eye.

Exit codes, stated in the header: `0` when MISSING_AFTER is 0 **and** FIELDS_DROPPED is 0 — no net
metadata loss; `1` when either is non-zero; `2` on usage or input error. This makes the roadmap's
"trial diff of the snapshot against itself returns zero differences" a literal exit-0 assertion, and
makes Phase 7's QUAL-02 gate a script invocation rather than a judgement call.

Implement the comparison with `jq` over the decompressed streams. Do not write intermediate files to
`/tmp` — if a scratch file is needed for a large join, place it beside the inputs under the fence
and remove it on exit with a trap.

Commit at mode 0755.
  </action>
