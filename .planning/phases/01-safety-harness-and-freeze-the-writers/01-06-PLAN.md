<objective>
Close the two application-layer writers that a mount audit cannot see.

Plan 01-05 made WRIT-01 structurally true at the mount level. Two writers survive that, by design and
by omission. Lidarr is the fifth writer the roadmap never counted: its root folder is `/media/Music`
with `renameTracks` on, and it has been actively renaming files inside the shared library tree.
Jellyfin is the documented exception that keeps rw — so its writing has to be disabled where it
actually originates, in the application.

Purpose: WRIT-03 and SAFE-05 are both settings changes with no Terraform provider, which is why D-27
makes a script the honest mechanism and why this plan's evidence is API responses and observed host
state rather than a config diff. The roadmap is explicit that Lidarr's state must be confirmed from
its API rather than its UI, and that SAFE-05's proof is an hour of watching a real folder.

Output: Lidarr repointed and de-fanged with API evidence recorded, Jellyfin's Music library frozen at
the application layer with its database backed up first, and a recorded one-hour sidecar watch.

This plan is `autonomous: false`. The Jellyfin settings are application state with no provider and no
stable CLI, and the one-hour observation is a wall-clock wait. Both are automated as far as their
APIs allow and then confirmed by a human, rather than pretended to be unattended.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API key in Lidarr's `config.xml` and Jellyfin's config | Credentials read from appdata on the host to make these changes; they must not end up in the repo or in a committed report |
| Lidarr → library tree | Two independent write paths — track renaming and metadata consumers — only one of which the roadmap counts |
| Jellyfin → library tree | The one container that keeps rw; mitigation is entirely at the application layer, so a setting silently reverting re-opens it |
| Jellyfin live SQLite database | Backed up while the instance is serving; a torn copy is a backup that only fails when it is needed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-31 | Tampering | Lidarr metadata consumers writing `.nfo` and images into the library independently of `renameTracks` | mitigate | Every metadata provider disabled and enumerated by name in the SUMMARY. Turning off `renameTracks` alone leaves this open — it is the write path the roadmap does not count |
| T-01-32 | Tampering | Torn Jellyfin SQLite backup from a plain copy of a live WAL database | mitigate | SQLite online-backup mechanism against the live file, followed by an integrity check before the file is treated as a backup |
| T-01-33 | Repudiation | Setting verified in the UI rather than from the API | mitigate | All three Lidarr settings and both Jellyfin options are read back from the API and saved as JSON under the fence. The roadmap names API-not-UI explicitly |
| T-01-34 | Repudiation | New sidecar indistinguishable from a pre-existing one | mitigate | The D-18 baseline from plan 01-01 plus a T+0 enumeration; the gate is the T+60-vs-T+0 delta, with the T+0-vs-baseline delta recorded separately |
| T-01-35 | Information Disclosure | Lidarr and Jellyfin API keys | mitigate | Keys are read from appdata at run time and never written into the repo, into a SUMMARY, or into any file under the fence. Recorded API responses must be inspected for embedded keys before being saved |
| T-01-36 | Denial of Service | Disabling the wrong Jellyfin setting and breaking Movies/TV metadata for a serving instance | mitigate | Both settings scoped to the Music library only; acceptance criterion asserts Movies and TV are unchanged and the global scheduled-scan task is untouched |
| T-01-37 | Tampering | Losing a Lidarr artist by removing the old root folder while artists are still bound to it | mitigate | Reassign before removing; the SUMMARY records what happened to any bound artist |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs. All changes are REST API calls plus one YAML suffix edit; no image tag changes |
</threat_model>
