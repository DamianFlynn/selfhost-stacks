<objective>
Write down what Phase 1 did, correct the document that would undo it, and put the harness check on a
path someone already runs.

This plan authors no new mechanism. Everything it records is already true on the host by the time it
runs. That makes it easy to treat as bookkeeping and skip — which is exactly the failure this phase
exists to prevent. Three specific things go wrong if it does not run:

1. **`beets.md:159` instructs `chown -R 568:545`.** It sits in the "Gotchas found the hard way"
   section, immediately after the `rsync` workaround — read at exactly the moment someone is copying
   files into the library and about to fix up ownership. Left in place, the document re-creates the
   drift plan 01-08 just removed. This is D-14 and it is still the highest-value edit in the plan.

   **But the reason D-14 gave was wrong, and plan 01-08 proved it.** `568:545` was not a baseless
   Windows/SMB-era convention matching nothing — **545 was the real on-disk gid on 1,171 entries.**
   The belief that it matched no folder came from reading the 01-01 census through LXC 100's
   unprivileged idmap, which collapsed on-disk `0:545` to `65534:65534` and `568:545` to
   `568:65534`. The whole phase reasoned about ownership from a mapped view and only the sweep,
   run from the hypervisor, revealed the disk.

   **The correction to `568:568` still holds — but not on "Music was the outlier" either.** That
   was 01-08's own first answer, taken from a per-subtree census that had not finished, and it is
   also wrong; see `01-08-SUMMARY.md` Deviation 7. The completed census shows **`/mnt/tank/media/TV`
   carries 114,218 entries on gid 545** — 48× Music's 2,357. The estate is **split**, not uniform:

   | Subtree | Dominant owners | gid 545? |
   |---|---|---|
   | Photos | 368,826 `0:568` | no |
   | **TV** | **64,546 `0:545`, 49,672 `568:545`** | **YES — 114,218** |
   | Movies | 22,903 `568:568`, 12,533 `0:568` | no |
   | **Music** | **1,186 `0:545`, 1,171 `568:545`** | **YES — 2,357** |
   | Books | 42 `568:0` | no |

   So the honest justification for `568:568` is **not** "Music was uniquely wrong". It is:
   **gid 545 is an orphan gid** — `getent group 545` returns nothing on the Proxmox host, and 545
   is unmapped in LXC 100's idmap, which is precisely why the container saw `65534` and why `chown`
   was impossible from inside it. **gid 568 is `apps`**, stated in `STANDARDS.md:141`,
   `DEPLOYMENT.md:31`, `README.md:29` and `CLAUDE.md:52`, and is the estate majority (~78% of media
   entries). Music and TV almost certainly arrived together from a system where 545 was meaningful
   (the Windows/SMB `Users` RID and the TrueNAS `builtin_users` gid).

   **Write that reason into `beets.md`, not the two superseded ones.** This bullet has now been
   wrong twice for two different reasons, which is itself worth a line in the record.

2. **The decided value is not in the repo.** Roadmap criterion 5 is two claims: `stat` returns one
   decided `uid:gid`, *and* that value is recorded in the repo, because it also sets `anonuid`/
   `anongid` on the Phase 2 export. Plan 01-08 made the first true. Until this plan runs, WRIT-04 is
   half-met and Phase 2 has to re-derive a decision that was already taken.

3. **The harness is only checked by a script nobody runs on a schedule.** `check-music-freeze.sh`
   exists and asserts, but D-29's whole argument is that a check off the beaten path is a check that
   does not fire: the docker `created`-state blind spot left dispatcharr and teleport down for six
   weeks while the estate reported clean. Folding it into `quick-health-check.sh` puts freeze drift
   on a path already in use.

The plan also corrects one thing that will otherwise misinform every later phase: `PROJECT.md`'s
Constraints section states that ownership "is undecided, not merely inconsistent". That was true
when it was written and is false the moment 01-08 completes. The same paragraph is mirrored into
`CLAUDE.md`'s project section, so both are corrected in the same commit — a stale constraint in the
file that is auto-loaded into every session is worse than one in a planning document.

Output: `beets.md` extended and corrected, a harness block in `quick-health-check.sh`, PROJECT.md
Key Decisions rows and a corrected constraint, and a final pass confirming all six roadmap criteria
for Phase 1 are true.
</objective>
