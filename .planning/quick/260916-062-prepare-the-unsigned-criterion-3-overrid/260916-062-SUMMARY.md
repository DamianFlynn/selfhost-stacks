## The credential screen — and the defect it exposed in the plan's own verify block

**The plan's screen was blind, and its `TIER_A_RC=1` "clean" result was vacuous.** This is a real
finding, not a nit, and it is the exact failure mode this plan exists to guard against.

The plan's Gate C pipes:

```
git diff --cached -U0 | grep -E '^\+' | grep -v '^\+\+\+' | grep -nEi "$TIER_A"
echo "TIER_A_RC=$?"    # must be 1
```

The middle `grep -v '^\+\+\+'` is a **basic** regular expression. This workstation's `grep` is
**ugrep 7.8.4**, where `\+` following `^` is a repetition operator with no operand:

```
ugrep: error: error at position 5
(?m)^+++
     \___invalid syntax
```

It exits **2** and emits **nothing**. The downstream grep then reads an empty stream and exits
**1** — which the plan declares to mean "no credential-shaped string in any added line". Tier A
(the hard gate), Tier B (the advisory) and `ESTATE_CMDS` all passed on an empty input. The plan's
positive control could never have caught this, because the control runs a *different* pipeline
(`printf … | grep`) that never touches the broken BRE.

Three fixes were applied (deviation Rule 1 — a broken verification instrument):

1. `grep -Ev '^\+\+\+'` (ERE), so the extraction actually runs.
2. The extraction is materialised once to a file and its line count asserted non-zero
   (`ADDED_LINES=703`) — "could not look" is now distinct from "nothing is wrong".
3. The positive control is injected into **the real pipeline's input**, not a parallel one.

With the screen actually looking:

| Gate | Required | Measured |
|---|---|---|
| `DIFF_RC` | 0 | **0** |
| `ADDED_LINES` (non-vacuity floor) | > 0 | **703** |
| `CONTROL_RC` (planted 32-hex caught in the real pipeline) | 0 | **0** |
| `TIER_A_RC` (staged diff clean) | 1 | **1** |
| `ESTATE_CMDS` over the four deliverables | 0 | **0** |

**Both assertions hold.** `TIER_A_RC=1` alone would prove nothing; it is believable only because
`CONTROL_RC=0` on the same input path, with a non-zero line count behind it.
