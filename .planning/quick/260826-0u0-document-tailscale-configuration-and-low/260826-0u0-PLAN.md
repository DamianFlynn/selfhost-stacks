# Quick Task 260826-0u0: Tailscale configuration and low-level design

## Why

Tailscale is load-bearing for this estate — it is how the LAN is reached off-site and how
~11 services are published — but it was undocumented and spread across four unrelated
deployment mechanisms. On 2026-08-25 the gateway's Tailscale died after a firmware update
and took the *entire* `172.16.1.0/24` route with it, because the gateway was the only
subnet router. Recovering it required knowledge held nowhere in the repo. A second subnet
router (Home Assistant) was added the same night.

This task writes that design down before it is forgotten again.

## Tasks

### Task 1 — Create `TAILSCALE.md`

**files:** `TAILSCALE.md` (new)

**action:** Write the low-level design covering:
- Tailnet identity, node inventory, tag model
- The four deployment patterns and why each exists
- Subnet routing / exit node design, HA failover, primary election
- The standby-router LAN-IP behaviour (documented as designed behaviour, not a bug)
- Failure modes: firmware wipe, OOM at boot, key expiry, single-router SPOF
- Ops runbook: recover a dead gateway client, fail back, verify

**verify:** All IPs/versions/paths match live output captured 2026-08-25/26; no invented
hostnames or option names.

**done:** `TAILSCALE.md` exists and every claim traces to observed state.

### Task 2 — Cross-link from `NETWORK.md` and `CLAUDE.md`

**files:** `NETWORK.md`, `CLAUDE.md`

**action:** Add a Tailscale/Remote Access section to `NETWORK.md` pointing at `TAILSCALE.md`,
and add `TAILSCALE.md` to the Documentation list in `CLAUDE.md`.

**verify:** Links resolve to a real file; existing content not restructured.

**done:** Both files reference `TAILSCALE.md`.

## Out of scope

- Changing any live Tailscale configuration (the estate is already in the target state)
- ACL policy file management (lives in the Tailscale console, not this repo)
- Fosse Road `gl-mt3000` remediation (offline since Jun 13 — a separate task)

## Must haves

- The gateway is NOT the only subnet router any more, and the doc says why that matters
- The firmware-wipe failure mode and its hardened unit are recorded
- The standby LAN-IP gotcha is recorded as expected behaviour with the workaround
