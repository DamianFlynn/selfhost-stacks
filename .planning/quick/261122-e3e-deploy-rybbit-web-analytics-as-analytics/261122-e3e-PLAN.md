- `redis:8.6.4-alpine` (Docker Hub 200; upstream pin)

**Upstream env names (v2.9.3 compose):** backend reads NODE_ENV, CLICKHOUSE_HOST, CLICKHOUSE_DB,
CLICKHOUSE_PASSWORD, CLICKHOUSE_QUERY_PASSWORD, POSTGRES_HOST, POSTGRES_PORT, POSTGRES_DB,
POSTGRES_USER, POSTGRES_PASSWORD, REDIS_HOST, REDIS_PORT, REDIS_PASSWORD, BETTER_AUTH_SECRET,

LITE_DASHBOARD, OPENROUTER_API_KEY, OPENROUTER_MODEL. Client reads NODE_ENV, NEXT_PUBLIC_BACKEND_URL
(= BASE_URL), NEXT_PUBLIC_DISABLE_SIGNUP, NEXT_PUBLIC_DEPLOYMENT, NEXT_PUBLIC_LITE_DASHBOARD.
ClickHouse reads CLICKHOUSE_DB, CLICKHOUSE_USER (leave as `default` — "the backend always connects
to ClickHouse as the default user"), CLICKHOUSE_PASSWORD, CLICKHOUSE_DEFAULT_ACCESS_MANAGEMENT=1.
Backend listens 3001 (healthcheck `wget --spider http://127.0.0.1:3001/api/health`); client 3002;
ClickHouse healthcheck `wget --spider http://localhost:8123/ping`; postgres `pg_isready`; redis
`redis-cli -a $REDIS_PASSWORD --no-auth-warning ping`.

**Upstream routing:** `/api/*` and `/.well-known/oauth-*`, `/.well-known/openid-configuration*` →
backend:3001; everything else → client:3002.

**The tracking script derives its host by splitting its own `src` on `/script.js`**, so with
`src=https://pulse.deercrest.info/api/script.js?siteId=N` every browser call goes to
`https://pulse.deercrest.info/api/...`. Browser-hit backend paths (v2.9.3 index.ts + tracking.ts +
cors.ts `isPublicCorsPath`):
- GET `/api/script.js`, `/api/replay.js` (rrweb, session replay), `/api/metrics.js` (web vitals lib)
- POST `/api/track` (pageviews, custom events, outbound, errors, web-vitals all ride this)
- POST `/api/identify`
- POST `/api/session-replay/record/{siteId}`
- GET `/api/site/tracking-config/{siteId}`
- POST `/api/site/{siteId}/feature-flags/evaluate`
These are exactly the public router's paths. Deliberately NOT public: `/api/sites/{id}/sessions`
and `/api/sites/{id}/embed-stats` (in upstream's public CORS list, but they only serve Rybbit's
public-dashboard / embed widgets, which this deployment does not offer), `/api/site/check-install`,
`/api/version`.

**Backend CORS already reflects any origin on those public paths** and skips its untrusted-origin
403 for them (cors.ts). So the Traefik public router must NOT add CORS handling of its own.

**Traefik trap found in planning:** `secure-headers@file` (part of both `chain-no-auth` and
`chain-authelia`) sets `accessControlAllowMethods: [GET, OPTIONS, PUT]` and `accessControlMaxAge`.
When a headers middleware has CORS options, Traefik answers preflight requests itself — so a
`chain-no-auth` public router would answer the `/api/track` preflight without POST and break every
cross-site pageview. The public router therefore uses **`default-headers@file` only**. The
verification step measures the preflight either way.

**Signup:** better-auth `disableSignUp: DISABLE_SIGNUP` in server/src/lib/auth.ts → env var
`DISABLE_SIGNUP` (D-05's guess was correct). The client mirrors it via NEXT_PUBLIC_DISABLE_SIGNUP.

**Cloudflare is in front:** Traefik's websecure entrypoint already trusts Cloudflare IPs
(`forwardedHeaders.trustedIPs=${CLOUDFLARE_IPS}`), and the backend sets `trustProxy: true`, so
visitor geolocation works without Caddy's trusted_proxies block.
