## Design decisions already made — implement these, do not re-litigate

1. **Target the real route via `--resolve ...:127.0.0.1`, not plain DNS.** Pinning to the local
   loopback asserts *this estate's* Traefik: the probe cannot pass because Cloudflare is serving
   something else, and cannot fail because external DNS or hairpin NAT broke. It deliberately does
   **not** assert public reachability — say so in the in-band notice so nobody later reads a green
   tick as "the dashboard is reachable from the internet".
2. **The pass condition is a protected answer, not 200.** `curl` sends no cookies, so an
   authenticated 200 is unobtainable from a script and demanding one would be a new permanent red —
   the same defect class being fixed here. Measured healthy answer is `302` to
   `auth.deercrest.info`.
3. **200 is a VIOLATION.** It would mean the Authelia chain was bypassed and the dashboard is being
   served unauthenticated. Its own ❌, its own wording, `EXIT_CODE=1`.
4. **No `--max-time` on curl.** The Linux-side `timeout $REMOTE_TIMEOUT` is the bound (house rule,
   point 3 of the four-point note at line ~368). Adding `--max-time` would convert a hang into curl
   exit 28 — a *real measurement* — and so erase the 124 "could not look" distinction.
5. **`/ping` is out of scope.** `--ping=true` is not set on this container, so probing it would
   require an estate change. Probing `api@internal` from inside the container was also rejected: it
   would assert less than the chosen probe (no entrypoint, no TLS, no middleware) and needs
   `docker exec`.
6. **Do not add an eighth `EXIT-CODE BEHAVIOUR CHANGED` notice header.** Exit-code behaviour is
   **unchanged** by this task — the probe was already fatal after WR-09. The file documents a

   convention.
7. **Keep the printed label `Traefik dashboard: ` byte-identical.** The failure tail at line ~1444
