  <files>scripts/check-drift.sh</files>
  <action>
Create the host-side image-drift check. It runs **on LXC 100** (it needs docker and the repo
checkout); the workstation only ever ssh's to it, exactly as `check-jellyfin-transcode.sh` does.

**Naming — do not conflate two concepts.** This file's subject is **IMAGE drift**. The estate
already uses "drift" for vendored-file sha256 mismatch (`VENDORED_DRIFT_PROMOTED`,
`DRIFT_APPDATA_ROOT` in `quick-health-check.sh`). Every identifier, metric and message here carries
the word `image` so the two are greppably distinct.

**Header block**, in this repo's in-band style, stating: where it runs and why; the exit-code
contract; the two known limits (below); and the sentence that a reader is most likely to get wrong —
*this compares the tag string the container was created with against the tag string git pins; it is
not a digest comparison and it is not proof the two images are the same bytes.*

**Resolution algorithm (the crux):**
1. Enumerate running containers with `docker ps -q`.
2. For each, `docker inspect` once, reading `.Config.Image`, and the labels
   `com.docker.compose.service` and `com.docker.compose.project.config_files`.
3. Group containers by their `config_files` value (comma-separated; split it and pass each as its
   own `-f`). Resolve each **distinct group once**, not once per container.
4. Per group, run `docker compose <-f each> config --format json`, bounded by `timeout`, and read
   `.services | to_entries[] | "\(.key)\t\(.value.image // "")"` with `jq`. This resolves `include:`
   and `${VAR}` substitution and ignores commented lines — which grep, and a hand-rolled YAML read,
   do not.
5. Look up the container's service key in that map to get the declared pin.

**Classification, per container, into exactly one bucket:**
- `OK` — normalised running ref equals normalised declared ref.
- `IMAGE_DRIFT` — both refs resolved, neither is digest-pinned, and they differ.
- `UNRESOLVABLE` — any config file in the group is missing, `docker compose config` exits non-zero,
  the service key is absent from the resolved map, or the declared image is the empty string.
  **UNRESOLVABLE is a counted outcome of a successful run, not a could-not-look.** It must not abort
  the run: `immich_redis` and `immich_postgres` are permanently unresolvable, and aborting on them
  would make this check permanently red on the day it ships — the 01-09 trap `quick-health-check.sh`
  already carries three notices about.

**Normalisation, before comparing** (each rule exists because a measured pin needs it):
- strip a leading `docker.io/`, and a `library/` path segment immediately after it;
- treat an absent tag as `:latest`;
- if **either** side carries `@sha256:`, classify as `OK` when the full `repo:tag@digest` strings are
  equal and as `DIGEST_PINNED` (reported, never `IMAGE_DRIFT`) when they are not. Four pins are
  digest-pinned today and a digest-pinned container must never appear in the drift list.

**Report mode (default, no arguments)** prints, in the estate's `✅`/`❌`/`⚠️` vocabulary: one line
per drifted container giving `name  running -> declared`; the unresolvable list with reasons; and a
summary block whose heading is anchorable by a downstream selector — use the literal
`📊 Summary` — carrying the tokens `image drift`, `unresolvable`, `unhealthy`, `created`,
`commits behind` and `FAILURES total`, mirroring `check-jellyfin-transcode.sh`'s section 6.

**Also count, in the same `docker ps` pass** (cheap, and the alert rules need them): containers whose
health status is `unhealthy`, and containers in state `created`. The `created` state is a documented
estate blind spot — `--filter status=restarting|dead|exited` misses it, and it once hid two dead
containers for six weeks.

**Also report `commits behind`**: `git -C /mnt/fast/stacks rev-list --count HEAD..origin/main`.
⚠️ Without a `git fetch` this uses the last-fetched ref and is therefore a **lower bound** — say so
in the header and in the output. Provide `DRIFT_GIT_FETCH` (default `0`); when `1`, fetch first. It
is **off by default** because a timer that mutates `.git` hourly is a host change nobody asked for.

**`--prom` mode** writes a node-exporter textfile. Emit, each with its own `# HELP` and `# TYPE`:

| Metric | Type | Meaning |
|---|---|---|
| `selfhost_image_drift_containers` | gauge | count classified `IMAGE_DRIFT` |
| `selfhost_image_drift_unresolvable_containers` | gauge | count classified `UNRESOLVABLE` |
| `selfhost_image_drift_container{name=...,running=...,declared=...}` | gauge, value 1 | one series per drifted container |
| `selfhost_containers_unhealthy` | gauge | health status `unhealthy` |
| `selfhost_containers_created` | gauge | state `created` |
| `selfhost_repo_commits_behind_origin` | gauge | lower bound, see above |
| `selfhost_image_drift_last_success_timestamp_seconds` | gauge | `date +%s` of this successful run |

**The timestamp gauge is the fail-closed lever and must be treated as such.** Write it **only** on a
successful measurement. On a could-not-look, leave the existing `.prom` file **completely
untouched** — no partial write, no fresh timestamp — so the file goes stale and the staleness alert
fires. A half-written file would also break node-exporter's parse of the whole directory.

**Write atomically**: `>` a temp file in the *same* directory whose name does **not** end in `.prom`
(node-exporter globs `*.prom` continuously and would parse a partial file), then `mv` it into place.
`chmod 0644` so node-exporter, which runs as its image default user and mounts the directory `ro`,
can read it. Output directory from `DRIFT_PROM_DIR`, default
`/mnt/fast/appdata/monitoring/node-exporter-textfile`, file `image-drift.prom`. **Never `/tmp`** —
tmpfs on this LXC is host RAM.

**Exit codes — the two modes differ deliberately, and the header must say why:**
- report mode: `0` clean; `1` on image drift found, on an unresolvable count other than expected, or
  on any could-not-look; `2` on a usage error (matching `quick-health-check.sh --nonsense` -> 2).
- `--prom` mode: `0` whenever the measurement succeeded and the file was written, **regardless of the
  drift count**; non-zero only on could-not-look. Rationale to state in-band: in `--prom` mode the
  metric *is* the signal; exiting non-zero on drift would put systemd permanently in `failed` for a
  condition the alert rule already owns, and would make a genuine could-not-look indistinguishable
  from ordinary drift. State explicitly that `last_success` means *the measurement ran*, not *there
  is no drift*.

**Could-not-look conditions** (each its own distinct `⚠️ UNKNOWN` message, never `0 problems found`):
docker unavailable or `docker ps` non-zero; `jq` absent; `timeout` absent; the repo checkout absent
at `/mnt/fast/stacks`; the `--prom` output directory absent or not writable.

**Env overrides — every one may only make the check redder** (the `DRIFT_APPDATA_ROOT` contract
already in `quick-health-check.sh`; copy that reasoning into this file's header):
`DRIFT_EXPECT_UNRESOLVABLE` (default `2`, asserted — a third unresolvable container is a new stale
compose project and must go red), `DRIFT_EXPECT_UNRESOLVABLE_NAMES` (default the two immich names),
`DRIFT_PROM_DIR`, `DRIFT_REPO`, `DRIFT_GIT_FETCH`. There is deliberately **no** success-producing
override and **no** sentinel that skips the check.

**Two known limits, stated in the header rather than hidden:**
1. A **floating tag** (`:latest`, `:main`, a two-part tag) that has moved upstream reads as no drift,
   because both sides carry the same string. This is DEPLOYMENT.md § 5's "two-part tags float" trap
   in a new costume. Not fixed in v1.
2. `commits behind` is a lower bound without a fetch (above).

Mark the auto-apply seam for D-01/D-03 with a single named constant — `IMAGE_DRIFT_AUTOAPPLY=0` —
and a comment naming what flipping it would mean. Do not write the apply path.
