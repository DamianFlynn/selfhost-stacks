## Decisions taken in this plan (Claude's discretion, each with its reason)

- **Stack directory `bookorbit/`, not a reuse of `books/`.** Recent stacks (trek, silo, airtrail)
  are named per app. The name also matches the dataset and the compose project. `books/` exists
  only for Booklore, which R6 deletes whole. Container names follow upstream: `bookorbit-app` and
  `bookorbit-db`.
- **Auth (R2): the whole host is on BookOrbit's own auth.** There is one router, on
  `chain-no-auth@file`, with no forward-auth. A narrow bypass would not be narrow here:
  - Every native client and every data-bearing endpoint sits under `/api/`. So the bypass the
    clients need already exposes 100% of the application logic.
  - Forward-auth on everything else would guard only the static SPA bundle and the `/socket.io/`
    handshake, and BookOrbit authenticates the sockets itself.
  - It would cost a second login, plus an Authelia account for Breege, who has none. A
    forward-auth login is a browser cookie that native apps never carry.
  - An explicit router does not depend on the estate's `^/api` Authelia bypass, which is flagged
    for repair.

  Compensating controls, each verified in T5:
  - the setup token, with setup run over the internal IP before DNS is published;
  - registration closed (403);
  - Swagger off;
  - OPDS left disabled until the operator opts in;
  - upstream login throttling;
  - Cloudflare proxying.

  The router gets an explicit middlewares label and a comment block, as airtrail and TREK do, so
  the kiosk-style audit classifies it as deliberate. Authelia OIDC is noted as optional and is
  not configured.
- **Cloudflare (R2): orange cloud (a proxied CNAME, the estate default).** The 100 MB cap applies
  to request bodies only. BookOrbit uploads in 16 MiB chunks, and streaming and download
  responses are not capped. Grey-clouding would publish the origin IP for no gain. Re-evaluate
  only on a 413 or 499.
- **Datasets (R3), following the immich precedent.** The parent `fast/appdata/bookorbit` (128K)
  goes on mp37, and the child `fast/appdata/bookorbit/postgres` (16K) on mp38, each with its own
  mount_point. App data (covers, book-bucket, possible audiobook uploads) suits 128K. There is no
  quota on the Postgres dataset, because ENOSPC on the WAL means a Postgres PANIC.
- **Postgres image `pgvector/pgvector:0.8.7-pg18`.** It is the same exact pin openwebui uses, so
  the image is already pulled and the existing pgvector major-disable rule covers it.
- **BookOrbit Renovate rules.** Add an `automerge: false` + `manual-review-required` rule for
  `ghcr.io/bookorbit/bookorbit`, because every start runs forward-only migrations. Retarget the
  "Auto-label by stack: Books" rule to bookorbit. No deploy-agent hold: the agent only deploys
  IMAGE_DRIFT, and a manual-review merge is the human gate.
- **Bookshelf Renovate rule (R10).** Use versioning only:
  `regex:^hardcover-v(?<major>\d+)\.(?<minor>\d+)\.(?<patch>\d+)(?:\.(?<build>\d+))?$`. The
  `softcover-*` tags and the floating `hardcover` tag do not match, so Renovate can never propose
  a cross-flavour "update". It must be a versioning-only object with no `matchUpdateTypes`,
  because the validator rejects that combination (see the LSIO rule's description). The default
  arr automerge applies, like the LSIO arrs.
- **The fresh Bookshelf config carries over ONLY the old `config.xml`.** It holds instance
  settings (port, ApiKey, auth mode, URL base), not the Goodreads database. What it preserves:
  - The ApiKey, so `readarr-exporter` (`READARR_API_KEY` in the arrs `.env`) and Prowlarr's
    Readarr application keep working with no secret being read, moved or printed.
  - The authentication mode, so the instance never comes up open.

  This is a deliberate deviation from the operator's working assumption that Prowlarr "needs the
  NEW API key". The intent (Prowlarr works against the new instance) is met, with less secret
  handling. If the operator wants a rotated key, that is a later, separate step that must also
  edit the arrs `.env`.

  `readarr.db`, `logs/` and `MediaCover/` are not copied.
- **Download clients are re-created from the OLD database's `DownloadClients` rows.** A
  `python3 -I` sqlite read of the preserved `readarr.db` is posted to the new instance's API, so
  they match the previous setup exactly. No credential is typed, printed or put in argv.
- **Authors are added with `monitor: none`, `monitorNewItems: none` and
  `searchForMissingBooks: false`.** "none" is the stricter of the operator's two options. Disk
